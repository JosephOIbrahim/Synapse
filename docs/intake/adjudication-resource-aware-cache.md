## Verdict

This is a **proposed feature architecture, not a governing-blueprint successor** — and it says so itself, which remains the largest difference between it and the `SYN-NEXT-001` intake. Its design spine is genuinely harvestable: unknown-is-valid, no-forced-cook, LLM-outside-the-verdict, ranges-not-points, and the topology/bake/validity separation are all correct, all survive both adversarial passes, and several are better-stated than anything currently in the tree. Its plane table extends the six-plane architecture 1:1 with no invented plane, and §20 explicitly refuses to rewrite the router, bridge, or executor.

But the two mechanisms the whole safety argument rests on are **illusory at HEAD.** "Disk writes require explicit approval" resolves, through the exact registry the artifact names, to `_panel_consent → return True` with `_bridge._gate = None`. And Phase 2's cancellation requirement is a capability this repo has already escalated to SideFX as nonexistent on this build. An implementer given this document at its own default TASK MODE would write `test_cache_bridge_gates.py`, watch it pass on registry membership, and ship a 180–240 GB unconfirmed write — then stall on a cancellation exit gate that cannot be met, or fake it.

Three further structures are parallel rather than extending: a probe that duplicates two shipped `host/introspect_cook_*.py` files, a receipt carrying none of the audited receipt's fields, and eleven new modules with no named live caller against a governing rule that a dormant implementation is not a shipped feature. And the flagship worked example — the one an implementer would fixture from — is arithmetically impossible in five independent ways.

None of that is fatal to the *design*. All of it is fatal to the *default mode*.

**Claim counts: ADOPT 16 · ADAPT 6 · CORRECT 16 · REJECT 5**
**Challenges: 19 raised · 19 sustained**
**Confabulations:** C1 clear (no "has launched" claim; the 22.0.400 pin is corroborated by `drop.json` and the symbol-table stamp) · C3 clear (deterministic local policy from typed evidence; zero vector similarity; no cognitive-STATE claim; the LLM is explicitly outside the policy boundary).
**Boundary-pressure:** rigging / KineFX / APEX **0 events** — §9's context table is SOP / DOP / LOP / COP only, all inside the declared authoring domains, no proxy variants; §13/§16/§20 name no rigging surface. Two non-rigging events: **process** (§0 self-set TASK MODE) and **scope** (11 new modules + 3 tools, no G1–G9 home, no named caller).

**Recommended TASK MODE: REVIEW_ONLY**

Reached independently by both passes, and the case is now much stronger than my first pass had it. Four showstoppers sit upstream of any implementation: the approval gate does not gate (Ch. 7), the required cancellation does not exist (Ch. 5), the Phase 0 probe already ships (Ch. 2), and the document authorizes itself (Ch. 14). `REVIEW_ONLY` costs nothing and forfeits nothing — the artifact's own Final Directive already sequences read-only first, so `REVIEW_AND_IMPLEMENT_PHASE_0_1` stays available the moment the human grants it and the four showstoppers are dispositioned.

**Escalations (human + CTO — I flag, never execute):**

- **E1 — Self-authorizing TASK MODE.** §0 ships a paste-ready prompt with the mode fixed at `REVIEW_AND_IMPLEMENT_PHASE_0_1` and instructs the agent to proceed after its own report. Per **P4** the mode is a human gate; the anti-runaway anchor exists so that no agent ratifies its own findings. Also close the §0 item-9 gap: it forbids "destructive Git operations" but not `git push` / `git merge`, which the harness rules prohibit outright. **Second instance of this pattern through this channel** — worth treating as a recurring shape rather than a one-off.
- **E2 — `ESCALATE: possible version bump.`** `python/synapse/cache_policy/` (6 modules), `server/cache_probe.py`, `server/handlers_cache.py`, `panel/cache_advice_card.py`, `host/introspect_cache_capability.py`, 7 test files, and three new tools are a **new product surface with no home in G1–G9 and no named live caller** — against the governing rule that a dormant implementation is not a shipped feature. Folded in: the Phase 0 probe must **extend** `host/introspect_cook_api.py` and re-run on 22.0.400, not fork it. Whether any of this becomes a gap is the human's decision.
- **E3 — Approval-gate reality (highest severity).** The panel bridge resolves consent to `return True` with HumanGate disabled, for a documented and defensible reason (the blocking poll deadlocks the GUI thread that must draw the approval card). Separately, the live `/synapse` transport bypasses the bridge entirely and runs `execute_python` ungated — which is the path today's cache recipes actually use. **A 180–240 GB disk write has no working artist-confirmation mechanism on either path.** This outranks the cache feature and should be settled before any Phase 2 is authorized for any caller.
- **E4 — Contract reconciliation.** `CacheDecision`, `CacheReceipt`, and `CacheManifest` must bind by name to the existing `IntegrityBlock` and the governing `synapse.execution_receipt/v2`, including a `fidelity` linkage under fidelity=1.0-or-stop; adopt the namespaced `"schema": "synapse.<name>/v<n>"` convention rather than a parallel `schema_version` field; and site the three new persistence authorities inside the Memory plane with the unsaved-HIP identity case addressed. Converges with `SYN-NEXT-001`'s still-open receipt-schema escalation — one decision, now with two callers.
- **E5 — Orphaned `cookTime` disposition.** §16 Phase 0 task 8 offers "reconnect or deprecate, do not silently maintain two truths" for one module. There are **three** (`performance_profiler.py`, `explain_mode.py`, `network_trace.py`), five call sites, all phantom-shaped on both builds, all in the documented orphan set. The disposition is the human's; the adjudicator records only the corrected count.
- **E6 — Uncancellable, unbounded bake.** Phase 2 requires cancellation of an in-flight bake on a build where this repo has already told SideFX no such API exists, and advertises a 22–31 minute panel action against a published ≥250 ms warn budget and a ratified Boundedness law. Either the phase is redesigned around a chunked/out-of-process bake with a real interrupt surface, or the cancellation exit gate and §17.4 assay 10 are withdrawn. This is a capability decision, not an implementation detail.
