# SYNAPSE v5.104.1 — two seat fixes, and World Labs import reads Atlas

**Install this over 5.104.0.** The first seat installed with 5.104.0 showed two faults: the
Moneta schema was no longer registered, and Claude Code could not authenticate to Houdini once
Setup had created the key. Both are fixed here. World Labs now serves only its Atlas API, so
the World Labs import is rebuilt for Atlas: it reads finished Atlas splat scenes and local
`.spz` or `.ply` files, and it never starts a paid Atlas task.

## Fixes

- **The Moneta schema stays registered.** When Setup keeps an extra path that an earlier install
  put in the package's `PXR_PLUGINPATH_NAME`, 5.104.0 wrote the value as a list under
  `method: replace`. Houdini 22.0.400 keeps only the last entry of such a list, so it registered
  the kept path and dropped SYNAPSE's own Moneta schema, and Doctor's `moneta_substrate` check
  failed. Setup now joins the list into one `;`-separated string, with the bundled schema first.
  A fresh install wrote one path string before and is unchanged. Running 5.104.1's Setup rewrites
  the package file.
- **The same guard for `PYTHONPATH`.** If a previous package kept `PYTHONPATH` under `replace`, or
  with no method, Setup also wrote a list there, and by the same package rule Houdini would keep
  only its last entry and drop SYNAPSE's `python` folder (measured for the schema path, not for
  `PYTHONPATH`). Setup now writes that list as one string too. An upgrading Setup keeps the previous
  package's method, so a package written with `replace` or no method (by hand, or by an older
  deployment) was exposed. Every Setup from 5.100.0 on, and the source package, write `prepend`.
  This was found in review, not on a seat.
- **Claude Code reaches Houdini again once a key exists.** The MCP server (`mcp_server.py`) sent
  its `authenticate` message as a binary WebSocket frame, and the Houdini server ignored binary
  frames, so every MCP client holding a key waited 5 s and failed with "didn't respond to
  authentication". The panel's own `/mcp` path was not affected. Both sides are fixed: the client
  sends a text frame, and the server decodes a UTF-8 binary frame before its auth check, so an
  older client that still sends bytes authenticates too. A binary frame that is not UTF-8 is
  logged and dropped, and a binary command from a client that has not authenticated is refused.
- **An unreadable collider no longer stops a World Labs import.** Since 5.89.0, a
  `<world>_collider.glb` beside a splat that Houdini's glTF reader could not load made the whole
  import fail and removed its nodes. Now that file is skipped with a warning, the floor comes from
  the splats, and the import record does not name it, so the scatter recipe cannot bind it.

## World Labs: Atlas only

World Labs' API now supports Atlas only. 5.104.0's World Labs dialog asked for a Marble world;
that path is removed.

- **What it imports.** A finished Atlas splat scene (an operation ID, or a folder downloaded with
  `worldlabs operations download`), or a local Gaussian `.spz` or `.ply`. **Connect to Atlas**
  lists up to 20 of your finished `posedImages2Splats` operations (one page). For an import by
  operation ID, **Most splats** takes the largest output and **Fewest splats · layout** the smallest;
  a downloaded folder uses its largest file.
- **It only reads.** SYNAPSE calls three Atlas routes: list operations, get one operation, and
  create an asset read URL. Any other route, every task route included, is refused before a
  request is built, because each Atlas task costs credits. Run tasks with the `worldlabs` CLI or
  the World Labs app. The signed download carries no key.
- **The key.** A key typed in the dialog wins, then `WLT_API_KEY`, then the key that
  `worldlabs auth login` saved for the Atlas origin. The saved key is read in place and never
  shown or copied. Local files need no key.
- **SPZ is converted first.** Houdini 22.0.400 cannot read SPZ: the File SOP and
  `hou.Geometry.loadFromFile` both fail on it. SYNAPSE decodes SPZ with numpy into a standard
  Gaussian PLY, cached by the SPZ's SHA-256 under `~/.synapse/worldlabs/spz/`, then imports that
  PLY the native way (File SOP → Bake GSplats → SOP Import LOP → a grounding Transform LOP).
  View-dependent colour of degree 1 or 2 is padded to degree 3, and degree 4 is reduced to 3.
- **Axes and scale.** An SPZ imports Y-up with no flip: Atlas's world frame is Y-up, and the one
  real Atlas file checked (below) imported that way. A local `.ply` keeps the Y-down default
  and its 180° turn. Atlas reports no metric scale, so an Atlas import's
  scale is recorded as unknown. Provenance on the new nodes records the SPZ hash and version, and
  the Atlas operation ID and task when the file came from Atlas; an import by operation ID also
  records the splat count.
- The dormant Atlas executor scaffold (`worldlabs/atlas.py`) is retired; the contracts the HD1
  track builds on stay, in `worldlabs/atlas_contracts.py`.

## A real Atlas splat, read end to end

On 2026-11-22 one refined `posedImages2Splats` run (5,000 credits) reconstructed the World Labs
quickstart photo of a torii gate on a lake. Atlas returned one file, `refinedSplats_2000000.spz`
(32,902,320 bytes):

- **SPZ version 2, gzip.** 2,000,000 splats, colour of degree 0 (no view-dependent colour) and
  12 fractional bits. Version 2 decodes on Houdini's Python 3.13; no zstd decoder is needed.
- **One flag bit the format does not define.** The header's flag byte is `0x40`. Niantic's
  reference loader defines only `0x1` (antialiased) and `0x2` (extensions), and the file carries no
  extension data: its uncompressed size is exactly the 16-byte header plus 19 bytes a splat.
  SYNAPSE ignores the bit.
- **SYNAPSE read it both ways, headless, in Houdini 22.0.400 (Python 3.13.10) on the release
  tree.**
  - *By operation ID*, the dialog's remote path: the key from the `worldlabs` CLI sign-in, the
    operation, a read URL, the signed download and the conversion took 2.6 s; the native import
    about 3 s.
  - *From the downloaded folder*: the conversion took 0.5 s, the native import about 3 s.
  - Each made a `ParticleField3DGaussianSplat` prim of 2,000,000 points, Y-up with no turn, at
    scale 1 marked unknown, lifted 0.63 units so its floor layer sits at y = 0. The provenance
    records the operation ID, the task and the SPZ hash, and by operation ID the refined splat
    count. It holds no URL, key, account ID, project ID or local path.

The scene is one photo sent twice (the task needs at least two views), so most of it is invented,
and its rendered look was not checked.

## Limits

- **One real Atlas splat was imported, headless.** It was SPZ version 2. Whether Atlas ever writes
  version 4 is unknown, and a draft output (`refine: false`) was not checked.
- **Version-4 SPZ needs a zstd decoder.** SPZ versions 1 to 3 are gzip and decode everywhere.
  Version 4 is zstd, which Python 3.14 has and Houdini's Python 3.13 does not; there the file is
  refused with a plain message. SYNAPSE does not use third-party zstd packages, whose one-shot
  decoders are not bounded by the size the file declares.
- **The fixed auth client and server were not run together against Houdini.** Each half is tested,
  and the live 5.104.0 seat answered a text authenticate message. The first `synapse_ping` from
  Claude Code after installing 5.104.1 is the end-to-end check.
- **Atlas scale is unknown.** Atlas reports no metric scale, and the grounding node holds a scale
  of 1 for an Atlas import unless a `<world>.world.json` sidecar beside a local file names one.
- **The rendered look of an Atlas import was not checked.**
- **Closing the World Labs dialog prevents a late scene import; it does not stop a download that
  is already running.**
- **A Connect froze Houdini once on the 5.104.0 seat.** On 2026-11-22 at 17:49Z, the first Connect
  after the 5.104.0 install held Houdini's main thread in project setup until Windows closed
  Houdini. The same step took 0.19 s headless, the next launch's Connect held the main thread for
  at most 255 ms, and the cause is not known. 5.104.1 changes nothing there.
- 5.104.0's limits still apply. [5.104.0's limits](v5.104.0.md#limits).
- Setup remains unsigned.

## Upgrading

1. Close Houdini.
2. Run Setup 5.104.1. It rewrites the package file, which restores the Moneta schema path.
3. Restart Claude Code sessions and any SYNAPSE MCP server.
4. For World Labs, sign in once with `worldlabs auth login`, set `WLT_API_KEY`, or paste an Atlas
   key into the dialog. Local `.spz` and `.ply` files need none.
