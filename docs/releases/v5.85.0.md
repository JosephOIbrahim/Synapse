# v5.85.0 — Identify selected nodes

Select nodes in a network editor, then click **Identify** beside **Connect** and
**Doctor**, or send `/identify`. A short note appears under each selected node:
what the node does, up to two parameters you changed, and any error, warning or
bypass. A LOP also names the first primitive it writes. Click **Identify** again
to clear the notes, or send `/identify off`. Each click is one undo step.

The note is built without a model call. It comes from the node itself and the
local [SideFX help library](../studio/SIDEFX_LIBRARY.md). A node the library does
not cover says **not in library** instead of a guess. Long summaries are
shortened to fit. The Selection Inspector shows the same text in a read-only
Identify column.

Each click labels up to 60 nodes, and the network editor reports how many of the
selection it labeled. Library lookups run off Houdini's main thread, and each
node type is looked up once per session.

Notes use Houdini's node comments. Your own comment text stays: Identify adds
its note below a `~ identify ~` line and removes only that part. Saving a scene
removes the notes from the file and puts them back afterwards, so saved scenes
do not carry them.

**Source release for Houdini 22.0.400 / Python 3.13.** No new Windows installer is
included. The older v5.75.2 Setup does not contain these changes. Follow
[source installation](../getting-started/installation.md#source-installation),
then restart Houdini and separate MCP processes to load the updated source.

## Also in this release

GitHub CI now runs on Windows as well as Linux and macOS, with Python 3.11 and
3.14 on each. A new ratchet stops new broad `except` handlers that swallow
errors without logging or re-raising: each file's count may shrink but never
grow, and a file the check cannot parse fails it. See
[hardening ratchets](../HARDENING_RATCHETS.md).

The vendored fxhoudinimcp notice now records hashes of the committed file
contents, and `scripts/verify_vendor_notice.py` checks them, so Windows line
endings no longer change the result. ADR-0001 now lists the eight decisions
JEV may never make in the harvest pipeline.

The memory store no longer writes a record twice when a save lands between
adding it and the next background flush. The new Windows CI job caught it on
this release, where a seeded memory log grew from 7 lines to 14.

## Validation and limits

Identify was checked live in Houdini 22.0.400 through the SYNAPSE panel, on the
code in this release. Seven selected SOPs each got a note, including
PolyExtrude's "Extrudes polygonal faces and edges.", and an artist comment on
one node stayed above its note. With 200 nodes selected, 60 notes appeared
about a second after the click with a cold library cache and in 53 ms with a
warm one. Houdini's longest pause during that work was under 80 ms, against
55 ms when idle. A scene saved with 67 notes on the canvas reopened in hython
with no note text in the file and the artist comment intact. Earlier live gates
on this feature confirmed the button placement, one-step undo and the LOP
writes line.

Two independent reviews re-ran every acceptance check and planted 39 deliberate
defects in the new code; the tests caught 34, and the review records list the
other five. Across all 4,606 node help pages in the local SideFX library,
4,555 summaries read as clean prose. A local run of the new Windows CI jobs
passed on Python 3.11 and 3.14 after one timing-sensitive test was made robust.
Publication requires all six GitHub CI jobs to pass on the exact tagged commit,
linked in the GitHub release.

**Identify limits.** Of those 4,606 help pages, 39 node pages still give a
summary with leftover help formatting, such as a `= Name =` heading, a
`:warning:` tag on deprecated nodes, or an image link on six MaterialX nodes.
If your own comment contains a line that reads exactly `~ identify ~`, text
below that line is treated as part of the note and can be removed with it. A
LOP that only passes its input through can still report the primitive its input
wrote. If the SideFX library cannot be read the first time a node type is
identified, that type shows **not in library** until Houdini restarts. A JEV
lane for ranking changed parameters is included but not connected: a measured
comparison kept Houdini's parameter order, so Identify makes no JEV call.

**Found during validation, present in earlier releases.** The first save of an
untitled scene can hold Houdini for minutes while SYNAPSE copies the shared
untitled-scene memory into the new scene's folder. The copy rewrites the whole
memory store once per record. In the gate session, 1,458 records took about
seven minutes; a later save to the same folder was immediate. A fix is planned.

Five tests with known Windows-only failures are marked as expected failures on
Windows: three timing tests on Python versions before 3.13 and two memory
persistence tests. Fixing their causes is planned.

The inherited [v5.84.1 limits](v5.84.1.md#validation-and-limits) remain, including
incomplete SideFX fetch coverage, short-dock overflow, and unqualified remote
World Labs export and alternate themes. Local documentation caches and library
databases are not bundled.
