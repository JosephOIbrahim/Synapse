# v5.94.2 - The help page describes the panel as it is

One change on top of [v5.94.1](v5.94.1.md): the page that the panel's Help opens is rewritten. No Python file changes apart from the version strings, so what v5.94.1's notes record about behaviour in Houdini stands for this release's code.

**The help page is new.** `docs/help/index.html` was last changed on 3 August and still carried the banner v5.42.0. It named none of the controls a new user meets today: not Doctor, not Connect models, not Updates, Saved networks, Identify, Spatial or Render. The new page is written from the panel's source as it stands. It has five sections, shown one at a time: Start, Ask, The panel, Stuck and Limits.

**What each section holds.** Start walks a first session in four steps and a first build in three, then explains the receipt and Undo. Ask covers how to phrase a request, the question the panel asks before work goes to a model service and what that service can receive, verified recipes, memory and the choice of model. The panel is a map of the panel with nineteen rows beside it, one for each control and area from the model name to Render; choosing a control on the map goes to its row. Stuck gives the first thing to try in eleven situations, then the three ways to stop work and the three limits that end a turn. Limits says where the tool can be wrong and where it stops.

**It is written to be read calmly.** Sentences are complete, a paragraph carries one idea, and a name sits on the left with its answer on the right. The page uses the panel's colours and loads the panel's own font files from the source tree. It makes no network request. With JavaScript off, every section shows in order.

**Source release for Houdini 22.0.400 / Python 3.13.** No new Windows Setup is included. The v5.86.0 Setup contains none of the changes in v5.87.0 through this release, and its tree holds the older help page, so a copy installed from it keeps that page. Follow [source installation](../getting-started/installation.md#source-installation); the panel's Help then opens the new page from the source tree.

## Validation and limits

**Nothing in Houdini changed.** The release commit changes one HTML file, the version strings and documents. For what was seen in Houdini on this code, read [v5.94.1's validation](v5.94.1.md#validation-and-limits).

**Names against the source.** A script took each name the page marks up: 39 controls in bold, 20 on-screen words, 14 menu entries, 19 map labels and 4 commands. That is 96 entries, with a name counted once for each kind of markup it appears in. It looked for each as a string literal in `python/synapse/panel`, which this release does not change. 91 are there, two of them through a format string such as `Render %d frame%s`. Two are names from outside the panel, the Synapse shelf button and Houdini's "New Pane Tab → Synapse", and the script found those in the README. Three are labels on the page's map that stand for a control without quoting its text: "Model name", "Status line" and the lightning glyph. None was missing. The shelf button's label was also read in `houdini/toolbar/synapse.shelf`. Left out of the check: Houdini's own menu path for saving a desktop, and six short strings set in code type, such as `/stage` and `.ply`.

**Behaviour, in a desktop browser.** In headless Chromium 141, seventeen checks passed on the committed file. Each section opens from the bar, and from the link at the end of the section before it. A control chosen on the map lands on its row below the bar and marks it. A link to a row opens the right section, and Back returns to it. There is no script error and no network request, and with JavaScript off all five sections show. A closed section carries `hidden="until-found"` and opens on the `beforematch` event, which a browser sends when its find lands there; the check sent that event itself and did not drive a real find. At six widths from 1360 to 420 pixels nothing scrolled sideways and no map label was clipped. In all 57 rows that sit side by side, a name and the first line of its answer share a baseline. Print shows all five sections.

**The links.** The page has twelve outside links. Nine point at documents in this repository on `master`; each file, and each heading a link names, exists in this release's tree. The other three are the repository's front page, its new-issue form and its latest release.

**Tests.** No test reads the page. The full `tests/` suite passed on the release tree, on Windows with Python 3.14, with the tests that need a Houdini runtime deselected as CI does: 10,923 passed, 430 skipped, 186 deselected, 5 xfailed, 0 failed. Those are v5.94.1's counts. That run came before these notes were final and before the harness note and the Jev ledger row were added; the README receipt, the version conformance tests, the tool-count tests and the harness tests were run again after them. On Python 3.11 the same three test files passed, and so did CI's second and third pytest steps. Publication requires all six GitHub CI jobs to pass on the exact tagged commit, linked in the GitHub release.

**Limits.**
- **The page has not been opened from the panel.** It was seen in Chromium only. The panel's Help calls `hou.ui.showHelp` when Houdini offers it, and otherwise hands the file to the desktop's browser. Which of the two happens on 22.0.400 was not looked at, and the page was not seen inside Houdini's own help browser. If the font files do not load there, the stylesheet's next choices are DM Sans and then Segoe UI.
- **The page's version is typed by hand.** `scripts/sync_version.py` does not know the page, so the next release has to change the banner itself.
- **Nothing keeps the page honest.** The name check is a script outside the repository, and no test reads the page. If a control is renamed in the panel, nothing will say the page is out of date.
- **Four older pages in `docs/help/` are unchanged,** and two of them use older names: `events.md` calls Updates "Events", and `panel_docking.md` calls the shelf's Synapse button "Open Synapse Panel". The panel's source refers to none of them.
- **The page follows the handler, not the tooltip.** Emergency halt's tooltip in the lightning menu says it cancels cooks under `/obj`. The handler sweeps `/tasks`, `/obj`, `/stage` and `/out`, and the page says so. The tooltip is not fixed here.

The inherited [v5.94.1 limits](v5.94.1.md#validation-and-limits) remain.
