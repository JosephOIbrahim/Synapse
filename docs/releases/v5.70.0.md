# v5.70.0 — Tool names an artist can read

The panel names its own tools badly. This release fixes the naming, and fixes the
thing that let one of the two defects hide.

## Changes

- **Domain words survive.** The label fallback was
  `removeprefix("houdini_").replace("_"," ").capitalize()`. `.capitalize()`
  lowercases everything after the first character, so `houdini_create_usd_prim`
  reached the artist as **"Create usd prim"**. And only the `houdini_` namespace
  was stripped, so every `synapse_`/`cops_`/`tops_` tool led with a namespace
  nobody needs to read — **"Synapse solaris shotsetup karma xpu"**.

  | before | after |
  |---|---|
  | Create usd prim | **Create USD primitive** |
  | Synapse solaris shotsetup karma xpu | **Solaris shot setup Karma XPU** |
  | Cops reaction diffusion | **Reaction diffusion** |
  | Composite aovs | **Composite AOVs** |
  | Set opencl | **Set OpenCL** |

- **Abbreviations expand to the word an artist would say** — `parm` →
  parameter, `prims` → primitives, `matlib` → material library. `primvar` is
  deliberately left alone: it is the right word and has no plain synonym.

- **The curated label map was running at 4 of 8, silently.** Four keys were
  written against the tool registry's *second* column — the wire command name —
  while the label function receives the *first*. A key that matches nothing
  fails quietly: the artist just sees the derived label, which reads as a style
  choice rather than a miss.

  ```
  houdini_get_scene_info  ->  houdini_scene_info
  houdini_set_parameter   ->  houdini_set_parm
  network_explain         ->  houdini_network_explain
  capture_viewport        ->  houdini_capture_viewport
  ```

- **A guard so it cannot rot again.** `tests/test_activity_labels.py` reads the
  live registry and fails if any curated key stops being a real tool. That guard
  is the actual fix; the four keys are today's instance of it. No PySide, no
  Houdini — it runs on stock CI and cannot skip.

- Documentation: `PANEL_RHYTHM_SPEC.md` reconciled with the shipped code (it had
  asserted the opposite of the panel for nine days), and a measured panel design
  refinement filed against a Pentagram reference. No design change shipped.

## Verification scope

- Stock suite: **8920 passed, 430 skipped, 0 failed, 0 errors.**
- Panel seat suite under hython 22.0.400 offscreen: **201 passed, 5 failed** —
  identical to 5.69.0, same five known reds, **none new**. Two are recorded
  design conflicts awaiting a ruling; three are named and undiagnosed.
- The capitalisation table was **derived from the 128 live tool names**, not
  invented, and all 128 labels were previewed before the change was written.
- The call site is untouched; the structural pin on it stays green.
- Installer: **19 of 19 PASS, exit 0** against the isolated TestSetup, which carries
  the same payload sha256 as the published Setup. Installer unit checks 37 passed.
- Found while cutting this release: the seat suite and the stock suite share
  `~/.synapse/logs/synapse.log` and **cannot be run concurrently** — the loser of the
  race reports a plausible-looking timing failure. Recorded in
  `harness/notes/RELEASE_v5.70.0.md`; both numbers above were measured alone.

## Update

`SYNAPSE-5.70.0-Setup.exe` upgrades in place and preserves projects, memory,
credentials and custom files — that path is one of the qualification checks.

- Running from source? Pull `v5.70.0`. **A live Houdini session holds the old
  `activity.py` in memory until the panel is reloaded or Houdini restarts** —
  the labels change on the next load, not the next turn.
- The installer is **unsigned**; verify against `SHA256SUMS.txt`.
- `installer-verification.json` on the release carries the full evidence,
  including anything that was not run.
