# v5.94.3 - Eleven small repairs, each with its own test

Seventeen commits on top of [v5.94.2](v5.94.2.md). Eleven are small repairs, each one commit with one test file of its own. Two are one-line corrections to those repairs, two add a mode to the development harness, one is the release commit, and the last corrects one line in that commit's evidence note. **None of it was run in Houdini.** Every repair is checked by unit tests only, so what [v5.94.1's notes](v5.94.1.md#validation-and-limits) record about behaviour in Houdini was seen on code without these changes.

**A failed step no longer takes back the artist's last action.** `execute_python` and `configure_render_passes` each open an undo group and roll back after a failed step: `execute_python` when the script raises a coding error such as `NameError`, and `configure_render_passes` on any exception. Each did that with an unconditional `hou.undos.performUndo()`. If the step raised before it changed anything, that call could undo the artist's own previous action instead. Both now read the undo labels before the group opens, and undo only if the labels differ afterwards. `build_graph` already guarded its rollback this way.

**A rollback that failed is recorded as incomplete.** The bridge's rollback has one branch for a scene hash that is not a real digest of the scene, such as one that was never computed. On that branch an undo that raised was still recorded as `rolled_back`. It now records `rollback_incomplete` and adds a sentence to the error that names the target and recommends a manual review.

**Two names follow Houdini 22.** `synapse/hooks/synapse_hooks_houdini.py` asked for `hou.nodeEventType.InputChanged`, which 22.0.400 does not have, so its per-node callbacks could never register. It asks for `InputRewired` now. Two calls to `hou.expandString`, which SideFX's documentation marks as deprecated, now call `hou.text.expandString`: the one in `panel/cross_scene.py` and one of the two in `server/solaris_compose_tools.py`.

**The help pages are kept honest.** v5.94.2's notes listed five limits for the help page. This release closes two of them, the hand-typed version and the tooltip that disagreed with its handler, and narrows two more. A test now reads `docs/help/index.html`: each of the 20 on-screen words the page quotes must appear in the panel's source, and the page's version must equal `VERSION`. `scripts/sync_version.py` knows the page as a seventh surface, and for this release the script wrote the page's version itself: `help_page 5.94.2 -> 5.94.3`. Three older pages use today's names: `events.md` says Updates, `commands.md` says Saved networks and Updates, and `panel_docking.md` names the shelf's Synapse button. Two tooltips match their handlers: the panel's hidden help button names the page it opens, and Emergency halt names the four roots it sweeps.

**Three smaller repairs.** `server/handlers_memory.py` logged a warning through a name it never defined, so a bridge failure during the sleep pass would have raised `NameError` instead of falling back to running directly; the module has a logger now. `mcp_server.py` imports `concurrent.futures` at module level, where an annotation already named it. The component builder answered an unknown purpose by printing a Python set; it now lists the three valid purposes in alphabetical order.

**The development harness gains a graph mode.** `harness/rope/graph.py` runs repair sessions in separate worktrees under a session cap and a clock, and keeps a change only when its checks pass. It adds one guard, `sweep`, to `harness/jev/questions.json`. Nothing under `python/synapse` imports it, and it does not run inside Houdini. The eleven repairs above came from its first run.

**Source release for Houdini 22.0.400 / Python 3.13.** No new Windows Setup is included. The v5.86.0 Setup contains none of the changes in v5.87.0 through this release. Follow [source installation](../getting-started/installation.md#source-installation), then restart Houdini to load the updated source.

## Validation and limits

**No Houdini session was opened for this release.** Ten Python files of the product change: `mcp_server.py`, `shared/bridge.py`, `synapse/hooks/synapse_hooks_houdini.py`, and seven under `python/synapse`, which are `server/handlers.py`, `server/handlers_render.py`, `server/handlers_memory.py`, `server/solaris_compose_tools.py`, `panel/synapse_panel.py`, `panel/cross_scene.py` and `mcp/tool_impls/solaris/component_builder.py`. The release tool `scripts/sync_version.py` and the two version strings in `python/synapse/__init__.py` change as well. Every statement here about their behaviour rests on a unit test that uses stand-in objects for `hou`, or on a read of the source. The three Houdini names this release starts to use in those places, `hou.nodeEventType.InputRewired`, `hou.text.expandString` and `hou.undos.undoLabels`, are in the symbol table introspected from 22.0.400. `InputChanged` is not in it.

**Each repair's tests, against v5.94.2.** The eleven test files hold 26 tests. They were copied onto v5.94.2's tree and run there, one file at a time: 19 tests failed and 7 passed. Ten of the eleven files have at least one failing test on that tree. The eleventh is the help-page test, whose four tests pass there because the page was already accurate; that repair is the test itself. The other three passing tests, one each in three files, hold on either tree: one checks its own collector, one checks that the symbol table lists `hou.text.expandString`, and one pins that an undo which returns is still recorded as `rolled_back`.

**How a change was kept.** Each repair was written by a headless Claude session working from a card that named the files it could change. A change was committed only when it stayed inside those files and the card's tests passed: its own new test, and the existing test files chosen for the files it touched, with the tests that need a Houdini runtime deselected. Three more sessions then read the kept commits between them. That read missed one thing, a debug line the rollback repair had dropped. The session running the hour found it and restored it, and restored a dropped space in the import repair the same way. Seven of the eleven cards came from limits and review findings already on record, two from a linter, and two from the sessions' own reading of the source.

**Tests.** 42 new tests in `tests/`: 26 for the eleven repairs and 16 for the harness's graph mode. Nine more in `harness/jev/tests` cover the new guard. The full `tests/` suite passed on the release tree, on Windows with Python 3.14, with the tests that need a Houdini runtime deselected as CI does: 10,965 passed, 430 skipped, 186 deselected, 5 xfailed, 0 failed. That run came before these notes were final and before the harness note and the Jev ledger row were added; the README receipt, the version conformance tests, the tool-count tests, the help-page tests and the harness tests were run again after them. On Linux with Python 3.11, in a fresh clone of the pushed branch one commit below the release commit, the same command gave 10,643 passed, 763 skipped, 50 deselected, 3 xfailed, 0 failed, and CI's second and third pytest steps passed. On Windows with Python 3.11, the twelve new test files and the README receipt, version conformance and tool-count tests passed on the release tree. Publication requires all six GitHub CI jobs to pass on the exact tagged commit, linked in the GitHub release.

**Limits.**
- **Unit-tested only.** Nothing here was seen in Houdini. The stand-in objects in these tests behave the way the code expects, which is not evidence of how Houdini behaves.
- **The rollback guard changes one path.** Where no outer undo group is open, which is the live `/synapse` handler path, a failed step that changed nothing no longer costs the artist an action. Whether the old code really cost one depends on Houdini leaving no undo entry for an empty group, which is the project's own note and was not measured here. Through the panel and `/mcp`, the bridge's own undo group is still open when the handler's rollback runs. The project's notes say `performUndo` raises inside an open group, and the old code swallowed that. So on that path a failed `execute_python` was not rolled back before this release and is not rolled back now: its partial work stays until the artist undoes it. What the undo labels read inside an open group was not measured.
- **The rollback guard trusts the undo labels.** When the labels cannot be read, the two handlers now leave a failed step's changes in place, where the old code tried an undo. The guard compares labels and not entries, so a step that adds an entry while Houdini drops an old one, on a stack whose labels all read the same, would not be undone. That case was reasoned about and not tested.
- **Three `hou.expandString` calls remain,** at `server/solaris_compose_tools.py` line 145, `host/lookdev_suggestion.py` line 152 and `forge/extractors/hip_crawler.py` line 81. For the first two, stand-in objects in existing tests provide only the old name, and a repair session may not change an existing test. The third was not on the card.
- **`NetworkBox.addNode` is still used for section boxes,** at `server/handler_helpers.py` line 958. SideFX's documentation marks it as deprecated in favour of `addItem`. The same rule stopped that repair: the stand-in box in `tests/test_solaris_layout.py` only has `addNode`.
- **Nothing in the repository imports the hooks module.** The docstring of `synapse/hooks/synapse_hooks_houdini.py` describes loading it by hand from Houdini's Python Shell. For anyone who does, per-node callbacks now register where before none could. That path was not run.
- **Twelve tool arguments are read and then ignored.** They were found in the same hour and are not fixed: `purposes`, `proxy_reduction`, `materials` and `generate_thumbnail` in the component builder's `execute`; `component_path` in the plan step of `create_variants`; `parallel` and `frame_range` in the COPs batch cook; `conditions` in the HDA promote-parm handler; and `parent` in the planner's cloth, destruction, ocean and pyro pipelines. A caller who passes one sees no effect.
- **The help-page test covers the quoted words, not every name.** v5.94.2's script checked 96 marked names. The new test checks the 20 on-screen words the page quotes, one of them through an allowlist because the panel builds it from a format string, and the version. Control names in bold, menu entries and map labels are not read by any test.
- **One older help page was not looked at:** `docs/help/health_row.md`.
- **The help page has still not been opened from the panel.**
- **The harness's graph mode has run once.** Its scouting sessions raised eight claims that were false on inspection. Its router proposed nineteen of their claims for repair, and seventeen were held back after a read by the session that ran the hour.

The inherited [v5.94.2 limits](v5.94.2.md#validation-and-limits) remain, except "The page's version is typed by hand" and "The page follows the handler, not the tooltip", which this release closes, and "Nothing keeps the page honest" and "Four older pages in `docs/help/` are unchanged", which it narrows as described above.
