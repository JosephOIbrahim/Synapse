**Doctor now says more about a seat, and says it about the right folder.** It
checks Moneta's native (Rust) module against its pinned hash, counts sleep
passes, names third-party code a seat loads from outside its own runtime, and
reads the memory store an unsaved scene is actually using.

**Render QC groundwork lands too, and no artist sees a finding from the new detector yet.** A
positional firefly detector, two frame readers and a supervised CPU worker are
in the repository, with the owner's firefly rulings. Nothing calls the worker.
There are no durable receipts and no panel row. The detector, the worker-side
frame reader and the worker entry point are not in the Setup payload.

## What changes for an installed seat

The four Doctor changes are in `python/synapse/server/doctor.py` and its
helpers, which Setup installs. Doctor's truth contract is unchanged: a check reports ok or fail only
when its probe ran, and anything not probed reads `skipped` with the reason.

### Doctor reads the live store's folder, not the shared `untitled` root

Since BP12 item 1 (2026-09-29), each launch of an unsaved scene gets its own
store under `$HOUDINI_TEMP_DIR/untitled/sessions/<id>`. Doctor kept looking in
the shared `untitled` root above them, where no store binds, so for every
unsaved scene its memory checks inspected a folder the live store does not
use.

- The resolver now asks, in order: the folder of the store this process is
  already serving from; with no store live, the address the store would bind
  (a saved scene's folder, or this launch's existing session folder); with no
  session yet, the `sessions` folder the session will be created in. Never the
  shared root.
- It stays read-only: no store is constructed, no folder is made, and no new
  launch session is minted to get an answer.
- The write-plane probe (`python/synapse/server/write_plane.py`) reuses the
  same resolver, so it tests the folder the store really writes into.
- Two helpers carry it: `existing_unsaved_base()` and `unsaved_sessions_dir()`
  in `python/synapse/host/memory_lifecycle.py`.

Producers: `python/synapse/server/doctor.py` (`_live_store_dir`,
`_resolve_store_base_dir`) · `tests/test_doctor_store_follows_session.py`

### A new `moneta_native` check

Doctor reports Moneta's native module: whether it is loaded, the extension
file, and its sha256 against the reviewed pin in `native_artifact.json`. It
imports neither `moneta` nor `moneta_native`, builds no store and touches no
`hou`. Verdicts, first match wins:

| Verdict | Doctor shows | When |
|---|---|---|
| `hash_mismatch` | fail | The loaded binary's sha256 is not a pinned one, or disagrees with the hash Moneta took at load. **Whatever `MONETA_NATIVE` says, unset included.** |
| `not_requested` | skipped | `MONETA_NATIVE` is unset and Moneta runs Python. Unset is Moneta's auto, not a request from SYNAPSE (owner ruling, 2026-11-09). |
| `python_fallback` | fail | `MONETA_NATIVE` is set to leave native on, and Moneta runs Python anyway. |
| `off_by_choice` | skipped | `MONETA_NATIVE` is 0, false, off or no. |
| `ok` | ok | Loaded, and its sha256 is a pinned one. |
| `unknown` | skipped | Loaded, but no usable pin or no hashable file. Never a pass. |
| `not_loaded_yet` | skipped | Not off, nothing loaded, no evidence of a fallback. |

**An unset `MONETA_NATIVE` with a Python fallback reads skipped** (`473be2a3`).
That was settled before release: no released version showed FAIL. The
not-loaded detail does not say that unset leaves native on (`ef1dc58f`).

Producers: `_check_moneta_native` in `python/synapse/server/doctor.py` ·
`tests/test_doctor_moneta_native.py`

### Doctor counts sleep passes

`moneta_store.sleep_pass_stats()` is a new process-lifetime counter.
`MonetaBackedStore.run_sleep_pass` records every pass that returns
(`completed`) or raises (`failed`), from either caller: the
`synapse_sleep_pass` tool and the opt-in every-100th-add trigger (`None` when
the pass could not be diffed). A failed
pass is counted with what it had already pruned. An operator interrupt is not
counted.

**This changes a field's type.** Doctor's `moneta_consolidation` result now
carries `sleep_passes` (`count`, `completed`, `failed`, `last_at`, `last_monotonic`,
`last_result`), and `sleep_pass_called` is `count > 0`, a boolean. It was the
string `"not_tracked"`. Anything that parses that field needs to know.

Producers: `python/synapse/memory/moneta_store.py` (`sleep_pass_stats`,
`_record_sleep_pass`) · `tests/test_sleep_pass_counter.py`

### A new `runtime_provenance` check

On 2026-11-09 the installed 5.99.0 seat on the development machine loaded
orjson's compiled module from a development checkout, put on Houdini's search
path by a `.pth` file in Houdini's own site-packages. The payload does not ship
orjson, so that seat ran code a clean install does not have, and nothing said
so.

- Doctor now names each top-level package with a loaded module whose file lies outside the running
  SYNAPSE runtime, outside `$HFS` and outside Houdini's Python, with the folder
  it came from (the detail lists the first 8). **Any such module makes the check `fail`**, and the panel's
  Doctor shows NEEDS ATTENTION.
- Standard-library names and file-less entries are not third-party. **A
  relative `__file__` counts as no file** (`937fb995`): PySide6's shiboken
  support modules and `hou.session` report names like that, and resolving them
  against the working folder made them look foreign.
- It reads `sys.modules` and `sys.path` and imports nothing. It reads
  `skipped` outside Houdini or when the runtime root cannot be told.
- `tests/test_shipped_import_map.py` is the build-side companion: every
  third-party import in shipped code must be carried by the payload or
  classified.

Producers: `_check_runtime_provenance` in `python/synapse/server/doctor.py` ·
`tests/test_doctor_runtime_provenance.py` · `tests/test_shipped_import_map.py`

### Developer side: the docking-minimums width check runs under hython

## Render QC groundwork (development seat)

The Render QC chain is meant to let SYNAPSE look at a rendered frame and name
what it finds. This release lands its first pieces. **Nothing calls them yet.**

### What ships, and what does not

| Piece | Path | In Setup? | Called by |
|---|---|---|---|
| Positional firefly detector and `firefly_check` | `retina/firefly_scan.py` | **No** | the worker only |
| Worker-side frame reader | `retina/frame_reader.py` | **No** | the worker only |
| Supervised worker entry point | `retina/worker_entrypoint.py` | **No** | the adapter only |
| Host frame reader and exposure stats | `python/synapse/cv/` | Yes, dormant | nothing |
| Host adapter for the worker | `python/synapse/host/retina_worker.py` | Yes, dormant | nothing |

On a Setup-installed seat the adapter cannot reach a worker. It looks for
`retina/worker_entrypoint.py` under the root four folders above its own file,
and Setup does not install that file. Read from the code (not run on an installed seat): with
`SYNAPSE_RETINA_WORKER_PYTHON` unset it returns inconclusive
`not_configured`, and set to an existing absolute `*.exe` it returns inconclusive
`entrypoint_missing`.

### The positional firefly detector

`retina.firefly_scan.fireflies()` finds isolated pixels far brighter than
their neighbourhood, on Rec.709 luminance, and reports **where**: the count,
the worst pixel in array and frame position, and an optional mask image. It is
the localised companion to `retina.t1.firefly_count`, a whole-frame census
with no positions. Both stay (owner ruling QC-Q6).

- **Method:** the residual against a 5x5 median, a noise estimate per stop of
  brightness, then each lit pixel judged against the live noise in its own
  31x31 window. A constant backdrop or a noise-free linear gradient no longer
  zeroes a large object's estimate. Known limits (objects of 7x7 pixels or less,
  curved or steep gradients, silhouette pixels) are in the module docstring.
- **Honesty:** when lit pixels exist but no stop has enough of them to
  estimate noise, the result is inconclusive with a note. Never a count of 0.
- **The boundary holds:** it needs `cv2`, so it lives in the worker tree and
  imports nothing from `synapse`.

Producers: `retina/firefly_scan.py` · `tests/test_retina_fireflies.py` ·
`tests/test_retina_fireflies_local_noise.py`

### The owner's firefly rulings: a firefly is a candidate, not a fail

`firefly_check()` turns a scan result into one tri-state check. The owner
ruled on 2026-11-10 (QC-FIREFLY-RULES):

- **No firefly:** pass.
- **One or more:** pass, with the detail naming "N firefly candidate(s)" and
  the worst position. The count, worst pixel, sigma and mask path ride in the
  extras for a reviewer. A missing frame size changes nothing here.
- **Inconclusive** (pass `None`, with the reason): the detector could not
  estimate noise; every pixel was non-finite; `nonfinite_pixels` or `count` is
  present but not a whole number of 0 or more.

A tolerance that fails a frame is a policy decision for the owner of
`retina/qc_profiles.toml`. This function does not invent one.

Producers: `firefly_check` in `retina/firefly_scan.py` ·
`harness/next-release/proposals/render-qc.amendment.PROPOSED.json`
(`_owner_decisions`, QC-FIREFLY-RULES)

### Two frame readers, one on each side of the boundary

- **Host side, `python/synapse/cv/`.** `read_linear_rgb` and `read_frame`
  read a frame through OpenImageIO into float32 linear R, G, B; `read_frame`
  also returns the data and display windows, so array positions map back to
  frame positions. `exposure` reports luminance statistics. The package
  imports no `cv2` (blueprint P5, guarded by `tests/test_retina_boundary.py`),
  and numpy and OpenImageIO load only when a function needs them.
- **Worker side, `retina/frame_reader.py`.** One EXR part as linear R, G, B,
  picked by name, plus its origin (owner ruling QC-Q1). It mirrors the host
  reader without importing `synapse` or `cv2`. Integer formats are refused.

Producers: `tests/test_cv_reader.py` · `tests/test_cv_analysis.py` ·
`tests/test_retina_frame_reader.py`

### The supervised CPU worker and its host adapter (NR-WORKER-SUPERVISED)

**The worker** (`retina/worker_entrypoint.py`) reads one request JSON and
writes one result JSON beside it, atomically. It runs on the R4 CPU worker
interpreter (CPython 3.12.10 with OpenImageIO and `opencv-python-headless`),
never in Houdini.

- **One op only:** the firefly scan (owner ruling QC-Q7). Anything else is
  refused.
- **Read roots:** the frame must resolve inside a declared root, symlinks and
  `..` followed, or it is refused before any pixel is read.
- **The mask is a write into the render folder.** With the `beside_frame`
  policy (owner ruling QC-Q4) the worker writes `<frame stem>.fireflies.png`
  (`<frame stem>.subN.fireflies.png` for a non-zero subimage)
  next to the frame. The path is never taken from the request. A mask path
  that already exists as a link, junction, reparse point or multiply
  hard-linked file, or that resolves outside the frame's folder, is refused
  before the frame is read.

**The adapter** (`python/synapse/host/retina_worker.py`) is standard library
only.

- **Explicit interpreter, no discovery.** `SYNAPSE_RETINA_WORKER_PYTHON`
  must name an existing `*.exe` by absolute path (owner decision
  2026-11-10). Unset, relative, a `.bat`/`.cmd`, or any other file reads
  inconclusive `not_configured`.
- **Timeout:** 60 s by default, a safety bound, not a QC time budget. A
  worker that overruns is killed.
- **Never on Houdini's main thread.** A call there raises
  `MainThreadRefused` before anything is written or launched.
- Every other runtime failure (no start, timeout, non-zero exit, a missing,
  oversized or garbled result) reads inconclusive with the reason. A bad
  `timeout` or a non-path argument raises.

The new environment variable has its row in `docs/studio/DEPLOYMENT.md`.

Producers: `retina/worker_entrypoint.py` · `python/synapse/host/retina_worker.py`
· `tests/test_retina_worker_contract.py`

## Limits

**The owner's words, verbatim** (2026-11-10, recorded in the amendment's
`_owner_decisions`):

> "Decision 2: A — accept both open Codex gates as recorded limits; record my words in the amendment and the release Limits."

> "Decision 3: record leg C as a known machine precondition."

What those cover, and every other limit this note found:

- **No artist sees a finding from the new detector yet.** The existing frame-validation
  tool's saturation "firefly" check is unchanged. Nothing calls the worker or the adapter.
- **The detector's known limits** (from its module docstring, not re-measured): objects of
  7x7 pixels or less on a flat backdrop, curved or steep noise-free gradients and
  silhouette pixels can give false fireflies.
  There are no durable receipts (`NR-RECOVERY-RECEIPTS`) and no panel row
  (`NR-QC-PANEL-ROW`). No tool is registered for the detector.
- **Most of Render QC is not in Setup.** The detector, the worker-side frame
  reader and the worker entry point are outside the payload. The adapter and
  `python/synapse/cv/` ship, with no caller.
- **The Codex crux reviews did not run** for `NR-QC-FRAME-CONTRACT` and
  `NR-WORKER-SUPERVISED`: the Codex usage limit holds until 14 Nov. Both crux
  gates stay open. They do not block this release (QC-CODEX-LIMITS).
- **The seam-hunter hython leg did not run** for `NR-WORKER-SUPERVISED`
  (`harness/next-release/README.md` assigns it seam-hunter and Codex).
- **`NR-WORKER-SUPERVISED`'s graph predicate is still `test -f
  retina/worker_entrypoint.py`** (QC-OPEN-3). A behavioural predicate exists
  under `harness/next-release/proposals/predicates/` but is not the graph's.
- **The real OpenImageIO run covered one file shape.** The end-to-end tests on
  the real worker write one single-part RGBA half EXR (a 64x48 data window in
  a 96x80 display window) and read subimage 0. Multi-part files, other channel
  layouts and other pixel types were not run through the real reader.
- **The mask write has a check-to-write race.** The unsafe-path check runs
  before the frame is read, and the write comes later. A link planted between
  the two can redirect the write. This must be fixed before anything calls the
  worker.
- **Two decisions are not ruled:**
  - a cap on the firefly count: a huge whole number passes as candidates
    (`firefly_check({"count": 10**400, ...})` gives pass `True`);
  - a frame with non-finite pixels, a count of 0 and no usable frame size
    stays inconclusive (a `PLAN_GAP` in `firefly_check`).
- **A known crash in `_whole`.** `firefly_check` raises `OverflowError` on a
  count of `Fraction(10**400)`, because `_whole` converts a non-integer
  `numbers.Real` with `float()`. Reproduced on `35a31072`.
- **POSIX seats read `not_configured`.** The adapter launches only a `*.exe`
  on every platform, so a worker interpreter without that suffix is never
  launched.
- **Leg C's uninstall-registration precondition fails on this machine.** Its
  check `production_uninstall_registration_absent_before` has failed here
  since the 2026-11-09 live install created the per-user uninstall
  registration (leg C gave 18 of 19 on the `9cba9a6a` and `202902ad` seat
  builds). By the owner's ruling, that single check failing is a known machine
  precondition, not a release red; any other leg C failure is a red. This
  release's leg C result is in its verification record, a release asset of
  the `v5.100.0` tag.
- **Doctor's `runtime_provenance` can fail a seat that worked yesterday.** It
  fails on any loaded module from outside the runtime, `$HFS` and Houdini's
  Python. That is the point, and it is new.
- **`hash_mismatch` still fails with `MONETA_NATIVE` unset.** Only the
  fallback evidence moved to skipped.
- **Owner decisions still open:** QC-Q3 (the time budget, after
  `NR-QC-TIMING`), QC-Q5 (the frames and scratch scene for `NR-QC-TIMING` and
  `NR-QC-LIVE-CHECK`), QC-OPEN-1 (`NR-WORKER-SUPERVISED`'s
  `NR-GPU-QUALIFICATION` dependency), QC-OPEN-2 (the `NR-QC-PANEL-ROW` seam in
  `python/synapse/panel/claude_worker.py`) and QC-OPEN-3 (above). From
  ADR-0002, decisions 6, 7, 10, 11, 15 and 18, Windows 26H2 vendor support,
  and what "demo v1" means stay open; decision 9 is ruled, but amendment item
  OD-17 still reads open in `harness/next-release/proposals/` until that file
  is updated.
- **anthropic 2.x remains unsupported.** The pin stays `anthropic>=1.0.0,<2`.
- **The product-surface tool does not see `retina/`.** Its figure counts none
  of the three new `retina/` files; the payload allowlist is the measure.
- **Setup remains unsigned.** The interactive wizard, the registry and
