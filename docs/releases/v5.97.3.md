## The short version

- **The Moneta Rust module stays out unless you opt in.** `MONETA_NATIVE=0` keeps the native module from loading when it is set before the first Moneta import. The native state is reported in memory status and in provenance.
- **A native panic no longer escapes in two places.** A panic while building the Moneta-backed store falls back to the JSONL store. A panic inside `synapse_sleep_pass` returns `ran=False`. A sleep pass that fails after pruning is audited.
- **A sleep pass needs an opt-in.** It runs only when `SYNAPSE_ALLOW_SLEEP_PASS=1` is set. On the WebSocket path it no longer runs inside an undo group.
- **Side fixes.** A false Solaris merge warning, test isolation, a CLAUDE.md drift fix, and a deployment-doc row for the new variable.
- **Not fixed here.** Risk B, the loss of undrained attention on every save. The WebSocket panic arm is not built. No check recorded for this range ran under hython.

## What changes

### Native Moneta: kill switch, status, panic fence, provenance

- **`28dd117b` NATIVE-KILL-SWITCH.** Moneta imports `moneta_native` when its package loads, and it reads `MONETA_NATIVE` only when objects are built. Before this commit, `MONETA_NATIVE=0` still loaded the DLL into Houdini. Now, when the value is exactly `0` and the module is not yet loaded, `moneta_runtime` puts `None` into `sys.modules` before `import moneta`. Moneta then stays on its pure-Python path. A module that is already loaded is left alone and reported as `already_loaded`. Test: `tests/test_moneta_native_kill_switch.py` (fakes only).
- **`fcfbc287` NATIVE-STATUS.** `memory_status` reports whether the native module is `not_loaded`, `blocked` or `loaded`, with its file, version, size and mtime. It never imports anything and never raises. It catches `BaseException`, because PyO3 panics are `BaseException`, and re-raises `KeyboardInterrupt` and `SystemExit`. Test: `tests/test_memory_native_status.py`.
- **`8fffe324` B-PROVENANCE.** `moneta_provenance()` gains a `native` block with the same state, the `MONETA_NATIVE` value and any helper error. Every existing key is unchanged. Test: `tests/test_moneta_provenance_native.py`.
- **`d9964aa2` PANIC-FENCE-CONSTRUCTION.** A Rust panic reaches Python as `pyo3_runtime.PanicException`, which derives from `BaseException`. It passed the `except Exception` fallbacks, so no store was served, nothing recorded the fallback, and every later call panicked again. The Moneta and shadow construction paths now take a second arm that catches a native panic only. It logs the panic, records the fallback with a reason that names it, and serves the JSONL store. `KeyboardInterrupt`, `SystemExit`, `GeneratorExit` and `CancelledError` still propagate. Test: `tests/test_native_panic_construction.py` (fakes only).
- **`6fcdb445` PRUNE-AUDIT-ON-FAILURE.** Moneta's `run_pass` removes the prune set before it stages, authors and snapshots. A pass that raised late had already deleted rows, and the next save made that permanent, but nothing recorded what was pruned. A failed pass is now audited as `FAILED-PASS`, with its payloads, and the original exception is re-raised unchanged. Test: `tests/test_prune_audit_on_failure.py`.

### The sleep pass: opt-in, outside the undo group

- **`d459f406` D4 (decision 2).** One gate sits at the top of `_handle_sleep_pass`. The pass runs only when `SYNAPSE_ALLOW_SLEEP_PASS` is exactly `1`. Otherwise it returns `ran=False` and `refused=True`, with a reason that names the opt-in. The payload is not read.
  - **Behavior change.** A caller that expects `synapse_sleep_pass` to prune must set the variable. The panel worker's DENY list (`panel/worker_policy.py`) is unchanged.
- The handler no longer calls `bridge.execute()`. It opens no undo group of its own, so no `performUndo` can take back the artist's last edit. A pass that ran appends one observe-only `IntegrityBlock` (`execution_path "live"`, agent CONDUCTOR, with consent, undo and composition recorded as not applicable).
  - **Route caveat.** The in-Houdini HTTP `/mcp` route and the panel's tool route still send every non-read-only tool through `execute_through_bridge`, which wraps the handler in the bridge's outer undo group (`panel/bridge_adapter.py:437-452`). An opted-in pass on those routes therefore still runs inside an undo group. The default refusal holds on every route.
- Both ungated `_do_prune` fallbacks are deleted: the one under `except ImportError` and the one under `except Exception`. The second could run a second destructive pass after `execute()` failed.
- A PyO3 panic in the sleep pass returns `ran=False`. `KeyboardInterrupt`, `SystemExit`, `GeneratorExit` and `asyncio.CancelledError` still re-raise.
- Tests: `tests/test_sleep_pass_consent.py` (new, 25 cases) and `tests/test_sleep_pass_gate.py` (its bridge-path pin moves with the change).
- `docs/studio/DEPLOYMENT.md` documents the variable (`02a1862a`).

### Solaris merge warning (side fix)

- **`725e7d30` B-SOLARIS.** The validator read a wire with no `input` as input 0 on every target. Into an existing merge, the planner treats such a wire as an append onto the lowest free input. Two appends therefore warned `input gap: indices [0, 0]`, while the planner placed them at 0 and 1. The validator now skips implicit appends into existing targets. A missing input on a new target is still input 0. The planner did not change. The v5.97.2 production validation had recorded this warning on the 22.0.400 seat (`harness/notes/release-v5.97.2/production_validation/production.json:124`). Test: `tests/test_solaris_merge_unordered.py` (new).

## Limits that remain

- **Risk B is not fixed.** Every save writes ECS rows and unlinks the WAL. Undrained attention is lost at the next store switch or quit, and nothing drains it automatically. The artist sees no error (`TAKEOVER_REPORT.frozen-e6717419.md:245`). The fix is planned for the next Moneta release: attention durability (R1′), the WAL fsync (F1) and the ce45 decision (`PROGRAM_2026-10-18.md` row 3; CTO D7). `d459f406` closes only the register row `NEW-SLEEP-PASS-UNGATED` (`:249`), the one-call path that prunes what risk B leaves prune-eligible.
- **The WebSocket panic arm is not built.** `PanicException` handling at the WebSocket connection handler (`websocket.py:607`, as the takeover report cites it) is absent. No `PanicException` or `is_native_panic` reference exists under `python/synapse/server` except in `handlers_memory.py`. The arm touches core server code and needs a ruling (`TAKEOVER_REPORT.frozen-e6717419.md:156` and `:235`). The sleep-pass arm is built, at `handlers_memory.py:586-590`.
- **The provenance version label can mislead.** `_dist_version()` reads installed-package metadata. With Moneta source on `PYTHONPATH` over a pip-installed `1.2.0rc1`, provenance can label `1.3.0rc1` code as `1.2.0rc1` (`TAKEOVER_REPORT.frozen-e6717419.md:614`; CTO F6). `8fffe324` reads the native module's own namespace and leaves `_dist_version()` as it was.
- **CI shows that Moneta imports, not that the Rust extension runs.** The CI Moneta steps run only when the `MONETA_DEPLOY_KEY` secret is set (`.github/workflows/ci.yml:65`, `:89`, `:93`). It is set: the v5.97.2 release-commit run printed `Moneta available: True | import_error: None` ([run 38263471969](https://github.com/JosephOIbrahim/Synapse/actions/runs/38263471969)). That line shows Python availability only (candidate document lines 14 to 16). CI has no Python 3.13 arm (CTO F4, line 89).
- **Nothing here has run under hython.** The rc1 binary has never run under hython. The hython seat suite for 5.97.3 is a separate launch with its own go (CTO line 49). The takeover report records earlier hython 22.0.400 launches whose launch contexts were not captured, including a sealed 10-14 child-category run (`TAKEOVER_REPORT.frozen-e6717419.md:76-77`). The H22.0.400 evidence that `docs/inspection-child-category.md:41-44` cites was taken for the candidate's two product files before `85b6cce4`. That commit changed the advisory wording in both files, so those pinned hashes no longer match the tip.
- **Python 3.13 evidence for the code after `725e7d30` is syntax only.** The two merge reviews compiled the changed product files under Python 3.13.14 (`handlers_memory.py`, `introspection.py`, `selection_snapshot.py`, `scripts/install_synapse_package.py` and `moneta_runtime.py`). The 3.13 import smoke predates D4's change to `handlers_memory.py`.
- **Python 3.13 risk.** Five of the nine changed product modules lack `from __future__ import annotations`. Every green run here was on CPython 3.14. The seat runs 3.13.10 (CTO line 104).
- **The live seat is unchanged by this release.** D6b, which pins `MONETA_NATIVE=0` in the deployed package, waits for the landing window (CTO line 39). A takeover-time edit to the deployed package during a helper test was reverted byte-identically (CTO "Disclosure", lines 109 to 115).
- **The receipts are local.** `private-recovery-records/` is git-ignored (CTO line 27). The takeover citations in these notes resolve only in the maintainer's checkout. They do not ship with this repository.
- **The `child_category` field is new.** Consumers that reject unknown response fields need separate compatibility qualification (`docs/inspection-child-category.md:24-25`).
- **Held phantom rows.** `hou.cookPDGGraph`, `hou.pdg.workItem` and `hou.pdg.cookWorkItems` are ratified but not landed. With them present, `tests/rulebook/test_rulebook_meta.py` test 5 fails on `scout_eval.py` lines 52 and 55, which need them. `usdrender` is held too, because the lint pattern matches `usdrender_rop` (95 hits) (`0bb13764`).
- **Behavior change.** `synapse_sleep_pass` is refused unless `SYNAPSE_ALLOW_SLEEP_PASS=1` is set (`d459f406`).
- **Automatic consolidation has neither new guard.** With `SYNAPSE_AUTO_CONSOLIDATE` on (it is off by default), `add()` calls `run_sleep_pass()` without the `SYNAPSE_ALLOW_SLEEP_PASS` gate. That path has its own opt-in and a mirror-safety refusal, but its handler catches `Exception` only, so a native panic there escapes the `add()` that triggered it (`python/synapse/memory/moneta_store.py:1020-1028`).
- **Two routes still wrap an opted-in pass in an undo group.** On the in-Houdini HTTP `/mcp` route and the panel's tool route, `execute_through_bridge` still opens the bridge's outer undo group around the handler (see the route caveat under "The sleep pass"). Only the WebSocket path runs the pass outside any group. The default refusal holds on every route.
