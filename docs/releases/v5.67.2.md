# v5.67.2 — Memory LOOP substrate fixes

This release connects the optional observational memory LOOP and fixes two
runtime paths that could prevent it from working reliably in Houdini.

- **Recall feeds the next operation.** SYNAPSE borrows the existing Moneta owner,
  composes an allowlisted private context stage with Octavius, records a Hanish
  forecast before dispatch, and returns the observed handler outcome to durable
  Moneta memory. The next context request can recall that result.
- **Recovery preserves evidence.** Failed deliveries remain in a durable outbox.
  Retries reconcile existing forecasts and deposits without replaying scene
  actions, duplicating outcomes, or turning missing evidence into a failure.
- **Substrate subprocess waits stay off the interface thread.** The native Houdini WebSocket
  path now awaits a worker for enabled LOOP operations. Panel fallback dispatch
  brackets its existing main-thread bridge call from a worker as well.
- **Reopening the shipped panel retains its memory owner.** The loader refreshes
  panel code and its import-cache references while keeping host, server, session
  and memory modules alive. Qualified worktree deployments can retain their
  original configuration through the explicit `SYNAPSE_ROOT` setting.
- **Solaris reference intake has provenance.** Eight Rob Pieke H22 Solaris notes
  include source timestamps and excerpts. Intake verifies the source file hash,
  is idempotent, and labels each note as reference knowledge rather than a
  runtime-verified procedure.

The release also includes the previously unreleased Stage 0 lookdev experience
scaffold and artist-requested saved lookdev suggestions. Suggestions remain
bounded to the supported fixed lookdev fixture; they do not provide general
predictive node-network creation.

Stage 0 experience matching includes the exact SYNAPSE version. Checked
experiences recorded against v5.67.1 require a new matching developer rehearsal
and import for v5.67.2 before they can appear as suggestions.

## Artist control and configuration

The LOOP is **off by default**. Enabling `SYNAPSE_LOOP_ENABLED=1` requires explicit
paths to qualified Hanish and Octavius sources and a compatible Houdini USD Python
runtime. Dependencies are not installed automatically. Configuration and data
flow are described in [MEMORY_LOOP_REPAIR.md](../MEMORY_LOOP_REPAIR.md).

This is observational scaffolding. Existing consent and artist instructions
remain authoritative. It does not automatically choose actions, edit approved
networks, train a predictive model, or perform recursive policy improvement.
A Hanish HIT here only describes the narrow synchronous handler outcome; it
does not establish artistic quality or render correctness. SALUS path evaluation
remains unavailable and is never reported as approval.

## Qualification

The repair was exercised with real Moneta, Hanish and Octavius interfaces,
including successful and failed handler outcomes, unknown outcomes, lost
acknowledgements, failed deliveries, reopening memory, and a second operation
consuming the first operation's recall. In live Houdini 22.0.400, the native
connection completed the cycle and the next request recalled its durable result.
Solaris source notes were imported and retrieved in the live project. A separate
Houdini-Python process reopened a copy of the actual durable project snapshot and
recovered the stored notes and outcomes.

Mutation tests rejected fabricated pre-action authoring, removal of
worker offload, global panel-module purging, stale UI import-cache references,
and loss of the configured source root. The pre-release repair runs included
294 focused checks, a later 83-check composed run, and 42 configuration/auth checks;
these suites overlap and are not a unique-test total. The v5.67.2 release candidate
passed **208 checks with zero skips**, including the real-substrate LOOP tests,
Stage 0 lookdev scaffold, panel reload, authentication and version conformance.

These checks do not qualify arbitrary Solaris graphs, production-scale latency,
or the eight lecture workflows as executable recipes. A complete GUI restart
and GUI panel reload after local deployment were not exercised; isolated repeated
loader execution and fresh-process memory/configuration checks were exercised.
The optional model-backed panel demonstration remained at the artist's connection
consent prompt. No live project memory or recovered personal records are included
in this release.

**Restart Houdini after updating the Python files.** Reopening the panel refreshes
its UI; it deliberately retains backend owners. The existing
[v5.67.1 qualification limits](v5.67.1.md) and standing production-hardening
requirements remain in force. This release does not close them by implication.
