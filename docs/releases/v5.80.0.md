# v5.80.0 -- the corpus arrives, and the referee reads it

**No product change beyond the version string.** `python scripts/product_surface.py --diff v5.79.1 HEAD`, measured after the release commit: 1 file, +2/-2, and both lines are `__version__` in `python/synapse/__init__.py`. Nothing else under `python/`, `mcp_server.py`, the tool modules or the installer moved. This release ships knowledge and instruments -- an H22 prose corpus, 31 vendored workflow guides, an outside-in benchmark harness, and two verify tools -- plus one README correction. The panel you run is v5.79.1's panel.

**No new installer in this release.** The `SYNAPSE-5.75.2-Setup.exe` the README links is the last built installer and does **not** carry these files.

## What landed

**An H22 prose corpus builder, with a phantom gate.** `rag/ingest/help_archive.py` reads SideFX's help archive into `rag/corpus/h22_prose/` and refuses any page that names a node type the live catalog does not know. Every chunk carries which scope it came from. (BP10-CORPUS; 15 fixture pages under `tests/fixtures/help/pages/`, 15 tests in `tests/test_help_archive.py`.)

**One scope-ranking table.** `rag/retrieval/scope_weights.py` ranks `h22_prose` above `guide` above `h21`, as a table rather than a heuristic buried in code. How-to phrasing ("set up", "how do I", "why does") lifts the guide scope above prose; a bare node or parameter name keeps prose first. The guide slot was landed inert by CORPUS and switched on by GUIDES in the same release. Editing the ranking is a text diff in one file. (12 tests.)

**31 workflow guides through the gate, with provenance.** `rag/ingest/guides.py` pulls the fxhoudinimcp guides (MIT, @ 29b6695b) into `rag/corpus/guides/`, one jsonl per topic, and quarantines any guide that names a phantom node. Five went to `rag/quarantine/guides/` (assets, heightfields, io, model, render) with the offending tokens listed, and `harness/notes/harvest/answer_key.json` is the empty template where the fix-or-drop decision per token gets recorded. (BP10-GUIDES; 9 tests in `tests/test_guides_ingest.py`.)

**Stated plainly in the README: staged, not yet served.** v5.79.0's README listed the guides corpus under "What's ready". No runtime path consults `rag/corpus/guides/` yet -- `KnowledgeRouter` still reads the semantic index and `corpus/h22_nodes.json` only -- so the line was a false readiness claim on an owned surface, and CRUX marked the leg BROKEN on that one line. It now sits below the list as "Staged, not yet served", with the provenance kept public. The serving wiring is a later act.

**An outside-in benchmark harness.** `harness/outside_in/` runs the same prompt through two isolated hython arms, SYNAPSE and fxhoudinimcp, and `verify.py` checks the resulting scene rather than the transcript. A prompt-leak check confirms neither arm can see the answer key. Plumbing is proven on one prompt; the full run (G5) is held for Joe's word, so no comparison number is claimed here. (BP10-BENCH; 8 + 7 tests.)

**Three Jev guards, in shadow.** JEV-RERANK (does this retrieved chunk answer the query), JEV-HARVEST (is this quarantined token a renamed node, a parameter, or a generic word), and JEV-BENCH (does the scene satisfy the prompt). Each is ledgered under `harness/jev/ledger/bp10.*.jsonl` and graded by `harness/jev/jev_grade.py --guard <name>`; none of them decides anything yet.

**Two verify tools, from PRs #109 and #110.** `harness/verify/gate_table_agreement.py`, a deterministic lint that surfaced 16 rows where a gate table disagrees with itself (advise-only, ratcheted), and `harness/verify/recall_oracle.py`, a recall-quality oracle that replays a store copy and scores relevance against an answer key.
