# v5.93.1 — The read says whether the camera's path is drawn, its undo step has a name in words, and a receipt goes after a hand undo

Five fixes from the checks of [v5.93.0](v5.93.0.md). Four of them close limits
that release listed.

**The read says whether the path is drawn.** `synapse_spatial_path` measures a
camera's move. It now also says whether SYNAPSE's guide curve for that camera
is on the stage it read. The result gains a `trail` field: `drawn`, `absent` or
`bypassed`, with the node, the prim and the point count where there are any.
Its sentence ends with one plain statement: the path is drawn on this stage, it
is not drawn, or it is not drawn because its node is bypassed. Drawn takes both
halves: a trail node of SYNAPSE's for that camera at or above the node that was
read, and the curve on that node's stage. The read is still read-only. v5.93.0
listed the gap: after an undo, a repeat ask was answered that the path was
still in the scene, when it was not.

**The path's undo step has one name, in words.** Houdini's Edit menu and status
bar named the step `SYNAPSE: synapse_spatial_trail: {}`: the tool's internal
name and its arguments. The tool's own result called the same step something
else. Both now read `SYNAPSE: Draw camera path`, whichever way the tool was
reached, and the Spatial control's answer ends "One Ctrl+Z reverses: Draw camera
path." Every other tool's step keeps the name it had.

**A receipt goes after a hand undo.** A click on Spatial, or a turn that draws
the path, leaves a "1 CHANGE" receipt with REVERT. When the artist then undid
the change by hand, the receipt stayed and went on claiming a change the scene
no longer had. The panel now reads Houdini's undo history on its two-second
tick, and hides the receipt once the history no longer holds that turn's steps.
It only hides. A REVERT click that lands before the next tick still refuses in
the words it had, and a redo does not bring the receipt back.

**The Spatial control leaves out a hint written for a model.** On an empty
scene the control answered "Spatial: /stage has no display node -- Pass a LOP
node path". A click passes nothing, so the second half was no use to an artist
at a control. The control now shows the reason and leaves that half out. A
model that calls the tool still gets the hint.

**A test run keeps out of the live log folder.** This one is for developers. A
full run of the test suite on a workstation left halt and freeze files in
`~/.synapse/logs`, where an open Houdini session keeps its own, and under
hython the render workspace's check rewrote the sidecar file that a live
session's clients read to find it. A test session now gets a folder of its own
for its logs and its sidecar.

**Source release for Houdini 22.0.400 / Python 3.13.** No new Windows Setup is
included. The v5.86.0 Setup contains none of the changes in v5.87.0 through
this release. Follow
[source installation](../getting-started/installation.md#source-installation),
then restart Houdini to load the updated source.

## Validation and limits

**The read, live.** In hython 22.0.400, on a copy of the demo scene, with the path drawn the read ended "Its path is drawn on this stage as /guides/demo_cam_path (144 points)." After one undo it ended "Its path is not drawn on this stage." After a redo the path was drawn again. With the trail's node bypassed, the read named the node, and the node stayed bypassed. The result was 1,633 characters with the path drawn and 1,520 without, against a limit of 1,800. The four reads took 0.70 to 0.78 s each.

**The undo step, live.** Through the panel's execution bridge with its undo wrapping forced on, one call to the trail added one entry to Houdini's undo history, `SYNAPSE: Draw camera path`, and the tool's result reported the same label.

**The receipt, live.** With the real panel offscreen in hython 22.0.400, on a copy of the demo scene and against Houdini's own undo history: a click showed "1 CHANGE". A tick left it. A selection change on top of the undo stack left it. After the undos that took the path back out, the next tick hid it. REVERT then refused in the words it had. A redo left it hidden. A fresh click followed by REVERT reverted. Reading the undo labels took 0.004 ms with 101 entries in the history, 0.04 ms with 1,001 and 0.12 ms with 3,001.

**The empty scene, live.** On an empty scene the tool said "/stage has no display node -- Pass a LOP node path", and the panel said "Spatial: /stage has no display node".

**Through the panel agent, headless.** Eleven conversations, nineteen turns, each conversation starting from a freshly loaded copy of the demo scene in hython 22.0.400, with the worker built as the panel builds it, on deepseek-v4.1-flash:cloud through Ollama.
- The path was drawn, then undone, and the model was asked directly whether it is still drawn. On this release: one call, to the read, and a right answer. On v5.93.0, twice: 4 and 6 calls, 3 and 4 of them errors, and a right answer both times.
- The path was drawn, then undone, and the same request was sent again ("Show me where this camera travels, and how close it gets to anything."). On this release, three runs: one read the stage, said the path had gone, and redrew it; one redrew it while saying nothing had changed; one made no tool call and said the path was already drawn, which was false. On v5.93.0, twice: both redrew it, one in 1 call and one in 7.
- The plain read, the UNKNOWN case and the draw request ran once each on this release, in one tool call each. The read's reply now says the path is not drawn.
- On v5.93.0 the drawn step's name in Houdini's undo history was `SYNAPSE: synapse_spatial_trail: {}`, or the same with the camera's name in the braces. On this release it was `SYNAPSE: Draw camera path` every time.

**Tests.** New test files: `tests/test_stale_receipt.py` (31 tests) and `tests/test_session_scratch.py` (4). `tests/test_spatial_handlers_pxr.py` gained 7 tests against real USD stages, `tests/test_spatial_action.py` gained 3, `tests/test_spatial_tools.py` gained 2 through the execution bridge, and `tests/panel/test_bc_wave.py` gained one on real Qt. The render workspace's own check passed under hython 22.0.400, and the sidecar of a Houdini session that was open at the time was byte-identical before and after it. The full `tests/` suite passed on the release tree on Windows with Python 3.14, with the tests that need a Houdini runtime deselected as CI does: 10,774 passed, 428 skipped, 183 deselected, 5 xfailed, 0 failed. Publication requires all six GitHub CI jobs to pass on the exact tagged commit, linked in the GitHub release.

**Limits.**
- **Not seen in the GUI.** Every check above ran in hython, or with the real panel offscreen. None of the five changes has been seen in the Houdini GUI. Two of them show there: the Edit menu and the status bar with the step's new name, and the receipt going after a hand undo.
- **Scope of the runs.** Everything ran on one model, deepseek-v4.1-flash:cloud, and on one scene.
- **The model can answer from its history.** Asked again after an undo, one run of three made no tool call and said the path was already drawn. It was not. The read's new sentence helps only when the read is called. After an undo, ask for a redraw.
- **Up to two seconds.** The receipt goes on the panel's next tick, so it can stay for up to two seconds after an undo.
- **Other tools' undo steps.** They still read as the tool's internal name and its arguments.
- **The audit log.** A full test run still appends about 47 KB to the real audit log in `~/.synapse/audit`. That log has no folder override.
- **A killed test run leaves its folder behind** in the system's temporary directory.
- **Two processes, one memory store.** A second Houdini process that loads a scene under the same `$JOB` binds the same memory store as the first, and the snapshot written last wins. This release's own checks met it on 2 October. It is not fixed.
- **The panel tests on real Qt.** They are not part of stock CI, and some fail before and after this release. Under hython on the workstation, 587 passed and 32 failed on this code, against 580 and 33 on v5.93.0. Every one of the 32 is among the 33. The one that passed this time is a test of closing a dialog during model discovery, which nothing in this release touches.

The inherited [v5.93.0 limits](v5.93.0.md#validation-and-limits) remain, except four: a receipt staying after a hand undo, the read not reporting whether a path is drawn, the undo step's name, and a reason worded for a model.
