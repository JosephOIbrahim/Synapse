## The chat follows the scene

v5.96.0 did not have this (its notes say "PUX-01 is not in this set"). It lands here as five commits, `e96d5bd1` through `f3f9d8c6`, in merge `7e8b3a41`.

**Before, a scene change could put one scene's chat into another scene's store.** `save_conversation()` with no path looked up `hou.hipFile` on every call, while the panel loaded its conversation once. After File > Open, the next save wrote scene A's chat (or an empty list) over scene B's `$HIP/claude/conversation.json`.

**Now the panel pins the file it loaded from.** Every save goes through `save_conversation_pinned` to that file, and the panel listens to `hou.hipFile` events:

- **Save As into another folder** moves `conversation.json` and its owner sidecar into the new `$HIP/claude/`, re-pins, and writes the live chat there. A chat already in the destination is parked into the destination's previous slot, which replaces any older previous there. The source's `conversation.previous.json` moves only when that slot is empty. Otherwise it stays in the source folder.
- **A plain save, or a Save As in the same folder,** touches nothing.
- **File > Open, and File > New outside a load,** save the chat to its own scene, then load the new scene's conversation as the model's history. The chat display gets one line: 'Scene changed', or, when that scene's chat is from an earlier Houdini boot, the parked-session notice. Old turns are not re-rendered, so the previous scene's messages stay on screen above that line, as with /restore-session.
- **A File > Open or File > New during a running turn waits.** The turn saves to the scene it was asked in, then the panel follows. A Save As during a turn follows at once, and the turn's answer is saved in the new folder.

**Every Save As follower keeps the parked previous chat (PUX-01c).** With two or three panels pinned to one scene, each follows the same Save As. `session_store.move_conversation` now records the carry on every completed follow (`session_store.py:205`), so a second or third panel no longer parks the first one's chat over the destination's previous slot. A failed follow (`OSError`) records nothing, so a later follower retries.

**Tests.** Four new test files under `tests/panel/`. None of them constructs `SynapsePanel`; they call the panel's methods and `session_store` with stand-ins. `test_conversation_follows_scene_every_shape.py` enumerates 96 shapes (source, source state, destination state, one to three panels) and asserts the exact files at both ends. Its commit records 12 of the 96 failing on the code before the fix (`f3f9d8c6`).

## Recall: `found` means a remembered decision

**At `scope=all`, a reference-docs row no longer sets `found=true`** (RECALL-P4, `b2585d89`). The recall handler adds a knowledge row to `matches` at `scope=all`. It used to set `found=true` when it did, so an empty store answered "found" with nothing remembered. Now `found` is whatever the store reported about decisions. The knowledge row stays in `matches` as context, and `count` and `knowledge_found` are unchanged.

**What the artist sees changes.** A knowledge-only recall now shows the panel's recall card as **NO HIT** (`recall_card.py:32-33`). Before this release the panel hid the card for a knowledge-only recall.

**One existing test changed,** as the Jev ruling allowed: `tests/test_recall_rag_seam.py` now asserts `found` is false for a knowledge-only result. `tests/test_recall_found_means_decision.py` is new.

These notes cite no new recall-eval run. The v5.96.0 recall numbers were measured before this change.

**One existing test changed,** licensed by the ruling: `tests/test_level1_m2.py` now expects `needs_artist`. `tests/test_doctor_gate.py` is new. The commit records no live Houdini run of this change.

## Code renders in Space Mono

**Before, code in the chat fell back to a generic monospace face** (DES-D01, `711cafdd`). The font stack quotes its family names (`"Space Mono", ...`), and the formatter put it raw into double-quoted `style="..."` attributes. The first quote closed the attribute, so Qt lost the family and everything after it, including `white-space:pre-wrap` on fenced blocks.

**Now the stack is escaped once** (`message_formatter.py:83`), and every code style in the transcript uses the escaped copy: the fenced block, its language label, inline code, the node-path chip and the timestamp. The typing indicator's sans stack is escaped the same way (`chat_display.py:1059`).

**What changed on screen** (offscreen renders, not committed: `rsi-pd/design/renders/DES-D01/before.png`, `after.png`). Before: the fenced block, the `vex` label and inline code in a Courier-like face. After: all of them, and the `/obj/geo1` chip, in Space Mono.

**Checks.** The commit measured the rendered fonts offscreen on hython 22.0.400. The CTO review ran the Qt font test and the Copy-control tests under hython 22.0.400 (17 passed, `merge_decisions.json`, DES-D01). On stock Python the Qt test skips; `tests/test_code_font_attr_escape.py` checks the HTML without Qt.

This closes the v5.96.0 limit "The code block's style is cut short" ([v5.96.0](v5.96.0.md), Limits).

## `bend_twist` twists on the Bend SOP

## Harness: the rope graph (development only)

None of this ships into Houdini. All five are in `harness/rope/graph.py` (H-NOSTASH also adds two lines to `GRAPH.md`), each with new tests.

- **No `git stash`** (H-NOSTASH, `76b998b9`). Every scout, fixer and referee prompt now forbids it and says to read old code with `git archive`. Stash refs live in the shared `.git`, and two lanes swapped patches on 2026-10-07.
- **Compound evidence is read as quoted spans** (H-EVIDENCE, `92860698`, `159216d5`). A quoted span counts only when it directly follows a `file:line` cite.
- **One word is never line evidence** (H-L2, `e1a23992`). The veto was replayed over all 86 routed findings of the cto run on their base tree, with the same verdict, line and evidence before and after the word rule. The replay found one more hole: a cite under `C:/Program Files` dropped the repo root, so a path that is drive-rooted, `/`-rooted or contains `..` is now vetoed "outside the repo" (`graph.py:905`).
- **A kept fix on the reference pages names the stale semantic index** (H-L1, `f29600f0`, `7a07b4ff`). The fix's note says `semantic index stale: run scripts/refresh_knowledge.py`, and the status line batches every such fix. It records the refresh; it does not run it.

Every session prompt carries the rule, and `gate()` returns `hython_bare` for a new `.py` file that runs under hython, imports `synapse`, and never stubs the package (`graph.py:671`). New modules inside `python/synapse` are skipped.

## Held back: H-PD1

**Loop 2's lesson was held by the CTO merge review and reverted.** H-PD1 (`d78fd959` through `91fe3def`, merge `4a74c906`) let the rope gate see and force-add a declared new file under a gitignored path such as `.synapse/contracts/`.

**Why it was held** (`merge_decisions.json`, H-PD1). The gate could copy a declared ignored path over an existing untracked ignored file of the same name in the main checkout, for example `.synapse/contracts/live_data.json` in the CTO's probe. `rope.revert` cannot restore that file, and on keep the overwrite is force-committed. The review asked for a repair on the branch.

**What the revert did** (`f41e56cd`). It removes H-PD1's gate code, its `GRAPH.md` lines and its test file. The `NEW` constant stays, because the H-PD3 hython gate reads it, narrowed to `("??",)`. The CTO review had asked for a repair forward rather than a revert; the revert was chosen to keep the change out of this release.

**What this leaves open.** The problem H-PD1 addressed is not fixed in this release: the rope gate still does not see a new file under a gitignored directory.

**Product**

- **After File > Open or File > New the transcript still shows the old scene's turns.** Only the model's history switches (`e96d5bd1`).
