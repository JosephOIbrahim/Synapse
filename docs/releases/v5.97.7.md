# SYNAPSE v5.97.7

**This release changes no product behaviour.** The shipped product diff from
v5.97.6 is the version string, plus two documentation lines inside the
installer's own README. The rest of the diff is test and CI wiring: the
`testpaths` list in `pyproject.toml`, two new steps in the CI workflow, and one
Windows race fix *inside a test file*. None of it changes what the product
does. What this release adds is evidence: an audit of an external Gaussian-splat
blueprint run against the live build, the standing probe that corrected one of
its findings, and two harness boards — neither of which has an open gate.

The v5.97.6 tag and its assets are preserved. Nothing about the existing
Windows Setup behaviour, the Moneta 1.3.0 pin, or the native-artifact policy
changes.

## What changes

### A World Labs Gaussian-splat blueprint was audited, and its script does not run

An external blueprint supplied to the seat (a `.docx`, not a SideFX or repo
document) proposes a World Labs Gaussian-splat pipeline for SYNAPSE. Every one
of its calls was executed against Houdini 22.0.400 and the result recorded from
the raised exception, not inferred.

- **Eight defects, in an eleven-entry ledger.** The script dies on **line 27** —
  the **third** node creation it makes, and the first that raises: a `geo` and
  a `file` are created successfully first, then `createNode("labs::bake_gsplat")`
  fails with `OperationFailed: Invalid node type name`. Everything after it never
  executes: the Solaris stage, the Karma settings, the render ROP. Three of the
  eleven entries are not defects. One names a method the script never calls.
  One describes a call the blueprint's own run never reaches. One was refuted
  by measurement. What remains covers **six calls that raise** and **ten
  parameter writes that name parameters that do not exist** — the wrangle's six
  channel parameters, then `intensity`, `exposure`, `renderer` and `samples`.
  Its `usdrender` node does not resolve in `/stage`; the LOP is
  `usdrender_rop`. Its `labs::bake_gsplat` node does not exist under that
  name; the built-in is `bakegsplat`.
- **Eight claims the code does not implement.** The blueprint's own
  "Corrected Error Audit" section claims a USD coordinate conversion, a
  pre-compiled VEX AST with schema gates, programmatic graph disconnection, a
  Karma XPU time-sample render with an FFmpeg export, a collider point group,
  automated absolute-path resolution, an automated lighting linker, and a
  completed desert half of the transition. Six of the eight are **prose**, and
  those are measured by counting the terms the claim would need, not by
  reading the claim. Five of them name terms the blueprint's own source does
  not contain at all. The FFmpeg claim is the sharpest: `mp4` and `sequence`
  appear once each, and both are inside strings — a hardcoded output path and
  a `print`. `usdrender_rop` has no video output parameter, and the script
  prints a line saying it is exporting a file it never writes.
- **The pipeline concept survives; the script does not.** A corrected script is
  landed with all eleven corrections applied, and it verifies **11/11** against
  the live build — the committed receipt records all eleven as passing on
  Houdini 22.0.400. The eight unproven claims stay open on purpose, each with
  the probe that would settle it. No World Labs asset was available, so no
  claim is closed by argument.
- **The wrangle needs seven channels, and the blueprint creates none of
  them.** Its VEX reads six float channels — `strength`, `spin`, `radius`,
  `falloff`, `drag`, `timestep` — and one **vector** channel, `chv("axis")`,
  which selects the spin axis. The corrected script creates all seven. The
  vector one is the sharp end: Houdini has **no `hou.VectorParmTemplate`** —
  the 22.0.400 symbol table carries `hou.FloatParmTemplate` and no vector
  form, and calling the missing one raises `AttributeError: module 'hou' has
  no attribute 'VectorParmTemplate'` — so the axis is a `FloatParmTemplate`
  with three components. And a multi-component parameter is **not** reachable
  as `parm("axis")`, because Houdini splits it into `axisx`/`axisy`/`axisz`,
  while `chv("axis")` **does** resolve the base name. A cook proves it. Until
  that seventh channel exists, the entire spin branch is dead code.

[corrected script](https://github.com/JosephOIbrahim/Synapse/blob/master/harness/probes/worldlabs_pipeline_corrected.py)

### The node catalogue was cleared — the finding that accused it was wrong

The audit originally reported that the repo's node-type authority
mis-described three Houdini 22 types. A live probe shows that was wrong, and
the audit is corrected in place.

The shipped catalogue matches the build exactly. For every audited type the
catalogue's parameter set equals the live type's own parameter interface:
17/17, 42/42, 131/131, 123/123, 194/194 and 73/73, with a Jaccard identity
match of **1.000** for each entry against the type it names. `usdrender`
resolves in both of its contexts. The original observation came from creating a
TOP node directly under `/tasks` — which is the scheduler, not a TOP network.

Two real hazards remain, and both are rules for the *consumer* of the
catalogue, not defects in it:

- **Alias resolution.** `createNode("gltf")` returns a `gltf::2.0` node, and
  `createNode("distantlight")` returns `distantlight::2.0`. Parameter names read
  from the unversioned catalogue entry are absent on the node you actually get:
  14 of 17 and 58 of 123 respectively. Read the catalogue entry for the type
  `createNode()` returned.
- **`#` in parameter names.** Names such as `animid#` are Houdini's spare
  parameter slots — present in the node's own interface, exposing no value to
  set. **7,155 of 152,918** catalogue parameter names (4.7%) carry one, across
  eleven category files. It is a Houdini-wide convention, not a fault of three
  types.

A standing probe now reads the live build and compares the catalogue against
it. It exits non-zero if a catalogue entry names a parameter no live type
carries, or matches no live type at all. The alias and spare-slot findings are
reported by the probe, not treated by it as failures — they are rules for the
consumer, not defects in the file. The probe exits zero today.

[Standing probe](https://github.com/JosephOIbrahim/Synapse/blob/master/harness/probes/catalog_types_check.py)

### `dir(hou.Node)` is not a valid phantom test

`dir(hou.Node)` exposes 146 members. `hasattr(hou.Node, "parm")` is **False**,
while `"parm" in dir(node_instance)` is **True** and `node.parm("snippet")`
works. Class-level introspection produces **false negatives** on the same
class — members that exist and work are missing from it — so the decisive
test for a `hou.Node` member is calling it on an instance.

**The number has a producer.**
`harness/probes/hou_node_class_dir_probe.py` measures the live build and
writes `harness/probes/hou_node_class_dir_receipt.json`. On the pinned
22.0.400 build the class-level `dir()` has **146** members and a live node
instance has **347**, and the class list is a strict subset of the instance
list: every class member is also an instance member, and the instance list
holds **201** that the class list does not. `parm`, `setParms` and `cook` are
three of those 201, and all three work when called on the instance. One
member is missing from **both** lists: `addParm` is not a `hou.Node` member
at all, because a parameter is added through `parmTemplateGroup()` — also
instance-only — and not through the node.

**The blind spot is in the committed symbol table too.**
`python/synapse/cognitive/tools/data/h22_symbol_table.json`
(`houdini_version` 22.0.400) carries **116** `hou.Node.*` names out of
**36,472** symbols, and `hou.Node.parm` is **not one of them** — the same
class-level omission, in a file this project treats as its existence
authority. That is the practical argument for the instance-level probe: an
authority built on class-level introspection cannot see `parm` at all. The
probe checks the committed table as well, so that number has the same
producer.

### Two harness boards, and no open gate on either

- The **attest** board (`harness/attest/`) is a refinement loop that attacks
  its own seed defects. Its blueprint is **DRAFT and unratified**: no gate on
  that board is open. Its first wave's five map legs each returned **PARTIAL**
  on their seed cluster. The map phase then corrected the seed's own stated
  forms: "installation.json holds only 10 native hashes" and "no per-file
  manifest for the tree body" are both false — the installed
  `payload-manifest.json` and `installation.json` carry a 1,972-entry
  per-file SHA-256 map, and a runtime check exists too: the shipped
  `setup_cli.py verify` re-hashes the tree and **fails today**, because
  nothing invokes it automatically. The same phase reversed the seed's own
  install-interval claim (**46.1 hours**, not ~21) and its
  panel-file-direction claim: the installed `synapse_panel.pypanel` *gained*
  `<includeInPaneTabMenu>` and lost its three UTF-8 em-dashes. That drift
  content matches Houdini's own rewrite of the file byte for byte — but four
  Houdini processes were running, so who wrote it stays **UNKNOWN**. The
  board's own summary: the seed defects are real, but **three of their
  stated forms are wrong**.
- **One item the map phase could not settle was left open, on purpose.** The
  map legs **disagreed with each other** on the bridge port — one measured a
  single listener, another measured two — so the board recorded it as a
  conflict between legs and carried it to the seam rather than picking a
  winner. The seam leg re-measured on the tree and settled it: **two**
  listening sockets, with the doctor naming the wrong one.
- The **crucible** verdicts are the crucible seats' own, not the orchestrator's:
  **SOUND-WITH-NITS** (S7), **SOUND-WITH-NITS** (SEAM-S1) and **BROKEN**
  (S6a-N1). S6a-N1 is broken for five measured reasons: it **adds carriers
  where it should consolidate** — the board's own `model_attribution` block
  already carries the truth under the design's exact proposed names; its
  **comparison misclassifies the host's real model strings** (the same model
  written two ways reads as different, two identical dated ids read as
  different, `<synthetic>` is unhandled); its **named falsification cannot
  fail** under the obvious fixture; the board's requested-model source is the
  sidecar its own spec forbids as evidence; and it **claims a file the wave
  assigned to the Joe-gated S6b seam**. Synth found a sixth: the design says
  12 `jc.ask()` call sites and the tree has 21.
- **Model routing is Jev-decided, and the alias in a receipt is a request, not
  a fact.** The routing seat carries the tier and the reason. The board's
  `model_served_by` values are a hand-authored constant —
  `REACHABLE_ALIAS = {'haiku': True, 'opus': True, 'fable': False}` — copied in
  from an out-of-repo script rather than from a probe, and the board's own
  unproven list records that whether a probe ever ran is **UNKNOWN**. The
  sidecar's `model` field is the alias that was *asked for*, and the board's own
  spec forbids it as evidence. What the board is allowed to claim about a tier
  is parked pending Joe (S6b).
- **A measured answer sits beside that constant, and it names the session
  model.** `harness/attest/STATE.json` → `model_attribution` (measured
  2026-10-22) reads each seat's requested and effective model out of that
  seat's own transcript: **all six seats resolved to the session model** — five
  asked for `haiku` and one for `opus` — and the `fable` alias was
  **unreachable** on this host. Its own honest reading: *"The JEV tier bought a
  LENS injected into the prompt, not a different model. A receipt saying
  model=haiku is a request, not a fact."* The blueprint says the wave
  **recorder** produces that block; the shipped recorder does not — the string
  `model` does not appear in it — so the block was written by hand from
  transcripts that live outside this repository, and nothing regenerates it.
- **The product-side carrier already exists; the consumer does not.** The
  shipped tree captures the served model: `python/synapse/model_access.py`
  records `requested_model` and the provider's `reported_model`, and
  `anthropic_provider.py:342` reads that model out of the live response's
  `message_start`. What is missing is a reader — the map leg measured **zero**
  readers of that field anywhere in `harness/`, and none in the product that
  turns it into a verdict.
- The wave's own record is committed at `harness/attest/WAVE-RECORD.md` and
  assembled by `harness/attest/record_final_wave.py` from the workflow run's
  own journal. The journal is a private log that lives **outside** this
  repository, so the record's path field reads `<path>` — that is the
  recorder's scrub working, not an unfilled field. The record names the run id
  and carries the journal's digest and row count, so a reader who holds the
  journal can confirm it is the one the record was built from, and can re-run
  the script on a later journal to see the delta. **The wave completed before
  this release was cut**: 17 seats dispatched, 17 returned, every phase from
  map through verify complete, and **11 seats of headroom left under the
  30 + 2 cap**. The two verify legs — SEAM-S1 and S7 — both returned **PASS**,
  and their evidence is in the record: the branch and SHA, the defect
  reproduced independently against both trees, the acceptance re-run by the
  verifier rather than read off the forger's word, and a mutation proof that
  the guard can fail.
- **The recorder's own test suite found three defects in the recorder.** It
  ships in this release with 17 hermetic tests — a synthetic journal in a tmp
  dir, no Houdini, no model, no network — and it is now wired into CI and
  into `testpaths`, because it was collected by nothing before. What it
  caught: a scrub that replaced SYNAPSE's own vocabulary with `<path>`
  (`/mcp`, `/version.mismatch`, the phrase "version / identity") and ate the
  port out of the `ws://localhost:9999` URL the seam leg had measured; a
  verify section that recorded **both PASS verdicts with `proof: null`**,
  because the seats had written their evidence under a different key than
  the recorder read — the verdict published, the evidence discarded; and a
  per-phase count that filed the seam and synth seats under "unknown" while
  the same file said they had returned.
- **Harness2** now carries a compose guard, a graph guard and a threshold
  calibration. It has no spec and no gate that could ratify it — it fails
  closed instead: with no Jev answer the decision is "adopt nothing", and the
  candidates are reported as still needing a human.

## Tests

Every number below was measured on this workstation, in an isolated
environment, against the release tree. Each control names the tree it ran on.

**What "isolated" means, so the numbers can be re-run.** The stock legs run
under the stock interpreter `C:\Python314\python.exe` (3.14.2, pytest 8.4.2):

```
C:\Python314\python.exe -B -m pytest tests/ -q -rs -p no:cacheprovider
```

The seat legs run under Houdini's own interpreter, `hython 22.0.400`
(3.13.10, pytest 9.1.1), so that the Houdini-dependent tests are collected
rather than skipped:

```
hython.exe -m pytest tests/ -q --continue-on-collection-errors -p no:cacheprovider -p seat_origin_plugin
```

In both, `PYTHONPATH` points at the tree under test's own `python` directory
and at the tree itself, so the tree wins over any installed copy.
`SYNAPSE_LOG_DIR`, `SYNAPSE_BRIDGE_FILE`, `SYNAPSE_LEDGER_DIR`,
`SYNAPSE_AUDIT_DIR` and `TEMP`/`TMP` are redirected into a disposable scratch
root; the seat legs also redirect `HOUDINI_USER_PREF_DIR`, so no leg reads or
writes the live seat's preferences. `ANTHROPIC_AUTH_TOKEN` and
`ANTHROPIC_BASE_URL` are cleared in the process. **The stock suite and the seat
suite are never run against a shared log directory.** The Git identity is never
replaced: the release commit and the tag carry the real author.

- **The stock suite passes, and the release tree and the published master are
  identical under both PATH conditions.** System Python 3.14.2, pytest 8.4.2.
  With Git's `usr/bin` on PATH, so the pre-commit-hook module is collected
  rather than skipped, the release tree gives **12,240 passed, 472 skipped, 11
  xfailed, 0 failed** in 686.04 s, and the published master commit `0c5a800d`
  gives **12,240 passed, 472 skipped, 11 xfailed, 0 failed** in 788.29 s.
  Without `sh` on PATH, the same command on the release tree twice and on master
  once each give **12,207 passed, 505 skipped, 11 xfailed** (622.64 s, 668.83 s
  and 631.23 s). The 33-test difference between the two figures is exactly
  `tests/test_harness_githooks.py`: the pre-commit hook it exercises is a POSIX
  `sh` script, so the module is skipped whole when `sh` is absent, and it
  passes 33 of 33 when it is collected. The difference is the PATH condition,
  not the tree. One of those runs omits `-rs`; it gives the same counts
  (12,207 passed, 505 skipped, 11 xfailed, 0 failed in 622.64 s), because `-rs`
  only widens the skip report.
- **The changed-area controls pass.** `installer/tests` 84 passed.
  `harness/harness2/tests` 38 passed. `harness/attest/tests` 17 passed.
  `harness/jev/tests` 97 passed. The two harness suites were collected by
  nothing before this release, so every assertion in them was decorative. They
  are hermetic — no Houdini, no model, no network — and they pass on Python
  3.11 and 3.14, which are the two interpreters CI runs.
- **The panel suite is not green, on either tree.** Run alone under hython
  22.0.400: the release tree gives **572 passed and 9 failed out of 581**, and
  the published master commit gives **571 passed and 10 failed out of 581**.
  The release tree's nine failures are all in the master's ten; the one extra
  master failure, `tests/panel/test_ollama_discovery.py::test_closing_parent_during_discovery_never_calls_deleted_qt`,
  did not reproduce on the release tree. The shared nine belong to the host,
  not to this release. This is a different comparison from the "573 passed and
  eight failed out of 581" recorded for v5.97.5, which compared two *installed*
  payloads for baseline equivalence; this one compares two *source trees* on
  one host.
- **One test node could not be measured on this host, and it is named here
  rather than dropped.** `tests/test_w3_harden_crash_recovery.py::test_hard_kill_at_replace_instant_preserves_last_durable`
  spawns a child Houdini that calls `os._exit(137)` inside `os.replace`, and the
  parent calls `subprocess.run(capture_output=True)` with **no timeout**. On
  this host the child's exit never completes, so the parent blocks forever. The
  test file is byte-identical on the published master commit, so the hang is a
  property of this machine, not of this release. That one node is deselected
  in the **seat leg only** — the stock-suite counts above are measured with it
  collected and passing. The seat comparison, which is the one that needs the
  deselect, is below.
- **The seat suite is not green on either tree, and every release-tree failure
  is also a master failure.** Run under hython 22.0.400 with that one node
  deselected: the release tree gives **125 failed, 12,426 passed, 171 skipped,
  1 deselected, 11 xfailed, 4 errors in 2434.13 s**; the published master
  commit `0c5a800d` gives **131 failed, 12,420 passed, 171 skipped, 1
  deselected, 11 xfailed, 4 errors in 3064.13 s**. The release tree's
  **125** failures are a strict subset of master's **131** — it has **none**
  that master does not also have — and the four errors are the same four on
  both trees. The six that master alone fails are all in the panel surface and
  all timing-sensitive: two panel tests and four rhythm-docking
  parameterisations. **Neither tree is green under the seat interpreter, and
  this release does not claim otherwise.**
- **An earlier release measurement was worse, and it is kept.** A first clean
  run gave **129 failed, 12,422 passed, 5 errors in 3115.52 s**: its fifth
  error was the R-D ruling guard firing because `docs/status.md` was edited
  while the leg was running, and its four extra failures were the same
  panel-timing nodes. The run above is the measurement of record. Two further
  re-measurements, one per tree, died part-way with `Windows fatal exception:
  access violation` in the panel region; the crash struck **both** trees at
  different nodes, so it reads as a host condition rather than a difference
  between the trees.

## Limits

This release changes no product behaviour, and it qualifies no new product
surface. The audit is of an **external blueprint**, not of SYNAPSE's own World
Labs import path, which is unchanged and unqualified here. The corrected
pipeline script is a probe: it verifies the eleven corrections on the live
build, and it has not rendered a World Labs export, because no export was
available. The eight unproven claims stay open.

The attest board is a DRAFT blueprint with no open gate, so its wave's verdicts
carry no authority over the product. The wave itself is complete and its
record is committed, but the record is a board's own account of a board: its
`model_served_by` is a hand-authored constant beside a hand-written
measurement, and the product still has no consumer that turns the effective
model into a verdict; its five `needs_joe` items are product decisions that
are still open, and its sixteen unproven claims stay unproven. The two forged
nodes (S7 and SEAM-S1) live on their own worktree branches, not on master, and
nothing in this release ships them.

Setup remains **unsigned**. Extraction and embedded-engine checks do not
establish an interactive wizard, a clean-machine install, or arbitrary artist
GUI behaviour. The [5.97.6 tests and limits](v5.97.6.md) remain applicable.
