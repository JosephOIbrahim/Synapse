# v5.95.0 - A miss is reported, not hidden

Three hardening loops on top of [v5.94.3](v5.94.3.md), run on the evening of 2026-10-06. **None of it was run in a live Houdini session.** Every repair adds its own test. Eleven of the thirteen graph repairs are tested with stand-in objects, and two by reading the source itself. The panel tests run the real stylesheet code and read its source, and the wordmark check needs a real Qt. The radius and composer changes were rendered offscreen under a standalone `hython` 22.0.400.

**The theme is one house rule: an error is never a success.** Seventeen tools now report misses they used to hide. Three fail outright, five return the miss as `cook_error`, and nine still succeed but name the miss in a new key. Some misses still go unreported; they are listed under Limits.

---

## Tools that now say what they missed

**A parm that does not exist is named in the result.** These tools write caller-named parms behind a guard that skipped a missing name without a word. Each now returns `parms_missed` (or `inputs_missed` for a node path that did not resolve), in the style of v5.94.0's guarded parm write:

- **COPs:** `bake_textures` (`resx` / `resy`), `stamp_scatter` (`seed`, `copies` / `count`, and its `stamp_source` input), `growth_propagation` (its `seed_mask` input) and `pixel_sort` (its input node).
- **`create_material`:** every explicit and preset shader value, scalar and colour.
- **`create_variants`:** per-variant material parms.
- **`hda_package`:** each node's parms; the miss is also added to the result's `warnings`.

The H22.0.400 node catalogue lists none of `seed`, `copies`, `count`, `resx` or `resy` on `vopcop2gen`. So on 22.0.400 those `stamp_scatter` and `bake_textures` writes always missed, and the tools reported them as applied.

**`execute_vex` refuses an input path that does not resolve.** It used to fall back to a new empty `/obj/synapse_vex_temp` container and run the snippet on empty geometry, and that container was never cleaned up after a failed cook. It now raises `NodeNotFoundError` before creating anything.

**Five USD tools report a missing prim instead of claiming the edit.** `set_usd_attribute`, `set_usd_primvar`, `modify_usd_prim`, `manage_variant_set` (create) and `set_payload_loadstate` (with `active`) emit Python that wrapped every edit in `if prim:`. A missing prim path cooked cleanly, and the tool reported the edit as authored. The emitted code now raises when the prim is missing, so the existing cook check returns `cook_error` in the result. The response itself is still `success: true`. The inner no-op for an unknown scalar attribute name is unchanged, as before.

**Two render tools name a settings call that raised.** `safe_render` returned `forced_background: true` even when writing `soho_foreground` failed or no ROP was found. It now sets the flag only when the settings call did not raise, and names a raised failure in `background_error`. `render_progressively` swallowed a failed settings write on each pass; each pass now carries `settings_error` when its settings call raised. A parm that does not exist is still skipped without a word by both, so both can still report a setting that did not land (see Limits).

**Two read tools report a missing service as a failure.** `router_stats` and `live_metrics` returned an error dict that the transport wrapped as `success: true`. They now raise, so the response is `success: false`.

**A PDG farm cook that failed without timing out, and whose rollback raised, is recorded as incomplete.** The bridge recorded `pdg_rolled_back` even when `dirtyAllTasks` raised. It now records `rollback_incomplete`, as v5.94.3 already did on the sentinel-hash branch. A cook that timed out is still recorded as `pdg_timeout`, whether or not its rollback raised. The `dirtyAllTasks` keyword itself is unchanged; see Limits.

## The panel, tightened

A design team worked from Pentagram's case study for Cohere and the panel's own design record. Four changes shipped, each removing a literal or a layer of indirection. The composed stylesheet hashes the same before and after for three of them; the wordmark change is checked by QFont equality at 1.0 and 2.25 instead. The offscreen pixel grab was compared only for the radius and composer changes:

- nine chat-layout tokens that nothing read are deleted;
- the wordmark names `WEIGHT_BOLD` instead of `600`;
- three radius values name `RADIUS_LG` / `RADIUS_SM`;
- one ordered composer builds the stylesheet in place of eight rebinds.

What was held back, and the proposals that would move pixels, are in [PANEL_TIGHTEN_2026-10-06](../design/PANEL_TIGHTEN_2026-10-06.md).

## The development harness learns from its own runs

Rope's graph mode, added in v5.94.3, gained three rules tonight: one from v5.94.3's own run, two from tonight's. None of them runs inside Houdini.

- **The gate discards a fix that drops a logging line its card never named.** In v5.94.3's run, a reviewer kept a repair that had quietly deleted a debug line.
- **A fix's new test gets a path that is not tracked in git, not on disk, and not claimed in the same route.** Tonight's first run reused the test names of v5.94.3's run, and the harness refused three of its six items as edits to existing tests before any fix was written.
- **Every fix runs four ratchets, not two.** The TOPs quarantine test and the except ratchet now run on every fix. Tonight a repair written outside the harness broke both, and only the full suite caught it.

## Validation and limits

**How a change was kept.** Thirteen repairs were written by headless sessions of rope's graph mode, each from a card naming the files it could change. A change was committed only when its own new test and the existing tests for its files passed. A separate review session read every kept commit; all thirteen were kept. The panel changes and the harness changes were written by separate agents in their own worktrees, and each was attacked by a reviewer that did not write it.

**Where the cards came from.** Finders aimed at one class of defect each, and a refuter then tried to disprove every claim. Of 42 candidate claims across the three runs, 4 were refuted, 10 were held back as needing an existing test changed or as the owner's call, and Jev routed the other 28. Jev sent two of those to a live Houdini check instead of a fix, and scored one below its confidence floor. The operator read every routed card before any fix ran.

**Tests.** The full `tests/` suite on the release tree, on Windows with Python 3.14 and the tests that need a Houdini runtime deselected as CI does: 11,028 passed, 431 skipped, 186 deselected, 5 xfailed, 0 failed. Against the same command on v5.94.3, compared by test id: 64 tests added, 0 removed, 0 newly failing. That run came before the Jev ledger row for these notes was added. Publication requires all six GitHub CI jobs to pass on the exact tagged commit, linked in the GitHub release.

**Limits.**
- **Unit-tested only.** Stand-in objects behave the way the code expects; that is not evidence of how Houdini behaves.
- **A TOPs live-monitor repair was held back.** `tops_monitor_stream` still asks PDG for `pdg.EventType.CookProgress`, which 22.0.400 does not have, and swallows the error, so a started monitor receives nothing. A repair exists on branch `tops/hour3-20261006`, but `handlers_tops/` is a structural quarantine (`tests/test_d_track.py`), so it waits for the owner's ruling.
- **Return shapes grew.** Tools that gained `parms_missed` / `inputs_missed` return one more key each; `stamp_scatter` returns two. `execute_vex`, `router_stats` and `live_metrics` now fail where they used to succeed.
- **`render_settings` still skips an unknown override silently,** and `render_progressively` still reports each pass's sample count when no sample parm took it, on `usdrender` and `ifd` ROPs. Jev routed the second to a live Houdini check.
- **`safe_render` still reports `forced_background` on a ROP with no `soho_foreground` parm,** because the settings call skips a missing parm without raising. The code comment beside it says more than the code does.
- **`manage_variant_set` (select) never cooks its edit,** so a missing prim or variant set still reports as selected. Jev routed it to a live Houdini check.
- **`matlib_bind`, `shotsetup_karma_xpu` and `hda_package` still roll back unconditionally on failure.** The fix needs an existing test changed.
- **The PDG rollback still calls `dirtyAllTasks(remove_files=...)`.** The 22.0.400 signature is `dirtyAllTasks(remove_outputs)`, so the rollback raises every time. This release records that truthfully; correcting the call needs a live probe.
- **Still open from v5.94.3:** two `hou.expandString` calls (`server/solaris_compose_tools.py`, `host/lookdev_suggestion.py`) and `NetworkBox.addNode` in `server/handler_helpers.py`, each held by a stand-in in an existing test; the tool arguments that are read and ignored; and the planner's default model id.
- **`audit_panel.py --strict` is red before and after this release,** with identical rows. Four model-token rows disagree with the audit's expected form; that is a design call.
- **A panel change was tested and refused.** Removing three inline `letter-spacing` spans would move pixels: an offscreen probe shows Qt honours them. It is ruling R3-B in the design note.

The inherited [v5.94.3 limits](v5.94.3.md#validation-and-limits) remain, except "Three `hou.expandString` calls remain", which this release narrows to two.
