# v5.93.3 — Scatter keeps to near-level ground

One change to the Scatter Instances recipe, a few hours after [v5.93.2](v5.93.2.md), and a correction to a number in that release's notes. The change was measured in hython. It has not been seen in the Houdini GUI.

**Scatter keeps to near-level ground.** The recipe's direction mask goes from 45 degrees to 20. At 45, sills, ledges and far roofs still caught instances. At 20 the count is nearly the same and almost all of it is on the lane. The recipe's notes now also name the two parameters that drop instances too far from the camera to read, `enablecameramaskfar` and `cameramaskfar`. The recipe does not set them, because the distance belongs to the scene.

**A correction to v5.93.2's notes.** Those notes say that with the mask "53 of 763 instances still sat above 1.5 m". That count used a flat height. The demo lane climbs about 1.2 m toward its far end, so it is not a count of instances off the ground. Measured as height above the lane, the figure for v5.93.2's recipe is 73 of 763.

**Source release for Houdini 22.0.400 / Python 3.13.** No new Windows Setup is included. The v5.86.0 Setup contains none of the changes in v5.87.0 through this release. Follow [source installation](../getting-started/installation.md#source-installation), then restart Houdini to load the updated source.

## Validation and limits

**The mask, in hython.** Houdini 22.0.400, the demo scene, the recipe's own payload built with `hou` and no model. Height above the lane is each instance's height less the tenth-percentile height of the instances in the same two-metre stretch along the lane. At 45 degrees: 763 instances, 73 more than 0.35 m above the lane, 5 of those within 26 m of the camera, the highest 6.33 m up. At 20 degrees: 758 instances, 12 above the lane, none within 26 m, the highest 2.16 m up. No parameter was missing and no node reported an error or a warning.

**With a far plane.** At 20 degrees with `cameramaskfar` at 26 m: 469 instances, none more than 0.35 m above the lane, the highest 0.18 m up. This is the scene-side option the recipe's notes name. The recipe does not set it.

**v5.93.2 in the GUI.** After v5.93.2 was published, Houdini 22.0.400 was relaunched on it and driven on the demo scene. The Scatter build call carried `enabledirection` 1 and `maxangle` 45 and left 763 instances on the stage. A turn that called `synapse_recall` and got back one knowledge article showed no "what I remember" card. The scale-and-ground request took 22.6 s, the Scatter request 25.9 s and a recall 6.4 s, with every tool call under one second. So both changes that v5.93.2's notes list as not seen in the GUI have now been seen there.

**Tests.** One new test file, `tests/test_scatter_recipe_mask.py` (3 tests): the direction mask is on and at 20 degrees or less, the camera mask stays on, and the notes name the two far-plane parameters. The full `tests/` suite passed on the commit that carries the change, on Windows with Python 3.14, with the tests that need a Houdini runtime deselected as CI does: 10,782 passed, 428 skipped, 183 deselected, 5 xfailed, 0 failed. The release commit on top of it changes version strings and documents only. Publication requires all six GitHub CI jobs to pass on the exact tagged commit, linked in the GitHub release.

**Limits.**
- **Not seen in the GUI, and not run through the panel agent.** The 20-degree mask ran in hython with `hou`. The agent's path is the same single build call as before. That call carried the 45-degree mask in three of three headless runs on the recipe before v5.93.2 was cut, and in one GUI run on v5.93.2.
- **Not zero.** At 20 degrees, 12 of 758 instances still sat above the lane, all more than 26 m from the camera.
- **The ground is estimated from the scatter itself.** Height above the lane is measured against the instances' own low points, not against a survey of the collider.
- **One scene.** The angle was chosen on the demo lane. A steeper street would need a wider one.
- **The model edits the recipe.** The recipe's values are what the model is shown, not what it must send.
- **A Scatter build can leave a memory record.** Across the GUI check on v5.93.2 the workstation's memory store went from 1,563 rows to 1,564, and the recall that followed the Scatter turn recited four scatter records where the morning's recited three. What wrote the row was not traced. Not fixed.

The inherited [v5.93.2 limits](v5.93.2.md#validation-and-limits) remain, except the two this release's GUI check closes and the count it corrects.
