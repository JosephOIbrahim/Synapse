# v5.85.2 — Karma render settings on Houdini 22

**SYNAPSE can change Karma Render Settings on Houdini 22 again.** Houdini 22.0.400's
USD Python API no longer offers `GetAddedOrExplicitItems` on `Usd.References` or
`Usd.Payloads`. SYNAPSE's composition check called it on every stage with an
authored reference, so the check could not finish and refused the change as a
"USD Composition violation". A stock Karma Render Settings node has such a
reference, so SYNAPSE could not set its engine or output picture, from the panel or
from Claude Code. The check now reads the authored references from the prim's layer
stack. It still refuses a prim that references itself and a reference to a file
that cannot be found.

**The check lands on the node you changed.** A LOP's dependents include the nodes
inside its own asset that read its parameters. SYNAPSE checked the stage of Karma
Render Settings' internal `pythonscript1` instead of the node's own. A change to a
LOP is now checked on that LOP's stage.

**Ramp parameters no longer break inspection.** `houdini_network_explain` and
`synapse_inspect_node` failed with "Type is not JSON serializable: Ramp" on any
network with a ramp parameter, such as Karma's tone-map curve. A ramp now comes back
as its basis, keys and values.

**Source release for Houdini 22.0.400 / Python 3.13.** No new Windows installer is
included. The older v5.75.2 Setup does not contain these changes. Follow
[source installation](../getting-started/installation.md#source-installation),
then restart Houdini and separate MCP processes to load the updated source.

## Validation and limits

The fix was checked live in Houdini 22.0.400 after a restart. Claude Code, limited
to SYNAPSE's read tools plus `houdini_set_parm`, wrote the engine and output picture
on a Karma Render Settings node. Both writes passed the composition check with full
fidelity, and the parameter pane showed the values. Before the fix, every such write
was refused. `houdini_network_explain` returned all 13 nodes of the test network,
including the tone-map curve, and `synapse_inspect_node` returned the Karma node
with its ramp.

The check also ran on Houdini 22.0.400's own USD library in `hython`. A stage with
an ordinary internal reference passed, while a self-reference and a missing file
were still refused. Nine new tests cover these cases, and six of them fail on the
old code. The full `tests/` suite passed locally on Windows. Publication requires
all six GitHub CI jobs to pass on the exact tagged commit, linked in the GitHub
release.

Two limits remain. SYNAPSE's read tools return a parameter's evaluated value, so a
value like `$HIP/render/$HIPNAME.$OS.$F4.exr` reads back as the expanded path. An
agent that compares the two can report a successful write as failed. Separately,
the scene hash was seen to change between two writes with only reads between them,
which marks the second write as following an outside change. Both are tracked for
a later release.

The inherited [v5.85.1 limits](v5.85.1.md#validation-and-limits) remain.
