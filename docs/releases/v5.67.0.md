# v5.67.0 — Editable Copernicus lookdev

SYNAPSE adds an editable Solaris lookdev fixture built around modern Copernicus, alongside a procedural texture correction and a fix for expired requests accumulating in Houdini's deferred queue.

## What changed

- **A Copernicus lookdev starting point.** The existing `synapse_solaris_build_graph` tool accepts the `copernicus_lookdev` template. It creates an owned subnet with editable plane geometry and UVs, a Texture Material Library with color and scalar roughness controls, a material binding, camera, light and preview settings. Vertical and horizontal outer layouts are available.
- **Procedural textures use modern CopNet.** `cops_procedural_texture` creates editable Layer and Fractal Noise nodes in a modern `Cop` network. Perlin, Worley, Alligator and a 3D Simplex XY slice are supported. Invalid settings and legacy `Cop2` parents are refused; existing argument aliases remain available. Other older COP helpers retain their existing behavior.
- **Expired queued requests are removed.** The dispatcher retains one outstanding native wake for its pending queue, so timed-out requests do not each leave a callback ahead of fresh work. Requests that have already started remain subject to the existing cooperative behavior.
- **Existing work is preserved.** The fixture refuses a reused name and preserves existing authored state and display choice. In an empty parent, Houdini displays the first fixture and the result reports that change. Construction failures clean up newly owned nodes and report any incomplete cleanup.

The fresh process loaded the reviewed queue implementation and answered bounded bridge requests.

## Scope and known limits

- Qualification is specific to **Houdini 22.0.400** and one fixed **256 × 256 lookdev preview**. Arbitrary scenes, sustained production use, higher-quality output and render-farm operation are unqualified.
- The fixture depends on the installed `QuickSurfaceMaterial` and **in-session `op:` texture references**. Textures are not packaged for another scene, process or machine. Export and farm portability need separate work and verification.
- Building checks authored settings, geometry, UVs, material wiring and binding. Rendering and exporting remain separate actions with their existing permissions. Subsequent artist edits require fresh verification.
- The existing studio-restricted builder requires `admin`; `viewer`, `artist` and `lead` are denied. Standard workers may use it; strict and demo workers may not. Local-mode permissions are unchanged.
- Queue qualification covers controlled idle withholding. It does not establish every minimize/restore scenario, remove callbacks left by an older loaded module, interrupt running work or guarantee interactive latency. Restart Houdini after saving work to load the complete update.
- One existing live-bridge memory-write probe was not run in the isolated battery. Successful hosted CI does not erase the recorded local failures or cover native Houdini behavior.
- During recovery, the tested model continued an older build after a new read-only prompt. Prompt adherence for interrupted tasks remains an open issue; this release does not claim to fix it. Live XPU rendering and painting were not tested.

Existing model-sharing and local-storage permissions remain in force. Locally saved memory may be included in an approved model request when recalled; this release does not establish a universal privacy guarantee.

The four standing requirements remain open: `mutation_fail_closed`, `hot_reload_gated`, `installer_host_targeted`, and `ci_covers_shipping_surface`. Any **Latest** designation does not establish that these requirements are satisfied.
