# SYNAPSE v5.104.0 — loopback by default, and outcomes that tell the truth

**Upgrade every seat.** Earlier builds started Houdini's web server with no address, and
Houdini's `hwebserver` binds the any-address (`0.0.0.0`) when none is given. With no key on
disk, authentication was off. By default the SYNAPSE server now binds to this machine only (127.0.0.1);
a wider bind needs an explicit opt-in and a key. Setup creates a key when no readable one exists.

This is Waves 0 and 1 of the 2026-11-20 repair program: 35 fixes (12 in Wave 0, 23 in Wave 1;
the node ids are listed in the `fix(w0)` and `fix(w1)` commit messages) from an audit of master
`4aab502a`, which is `v5.103.0` plus four docs commits (`git rev-list --count v5.103.0..4aab502a`).

## Security

- **Loopback by default.** The server passes `ADDRESS=127.0.0.1` and loopback-only allowed hosts
  to `hwebserver`. A non-loopback bind is refused without an explicit opt-in
  (`SYNAPSE_DEPLOY_MODE` set to a studio mode, or `SYNAPSE_ALLOW_LAN=1` with
  `SYNAPSE_BIND_ADDRESS`), and refused without a key even then.
- **Setup creates the key.** Every Setup install writes `~/.synapse/auth.key` when the file holds
  no readable key line, fresh installs and upgrades alike; a readable key is never replaced. A
  failed write stops Setup before the configuration changes. A source install creates no key:
  put one line of random text in `~/.synapse/auth.key` to turn authentication on.
- **Doctor checks the bind.** `synapse_doctor` reports the listen address and fails if the port
  accepts on any of this machine's hostname-resolved non-loopback IPv4 addresses in local mode.
- **Read-only mode covers aliases.** `engram_add` and `engram_decide` no longer bypass
  `SYNAPSE_MCP_READ_ONLY`.
- **Corrected claims.** `SECURITY.md`, the studio deployment guide and the agent instructions no
  longer say roles are enforced. No shipped endpoint checks them: the key is one shared secret,
  and anyone holding it can execute code. Where those files said "reversible", they now say what
  undo does.

## The artist's scene

- **A refused Solaris compose no longer undoes your last edit.** The compose handlers undo only
  when their own undo group recorded something.
- **The Solaris builder tools roll back only their own work.** A half-built chain is reported as incomplete, with
  its missing nodes, instead of as already built.
- **USD readback checks the right thing.** `reference_usd` verifies the referenced layer for
  references and payloads, and a variant selection is verified with `GetVariantSelection`.
- **Undo and Redo touch only agent steps made since the session started.** Undo takes back only
  a step an agent tool recorded after the session started, never the artist's own edit, an older
  step, or a panel action the artist started (the camera-path, Cancel cook and Emergency halt
  buttons among them, so an agent's own camera path or cancel is refused too). Redo re-applies
  only a step this session undid, and only while Houdini's undo and redo lists are exactly as
  this session's last Undo or Redo left them and no SYNAPSE command that can change the scene
  has been dispatched since (read-only commands do not count). The check and the step run in one call on
  Houdini's main thread, on every route; when the history cannot be read
  they refuse, and a batch refuses them outright. The history tools move from the inform gate to
  review, so the default panel worker refuses them; use Houdini's own Undo.
- **`atomic` leaves the `execute_python` schema,** and a batch always opens its envelope group.
- **Runaway Python in executed code stops.** A wall-clock deadline stops pure-Python loops in the
  executed code itself and returns a deadline outcome. `SystemExit`, `KeyboardInterrupt` and
  `GeneratorExit` raised by `execute_python` code become a typed failure.
- **A timed-out scene change reports an unknown outcome,** telling the model to check the scene
  before it retries.
- **The MCP handshake's project-context preload runs on Houdini's main thread.**

## PDG

- **`tops_cook_node` no longer holds the main thread by default.** It returns a task id at once
  and resolves through state reads and events.
- **A single TOP node is reported cancelled only once no work item is still active.** A network
  cancel returns `status: cancelled` once the signal is sent; that status is not confirmed by a readback. The cancel receipt reads Houdini 22's cook state with its
  `force` argument.
- **The wedge tools set real Houdini 22 parameters, or refuse.**

## Hands-off render

- **`synapse_autonomous_render` answers at once with a task id.** The loop runs on a worker
  thread; call the tool again with the `task_id` for the status and, once finished, the report. A
  second start with the same intent and settings joins the running task. The default panel
  worker refuses it (it is approve-gated); start it from Claude Code or another MCP client.
- **It works around Houdini 22's patched asyncio.** Houdini's event loop refuses to start tasks
  off the main thread, so the worker builds a plain loop of its own. If even that were refused,
  the plan's steps run without a loop, without pre-flight validation, and the report says
  `execution_mode: "sync_steps"`, with nothing graded and `success: false`.
- **The wall-clock bound stops at the next step boundary.**

## Results that say what happened

- A failing mutating live command records a failed integrity block (while the live envelope is
  on), and the block records the thread the command was dispatched on instead of a hard-coded
  `True`.
- `synapse_router_stats` works on a default handler; the circuit breaker classifies by outcome code
  and counts service errors and transport timeouts; geometry and scene reads are bounded and say
  when they truncate.
- Batches carry per-step receipts.
- Memory health can no longer read "ok" from a silent primary store, and a failed rebind on Save As
  is reported and retried on the next memory call.
- Both evaluators share the Rec.709 luminance weights; capture results carry the camera, frame and
  viewport; `inspect_stage` is bounded and stage totals come from a full traversal.
- Temporal analysis reports only the metrics it ran, the Karma scaffold reports the parameters it
  could not set, and APEX federation marks mock hits.
- Stage-keyed Solaris tools reach the bridge with their stage path, and the LOP knowledge catalog
  carries the 22.0.400 stamp.

## Limits

- **Roles are not enforced** on any shipped endpoint. Anyone with the key can run code. In a studio
  mode, live metrics and the dashboard still report `rbac_enabled: true`.
- **The bind was not checked from a second machine.**
- **The live render pass produced no image at the probe scene's configured path** and scored 0.00;
  image output from the loop was not verified live.
- **Autonomy steps take no mutation lock.** Steps run by `synapse_autonomous_render` do not
  serialise against another client's edits.
- **The deadline has two gaps besides C calls:** a loop in any code not compiled as the payload
  (library functions, or code the payload runs through `exec`/`eval`) is not traced, and an
  `except Exception` inside the loop swallows the deadline (CPython then drops the tracer). On
  Python 3.11 (a CI leg), a one-line infinite loop also escapes it. Houdini 22 ships Python 3.13.
- **Some TOP cooks still block the main thread:** `houdini_wedge`, `tops_cook_and_validate`, and
  `tops_batch_cook` (blocking by default).
- **The default panel worker can cook a single TOP node** (`tops_cook_node`, `houdini_wedge` count
  as parameter edits), and that cook may render.
- **`server/handlers_hda.py` still rolls back** with an unguarded `performUndo()`.
- **`server/api_adapter.py`,** an older REST adapter that no shipped path starts, still calls
  `hwebserver.run(port=8008)` with Houdini's default any-address. Do not start it by hand.
- **`synapse_batch` still lists `atomic`** in its schema and ignores it.
- **A consent card's Revert** asks the model to call `houdini_undo`, which the default worker now
  refuses; use Houdini's own Undo.
- **Undo and Redo can refuse one of this session's own steps,** never allow an older one:
  - when the starting history could not be recorded before the session's first change (the
    main thread was too busy, or the history was unreadable or switched off);
  - when the starting redo stack held a step with the same label that a later action (the
    agent's or the artist's) dropped;
  - after File > Open, File > New or a cleared history, since the starting record is never
    taken again (not checked live), and once Houdini's undo memory drops old entries;
  - for a step made through another handler: the in-Houdini `/mcp` server and the WebSocket
    server each keep one session for their lifetime, while the panel's fallback builds a new
    handler, and so a new session, for every chat turn, so there an earlier turn's step
    counts as pre-session;
  - for handlers that record no SYNAPSE group when called over the WebSocket route (for
    example `execute_vex`), whose entries there count as the artist's.
- **A timed-out Undo or Redo may still have run.** Check the scene before retrying.
- **A session is one handler's lifetime, shared by every client of the same route:** one client
  can undo another client's agent step on that route, and on the `/mcp` and WebSocket routes a
  new chat can undo an earlier chat's. Undo on one route can also take back an agent step another route recorded after this route's
  session started: the rule counts labels against this route's starting record, not which route
  made the step.
- **Two redo cases are not detected,** because Houdini's history carries labels, not
  identities, and both restore the same lists:
  - the artist's Ctrl+Y then Ctrl+Z on a step this session undid, so the agent's Redo can
    still re-apply it;
  - a render started off Houdini's main thread whose `SYNAPSE: render` step lands only after
    an agent Undo (the render runs on its own worker, after the dispatch that started it has
    returned) and is then undone. That group holds only parameter sets the render restores
    itself, so a wrong Redo there re-applies next to nothing.
- **Not checked live:** whether `undoLabels()` returns the whole stack on a very deep history.
- **Model-facing text lags.** The `houdini_undo` description still says "Steps back one undo
  level" and `houdini_redo` "Steps forward one undo level", the `synapse_autonomous_render`
  description still says it executes via TOPS (it renders through `render_sequence`, a ROP render),
  and the MCP `initialize` instructions still describe undo-group transactions for all mutations.
- **With `SYNAPSE_API_KEY` unset, a non-UTF-8 `auth.key` stops the server** from starting
  instead of being read.
- `stage_hash_mode` is empty on a live LOP network (22.0.400 has no `hou.LopNetwork.stage`).
- Setup remains unsigned.

## Upgrading

1. Close Houdini.
2. Run Setup. If `~/.synapse/auth.key` holds no readable key line, Setup writes one.
3. Restart Claude Code sessions and any SYNAPSE MCP server, so they read the key.
4. A client on another tool must send the key: the WebSocket handshake for `/synapse`, a `Bearer`
   header for `/mcp`.
5. `SYNAPSE_WORKER_TOOL_ALLOWLIST` is still honored.
