# v5.85.3 — Raw parameter reads and a steady scene hash

**Parameter reads show what you wrote.** `houdini_get_parm` returned only a
parameter's evaluated value. A string written with variables, such as
`$HIP/render/$HIPNAME.$OS.$F4.exr`, read back as the expanded path, so an
agent could not confirm its own write. Claude Code reported a successful write
of Karma's output picture as failed for that reason. Reads now also return
`raw`, the string as written, when it differs from the value, and
`houdini_get_parm` returns the `expression` that drives a keyframed parameter.
`synapse_inspect_node` returns `raw` per parameter.

**The scene hash holds still between writes.** SYNAPSE's scene hash counted how
many times a node had cooked, and it read that count before its own stage read
cooked the node. So after any write, the next read of an unchanged scene hashed
differently. The next write then reported an outside change, and an undo that
put the stage back still read "rollback incomplete". For a stage hashed in
full, the hash now covers the node layout and the stage content, not the cook
counts.

**The diagrams use two orange tones and black type.** The README and
documentation diagrams show SYNAPSE's own steps in deep orange (`#D07020`, the
panel's Houdini orange) and everything else in light orange (`#F6B26B`), with
black text and orange edges that read on GitHub's light and dark pages.

**Source release for Houdini 22.0.400 / Python 3.13.** No new Windows installer
is included. The older v5.75.2 Setup does not contain these changes. Follow
[source installation](../getting-started/installation.md#source-installation),
then restart Houdini and separate MCP processes to load the updated source.

## Validation and limits

This release closes both limits that the [v5.85.2 notes](v5.85.2.md#validation-and-limits)
left open. Reads now return the string as written, and the scene hash no longer
moves between writes when only reads come between them.

The fixes were checked live in Houdini 22.0.400 after a restart. Claude Code,
limited to SYNAPSE's read tools plus `houdini_set_parm`, wrote the output
picture on a Karma Render Settings node, read back `raw`, and reported the
write as taken. It then wrote the engine twice in a row. All three writes
passed the composition check, none reported an outside change, and the scene
hash stayed the same. The writes used the values the scene already held, so
the scene did not change.

A probe in `hython` on Houdini 22.0.400 showed the cause and the fix. Before
the fix, the stage content stayed identical while the cook counts moved, and a
stage put back to its original content hashed differently. After it, neither a
same-value write nor a real write left any drift, a real write still changed
the hash, and the restored stage hashed like the original. Twelve new tests
cover both fixes. Against the old code, the parameter-read handler test and
three of the five hash tests fail. The full `tests/` suite passed locally on
Windows. Publication requires all six GitHub CI jobs to pass on the exact
tagged commit, linked in the GitHub release.

The diagrams were rendered locally with mermaid-cli 12.0.0 in Chromium, on the
default and dark themes: 38 of 38 renders succeeded and were checked by eye.
GitHub renders mermaid on its own servers with its own version, and that
render was not checked. Diagrams in older CHANGELOG entries and past release
notes are records of their releases and keep their original colors.

Some limits remain. A stage above the size threshold is hashed with a reduced
signature that reads no attribute values, so that path still counts cooks and
can still report an outside change after a write. Undo and redo history
operations use a quick topology check that also counts cooks. Edge labels and
diagram frame titles keep GitHub's theme colors, so they stay legible in both
modes.

The inherited [v5.85.1 limits](v5.85.1.md#validation-and-limits) remain.
