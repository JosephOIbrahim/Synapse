# SYNAPSE v5.98.0

**This release changes what SYNAPSE does in the two places an artist feels it
most: writing a parameter, and rendering frames.** Both now read the effect
back instead of reporting that a call returned.

- A parameter write is read back, refuses what it cannot land, and a
  refused or failed write's receipt reaches the caller on every installed
  route, including the execution bridge's failure path.
- A render proves it produced *this* frame, a sequence fails on a lost or
  failed frame, a named frame list renders exactly those frames, and the
  report describes the attempt that ran.

Every comparison in this note is against one baseline: the v5.97.7 tag
(`d68a82bb`). The branch carries the 55 commits that landed on `master` after
that tag, one owner ruling, one records commit, and this release commit.

**One promise from v5.97.7 is not kept, and it is named first.** The v5.97.7
note deferred teaching the model-access guard the anthropic 2.x auth
convention "to v5.98". That work is **not started**. The dependency pin
`anthropic>=1.0.0,<2` is unchanged, and **2.x remains unsupported**. See
[Limits](#limits) and the
[migration ticket](../tickets/ANTHROPIC_SDK_2X_MIGRATION.md).

## What changes

### A parameter write reads itself back (G25)

`houdini_set_parm` no longer trusts the setter. Before it writes, it inspects
the parameter for keyframes and channel references. After it writes, it reads
the parameter back.

- **The reply carries `observed`** — the value `parm.eval()` returns after the
  write — beside the requested value, and a **`mismatch`** flag when the
  parameter did not take it.
- **An animated or channel-referenced parameter is refused by default.**
  `mode` says how to meet it: `refuse` (the default), `replace` (clear the
  keys, then set), `key_at_frame` (add a key at the declared frame) or
  `write_source` (write the parameter this one is driven by). Only
  `write_source` meets a channel reference; `replace` and `key_at_frame` on a
  reference are refused (`parm.reference_requires_write_source`). A
  parameter that is neither animated nor referenced is written normally under
  `refuse`, `replace` or `write_source`; under `key_at_frame` it gets a key at
  the declared frame, and a text parameter is refused (`parm.key_domain`). So no stray key is added, and no other node is written by
  accident.
- **A reference is not followed.** A parameter found to be a channel
  reference is refused unless `mode` is `write_source`, and the
  single-parameter setters pass `follow_parm_reference=False`.
- **A refused write writes nothing** (`write: not_attempted`). A write whose
  setter fails part-way restores each target it snapshotted — keys and Cycle
  extrapolation on an animated parameter, the authored string or value
  otherwise — and the receipt says whether that restore checked out.

Producers: `python/synapse/server/parm_authored.py` ·
`python/synapse/mcp/_tool_registry.py` (`houdini_set_parm` schema) ·
`tests/test_parm_write_truth.py`

### A queued write is checked against the state it was planned on

A write planned earlier and replayed later (`queued: true`) must say what it
expects to find: `expect` carries `value`, `raw_authored`, or both. The check
runs on Houdini's main thread before the first setter.

- A different state refuses the write: `parm.precondition_failed`.
- **An expectation the server cannot check refuses too**: a `raw_authored`
  expectation against a parameter that cannot report authored text, or a
  list-valued expectation, returns `parm.precondition_invalid` with
  `write: not_attempted`; a value expectation whose parameter cannot be read
  returns `parm.inspection_unknown`. Pin a uniform tuple with a scalar, which
  is checked against every component.
- A queued `key_at_frame` write must declare its `frame`. The playhead is not
  evidence of the frame the write was planned at, so a queued write without
  one is refused: `parm.frame_unknown`.
- `request_id` is echoed in the receipt, so a queued proposal and its replay
  can be matched.

### The write receipt reaches the caller on every installed route (NR-WRITE-RECEIPT)

The receipt is carried by the handler, by the stdio server `mcp_server.py`
(in `_meta["synapse/outcome"].evidence.receipt`), by the panel's executor, and
by the three panel consumers that turn a failure into a tool result —
`panel/claude_worker.py`, `panel/direct_tool.py` and
`panel/render_workspace.py`. The registry filter no longer drops `mode`,
`frame`, `queued`, `expect` or `request_id` before the handler sees them.

**It now survives the execution bridge too.** `houdini_set_parm` is a
mutating tool, so on the in-Houdini `/mcp` endpoint — which is also the
panel's route — it runs through `LosslessExecutionBridge`. When the handler
reports a refusal or a failure, the bridge's failure arm
(`_fail_with_integrity` in `shared/bridge.py`) returns a fresh result and
drops the handler's response. Until this release's last fix the adapter then
rebuilt the reply as an integrity-only failure, and the receipt was lost.
`panel/bridge_adapter.py` now keeps the handler's own response and carries
its `receipt` into the failure reply beside `_integrity`, so `/mcp` returns
it in `structuredContent`. Only a dict receipt is carried, and only from a
handler reply that itself reported failure. A failure the bridge raises
before the handler runs gets no receipt, and so does a write the bridge
fails after the handler completed it (a composition violation that rolls it
back, or a fidelity failure): that reply carries no receipt rather than
repeating the handler's "applied". This was found by this release's own
sentence check; the earlier receipt tests bypassed the bridge.
`tests/test_bridge_route_receipt.py` now takes it: two of its tests failed
before the fix, and a sixth, added when the fix was reviewed, failed until
the receipt was limited to handler-reported failures.

Producers: `python/synapse/core/tool_results.py` · `python/synapse/server/handlers.py` ·
`mcp_server.py` · `python/synapse/mcp/server.py` · `python/synapse/panel/tool_executor.py` ·
`tests/test_parm_write_receipt.py`

### A render proves it produced this frame (G32)

A product file that exists is no longer proof. The handler snapshots the
product's identity before `node.render()` and requires that identity to
change; a baseline it cannot read proves nothing. One exception remains: on a
usdrender ROP whose product did not change, `houdini_render` can still return
a GL flipbook preview, flagged `flipbook_fallback` and with no `output_file`.

- **The farm** carries `output_file` and refuses a flipbook preview or an
  absent product. It validates the product file — pixel checks when
  OpenImageIO is available, an intact-file check otherwise.
- **The progressive ladder** follows the same contract, requires every pass to
  report passed, and refuses an empty stage chain instead of reporting
  success.
- **A validator that raises does not fail** the frame or the pass. That is a
  limit, listed below.
- **RETINA** stamps a per-render nonce into a per-attempt manifest and into
  the `.done` marker it writes, and T0 grades by it. A sentinel or receipt that
  carries no nonce is *inconclusive*, never a pass.

Producers: `python/synapse/server/handlers_render.py` ·
`python/synapse/server/render_farm.py` · `python/synapse/host/retina_manifest.py` ·
`retina/t0.py` · `tests/test_render_proof.py`

### A render sequence fails on a lost or failed frame (G101)

A missing output, a farm-failed frame or a mismatch with the plan now fails
the sequence **whatever the mean score says**. Those hard failures are
reported in their own field of the sequence evaluation. The gap check still
lowers the score for any hole in the frame numbers — including a stepped or
sparse request, which it reports as missing frames.

- A cancel during execution stops with `success=False`.
- Frames completed before a retry survive the retry.
- Motion continuity is checked on pixels loaded from disk, through one shared
  path, so a recovered read cannot hide a discontinuity.

Producers: `python/synapse/autonomy/evaluator.py` ·
`python/synapse/autonomy/driver.py` · `tests/test_autonomy_evaluator.py` ·
`tests/test_autonomy_driver.py`

### Name the frames, get those frames (NR-SPARSE-RENDER)

`synapse_render_sequence` accepts an explicit `frames` list. When it is
present it is authoritative: those frames render, deduplicated and sorted,
and `start_frame` / `end_frame` are ignored. Entries are converted to whole
numbers, so 2.7 becomes frame 2. Before this release a sparse request reached
the farm as an invented contiguous range.

The list travels from the MCP schema through the handler to the farm. An
empty list is refused. `step` is still parsed when `frames` is given, so a
non-numeric step fails a frames request too.

Producers: `python/synapse/server/handlers_render.py` ·
`python/synapse/server/render_farm.py` · `python/synapse/mcp/_tool_registry.py` ·
`tests/test_sparse_render_contract.py`

### The report describes the attempt that ran (NR-PLAN-TRUTH)

The plan the artist declared is no longer rewritten to match what the farm
returned. `report.plan` is the declared request and `report.executed` is the
last attempt's state, so a report says what was asked and what happened as
two separate things.

- A rejected gate, an unsupported plan shape, or a cancel or wall-clock stop
  before the first validation (a negative budget ends this way) reports **no
  executed checks**, rather than presenting the planner's declared checks as
  if they had run. A failed validation reports the validator's own verdicts,
  and a cancel after dispatch keeps that attempt's checks.
- Retries reconcile against the original plan. A farm row for frame 99 is not
  a retry target for a request for frames 1-3, and the plan check for
  `start=1 end=10 step=2` uses frames 1, 3, 5, 7 and 9.

Producers: `python/synapse/autonomy/models.py` ·
`python/synapse/autonomy/planner.py` · `python/synapse/autonomy/driver.py` ·
`tests/test_render_plan_truth.py`

(2026-11-06 and 2026-11-07). The GPU node answers one blocker by execution: on

## Limits

- **anthropic 2.x remains unsupported.** The model-access guard still speaks
  only the 1.x auth convention, so the pin stays `anthropic>=1.0.0,<2`. The
  migration v5.97.7 deferred to v5.98 is unstarted.
- **The bridge-route receipt is proven by hermetic tests, not live.** The
  new tests drive the adapter with a bridge that mirrors the real failure
  arms; they were not run against a live Houdini bridge, and a change to
  the real arm would not turn them red.
- **A write the bridge fails after the handler completed it returns no
  receipt.** The reply is the integrity-only failure, so the caller learns
  the op failed but not what the handler wrote before the bridge undid it.
- **A step the start/end path cannot act on is not uniformly refused.** A
  step of 0 or a non-numeric step fails with an error; a negative step is not
  refused, and the farm returns a zero-frame report. No test covers step
  refusal.
- **A validator that raises does not fail the frame or the pass**, on the farm
  or on the progressive ladder.
- **A usdrender ROP whose product did not change can still return a flagged GL
  flipbook** from `houdini_render`. The farm and the ladder refuse it.
- **Live Houdini render and cancellation probes are still owed** for the
  sequence verdict. Its tests are hermetic.
- **A farm row outside the requested set still poisons the run.** It is no
  longer a retry target, but it stays in the run's accumulator, the evaluator
  keeps flagging it as unplanned, and the run ends `success=false` with
  `stop_reason=max_iterations`. Honest, but imprecise: the farm broke its
  contract, and the report says "tried too many times".
- **A boolean expectation passes on a numeric parameter.** `expect={"value":
  True}` is satisfied by a float parameter holding `1.0`. This matches
  Houdini's toggle semantics and is left as is.
- **Any list-valued expectation is refused**, not half-checked:
  `expect={"value": [1.0, 0.0]}` returns `parm.precondition_invalid`. Pin a
  uniform tuple with a scalar.
- **A float step such as 2.5 is converted to 2** by the handler and the
  planner.
- **No GPU image path ships.** The feasibility probe is not a build.
- **Setup remains unsigned.** The interactive wizard, the registry and
  Start-menu shortcuts, and a clean-machine installation are not qualified by
  this release.
- **The 2026-11-05 internal review is not published with this release.** G101
  and G32, named in the section headings above, are closed here, and G25 is
  closed for refused and failed writes.
