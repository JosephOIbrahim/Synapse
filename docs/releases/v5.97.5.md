# SYNAPSE v5.97.5

Windows + Houdini 22.0.400, Houdini Python 3.13. The release includes an unsigned
Windows Setup and source archives. Installation into an existing artist seat is
a separate action: save work and close Houdini before installing.

## What changes

- **Stable Moneta:** the Python backend is pinned to 1.3.0 commit
  `4f7afc73736aecce6d55d5e03f28fb3137d474d3`. The installer validates the
  dependency's exact inventory and redistribution grant, carries the MIT notice,
  and retains upstream metadata. See [the grant](../../installer/moneta_license.json),
  [validation policy](../../installer/synapse_setup/moneta_grant.py) and
  [installer checks](../../installer/tests/).
- **One experimental LIGHT operation:** an explicitly approved exposure change
  on one captured domelight in a closed disposable headless fixture. Calibration
  measures the actual host, restores every probe, fixes its training envelope
  before heldout validation, and uses bounded attempts and time. The gate keeps
  transaction ownership during evaluation. Rejection requires exact restoration;
  unexplained foreign changes quarantine without automatic undo. Cancellation is
  ordered against the commit decision. Local durable records remain unsettled.
  [Scope and procedure](../BOUNDED_LIGHT_HEADLESS.md),
  [gate](../../python/synapse/loop/light_gate.py),
  [custody](../../python/synapse/loop/light_custody.py),
  [transaction seam](../../python/synapse/recipes/transaction.py).
- **Release contents:** 37 SideFX reference files and obsolete references are
  excluded. Historical harness records and local orchestration configuration
  remain in Git history but are omitted from new source archives. Active release
  inputs have personal paths removed. This does not rewrite earlier tags or
  assets. [Archive policy](../../.gitattributes).

The native Rust wheel is not bundled, and the public installer keeps native mode
off by default. An individual seat can opt in after independent native and
persistence checks. This release does not install itself into an open session.

## Tests

The downloadable [installer verification record](https://github.com/JosephOIbrahim/Synapse/releases/download/v5.97.5/installer-verification.json)
and [public build report](https://github.com/JosephOIbrahim/Synapse/releases/download/v5.97.5/SYNAPSE-5.97.5-Setup.public-build.json)
identify the exact source commit, Setup/payload hashes and executed final checks.
Use those records to assess the binary; a passing test of another build does not
qualify it.

- Current composed H22 suite: **185 passed, 14 skipped**, 199 actual collected
  test cases. Its JUnit aggregate also counts 83 successful subtest reports;
  that does not mean 282 distinct tests. Producers include existing lifecycle,
  recipe verification, panic containment, new pure LIGHT checks and host guards.
- Explicit disposable host modules cover **19 matrix cases**, **four cancellation
  and foreign-edit cases**, and **10 review regressions**.
  [Matrix](../../tests/host/test_light_gate_matrix.py),
  [cancellation and quarantine](../../tests/host/test_light_gate_cancel_foreign.py),
  [review regressions](../../tests/host/test_light_review_regressions.py).
  These batches overlap with other checks and are not added together.
- A separate pure batch reports **64 passed, one skipped** on CPython 3.14.
  The skipped ctypes cache control targets CPython 3.13 and passes in actual H22.
  Eighteen deliberate in-memory safeguard mutations cause assertion failures
  with no test errors. [Pure controls](../../tests/test_light_precommit.py),
  [custody](../../tests/test_light_custody.py),
  [capture](../../tests/test_light_capture.py),
  [profile](../../tests/test_light_profile.py).
- The full panel comparison uses published 5.97.4 with its published dependency
  and the release candidate with stable Moneta. Both report **573 passed and eight
  failed out of 581**, with identical outcomes. The raw suites fail; this proves
  baseline equivalence only. Geometry/profile, receipt connection, endpoint
  discovery, dead-verb, tooltip, Ollama price, rail geometry and Opus identity
  failures remain. Two additional failures in the original recovered run did not
  reproduce; their cause is unknown.
- Separate normally configured native-seat probes on the existing 5.97.4 live
  runtime with stable Moneta 1.3.0 observe actual Moneta primary
  storage, advancing native scan/decay counters and zero fallback, then save and
  reopen disposable persistent-key data. A wrong-key copy refuses writes and
  preserves bytes. These qualify a local opt-in, not all artist stores or the
  public native-off installer default.

Independent source review is separate from executed evidence. Earlier failures
are retained in private release evidence rather than overwritten as passing runs.

## Limits

The LIGHT tests qualify a fresh closed disposable H22.0.400 fixture, not arbitrary
HIP files, artist GUI operation, render quality or foreign plugin races. There is
no new panel tool, full RC+xi framework activation, contract ratification or
external substrate installation. The existing Solaris recipe contract remains
`PENDING_HUMAN`. Local custody does not detect a matching rollback of both the
ledger and its independent acknowledgement, and is not a hostile-code sandbox.

Installer extraction and embedded maintenance-engine checks do not establish
interactive wizard, registry/shortcut, clean-machine or artist GUI qualification.
Production stores, encryption keys and artist scenes are not release fixtures.
Historical Git content is still history; export exclusions do not make it private.
Known-marker scanning is not a certification that every possible secret is absent.

The measured training/heldout envelope can refuse a later candidate; it does not
promise future population coverage. Moneta 1.3.0 implements undrained-attention
preservation for attached keyed snapshots. Degraded/keyless and unattached save
paths retain separate limits, and the local reopen probes do not establish every
attention/save/switch/quit path.

The prior native panic containment remains in place. Synthetic panic tests do not
prove every native extension's failure behavior or guarantee no partial writes.
