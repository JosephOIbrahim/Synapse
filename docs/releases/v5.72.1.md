# v5.72.1 - The receipts say the numbers now

A patch release that repairs this project's own evidence. **Nothing about the product changed.**

## What was wrong

Both v5.71.0 and v5.72.0 published a "Verification scope" section that read

> Measured on this build, alone, in this order.

and then listed five raw template placeholders - `{STOCK}`, `{SEAT}`, `{INST}`, `{QUAL}`,
`{PAYLOAD}` - where the measured numbers belong. Every one of those numbers had been measured
honestly against a real artifact. The document simply never received them, and nobody checked that
it had.

## What changed

- **Both published release pages are corrected in place**, filled from the artifacts on disk, and
  this release carries the corrected copies in the tree.
- **The composer can no longer fail silently.** It derives its target files from `VERSION` rather
  than a hardcoded path, and fills both brace spellings.
- **The release script now refuses to tag** if any `{PLACEHOLDER}` survives into the notes. The
  composer being fixed is not the same as the composer being checked.

## Why it happened, stated plainly

The composer was copied forward from an earlier release and string-replaced. That replaced
`release-5.70.1` but not `docs/releases/v5.70.1.md`, so it kept filling the *previous* release's
file. Its own guard then inspected that same previous file - already filled from its own release -
and passed. A guard that inspects the wrong file reports success for doing nothing, which is the
same failure class as a step that logs a number instead of gating on it.

## Verification scope

Measured on this build, alone, in this order.

- Stock suite: **{STOCK}**
- Panel seat suite, hython 22.0.400 offscreen: **{SEAT}**
- Installer unit checks: **{INST}**
- Installer qualification: **{QUAL}** against the isolated TestSetup, which carries the same
  payload sha256 as the published Setup (`{PAYLOAD}`).

## What changed in the product: two lines

`installer/` is byte-identical to v5.72.0. Under `python/`, exactly one file differs —
`python/synapse/__init__.py`, two lines carrying the version string, written by the release
script's own bump step:

    -__version__ = "5.72.0"
    +__version__ = "5.72.1"

Verify rather than trust:

    git diff --stat v5.72.0 v5.72.1 -- python installer

Expect **one file, two changed lines**. Nothing else in the runtime moved, so the code you install
is the code v5.72.0 qualified.

## Update

`SYNAPSE-5.72.1-Setup.exe` upgrades in place and preserves projects, memory, credentials and custom
files. The installer is **unsigned**; verify it against `SHA256SUMS.txt`.
