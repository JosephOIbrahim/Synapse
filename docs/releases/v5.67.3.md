# v5.67.3 — Panel reliability and memory recovery

This release ships the recent panel improvements and the repairs from the
September 8 CTO review. Artist approval remains authoritative; the optional
memory LOOP observes approved operations and does not choose scene actions.

## Artist-facing changes

- **Connect, then Doctor.** Both controls stay visible, with clearer spacing and
  a warm yellow Doctor accent. The tools control uses a lightning icon; the
  command shortcuts and Enter hint are centered.
- **Doctor is available directly from the panel.** It runs without a model call
  and reports its diagnostic result without blocking the interface thread.
- **Ollama selectors discover installed models.** Discovery also preserves a
  selected model and reports unavailable endpoints rather than replacing the
  list with invented entries.
- **Native Undo and Redo retain Houdini's history.** History commands execute
  outside a newly opened undo group. Provider service failures receive clearer
  messages, and reopening the panel preserves the model connection identity.

## Reliability repairs

- A lost, truncated or malformed MCP reply cannot trigger a second fallback
  execution of a possibly completed scene command. Fallback remains available
  when the tool request was definitely not sent.
- Raw and MCP-wrapped tool results retain receipts, recall results and capture
  paths. Checked vision capability is respected on both dispatch routes;
  malformed content is reported as an error.
- A process-owned worker registry survives panel reloads. Only the admitted
  worker can release its slot, preventing overlapping tasks across reopened
  panels, reentrant setup and delayed completion callbacks.
- The preferred MCP route records optional LOOP observations around its
  existing main-thread dispatch. An exception after dispatch does not replay it.
- Interrupted journals retain incomplete bytes and recover from committed
  events. Unreadable journals remain pending; temporary access failures cannot
  erase a known result. Recovery never replays the artist's scene action.
- Native main-thread timeouts remain unknown outcomes. Substrate worker stdout
  and stderr are bounded during collection, including when a child stops reading
  its input.
- The fixed Solaris lookdev verifier resolves a real standard MaterialX surface
  shader, validates its output name and types, and accepts valid NodeGraph
  forwarding. An existing attribute alone cannot establish shader correctness.

## Qualification and limits

The integrated repair candidate passed **384 focused checks** using Houdini
22.0.400's Python 3.13 and OpenUSD. Independent reviewers reproduced defects,
tested the corrections and applied removal/failure controls. The Solaris
validator also accepted Houdini's shipped Quick Surface material imported into
an anonymous in-memory USD layer.

These are isolated runtime, recording-transport and temporary-file checks.
They do not qualify a fresh live panel demo, a live COP cook/render, real-substrate
end-to-end recall, production-scale performance or power-loss durability. A
cross-runtime MCP stdio dependency check was excluded from the native selection
and is covered by the stock Python suite. Test selections overlap; their counts
must not be added into a unique-test total.

The unpublished TOPs/render-farm branch remains separate from this release.
Its cancellation and output-recovery repairs do not imply that native export,
Karma execution or render quality has been newly qualified.

**Restart Houdini after installing this update.** The retained host registry
cannot safely migrate a worker already running under the previous code.
Stage 0 saved experience matching includes the exact SYNAPSE version; existing
checked experiences need a matching v5.67.3 rehearsal and import before they
can appear as suggestions.
