# v5.94.0 - Recipes that hold, memory that answers, turns that end

Fourteen commits on top of [v5.93.3](v5.93.3.md), from one day of hardening before the demo take. Three of the changes were seen working in the Houdini GUI on the release's code. The rest are unit-tested and have not been exercised in Houdini; the limits below say which.

**Scatter builds the recipe as written.** v5.93.3's notes listed this limit: "The model edits the recipe. The recipe's values are what the model is shown, not what it must send." On v5.93.3 with five hardening commits, in the GUI, that is what happened: the recipe lookup returned `maxangle` 20, and the model built with `maxangle` 45, following an older note in the scene's memory. Two changes close it. `synapse_solaris_build_graph` takes `recipe="scatter_instances"`: with `dry_run` it reads the scene and returns the recipe's five bindings in one call, each with the place it was read from; without `dry_run` it reads again and builds only when every binding is known. When one is missing or ambiguous the answer is UNKNOWN and nothing is created. And when a model sends its own graph, a Scatter Instances node that authors the recipe's prim (`/World/scatter_rocks`) is held to the recipe's fixed parameters, each correction is reported, and the values are read back after the build. Any other Scatter Instances node is built exactly as sent.

**The memory answer no longer depends on the model's choice of tool.** A scene's landing record lives in its memory notes, which only `synapse_project_setup` returns. Search and recall read decisions and do not cover the notes. The panel's prompt did not say so, and on the evening of 10/4 two live answers in a row came from search and recall alone and missed the record. The prompt now sends questions about what is remembered of a scene to project setup first, and asks for the answer to be labelled as recall.

**A turn has a budget.** The round count was the only ceiling on a panel turn; one turn on 10/4 ran 15 minutes and read 5.77 million input tokens before round 25 stopped it. A turn now also ends after 600 seconds (`SYNAPSE_TURN_BUDGET_S`) or 3,000,000 input tokens (`SYNAPSE_TURN_BUDGET_TOKENS`). It ends the way the round cap does: one last model round with no tools, a closing line that names the budget, and `cap` in the turn ledger. `0` switches a budget off.

**Housekeeping rows are off unless asked for. This changes default behaviour.** The session tracker used to write "AI session started", "Executed: <command>" and a session summary into the memory store for every client. One night of bridge calls wrote 461 such rows and took a store past a record ceiling. `SYNAPSE_AUTO_MEMORY=1` turns them back on; unset writes none. Explicit memory writes, decisions and error rows are unaffected.

**Smaller changes.**
- **A store past 2,000 records binds again.** The ceiling refused any bind, load or adoption once a store held more than 2,000 records. It now limits what one migration carries.
- **An error is not a success.** Memory search, add, decide and recall fail when the store reports an error; before, the error came back as data inside a success. The integrity bridge no longer counts a failed handler as a verified operation.
- **Missing parameters are reported.** Four tools (scene template, component builder, Megascans import, COP AOV composite) skipped a parameter that does not exist on the build and still reported success. They now return `parms_missed`.
- **`execute_python` returns a measured zero.** A script that sets `result` to 0, False or an empty list got "executed" back.
- **`execute_vex` runs over the class it was asked for.** "Points" ran over primitives.
- **An error reply carries the request's id,** so a client no longer waits out its timeout.
- **The freeze watchdog stands down when Houdini quits.**
- **Two COP tools describe what they do.** `cops_create_network` says it makes a legacy COP2 network. `cops_analyze_render` returns `checks_requested` and `checks_performed` where it returned `checks_run`, and a clean node is `not_analyzed`, not `pass`: it reads no pixels.
- **The render-comp recipe cannot fail half-built,** and no longer triggers on "set up render comp" or "composite render passes".
- **Two ratchets.** Node types and parameter names in call sites, and in code strings under `routing/`, are checked against the 22.0.400 catalog. Today's misses are recorded as baselines that may only shrink: 24 and 18.

**Source release for Houdini 22.0.400 / Python 3.13.** No new Windows Setup is included. The v5.86.0 Setup contains none of the changes in v5.87.0 through this release. Follow [source installation](../getting-started/installation.md#source-installation), then restart Houdini to load the updated source.

## Validation and limits

**Scatter, in the GUI.** Houdini 22.0.400, relaunched on the last code commit of this release, a copy of the demo scene, the panel's agent on deepseek-v4.1-flash:cloud, the typed request "Scatter rocks along the cobblestone lane." Three tool calls: the recipe lookup, the resolver with `dry_run`, and the build. The resolver returned RESOLVED with all five bindings and their sources. The build reported no corrections and no missed parameters, and the reply states the direction mask at `maxangle` 20. The turn ledger records 3 rounds and 71,807 input tokens. Through the scene's camera the rocks sat on the lane floor, and none were seen on walls or windows. The same request two hours earlier, on v5.93.3 with five hardening commits: 8 rounds, 17 tool calls, 410,258 input tokens, a build at `maxangle` 45 and 763 instances.

**The memory answer, in the GUI.** Before the prompt change, on the same evening and on this release's code without it: two answers from search and recall that did not give the doorway assumption or the ground offset, then the full record at once when project setup was asked for by name. After it, in a fresh session after a relaunch, "What do you remember about how this world was landed?" made one `synapse_project_setup` call and gave scale 2.1362, two doorways taken as 2.10 m, ground offset 1.2897 m and ground height -0.016 m.

**The watchdog, on a real quit.** Houdini running this release's watchdog change was closed from its main window. The log shows "Watchdog stopped" during the quit and no freeze alarm.

**Tests.** The full `tests/` suite passed on the last code commit, on Windows with Python 3.14, with the tests that need a Houdini runtime deselected as CI does: 10,917 passed, 430 skipped, 183 deselected, 5 xfailed, 0 failed. The release commit on top of it changes version strings and documents only. Publication requires all six GitHub CI jobs to pass on the exact tagged commit, linked in the GitHub release.

**Limits.**
- **One run each.** After the changes, the Scatter result and the memory result are one GUI run apiece, with one wording and one model. The pit plan's bar for the resolver was three runs from a fresh launch.
- **No instance count at 20 degrees in the GUI.** The reply says it could not see the viewport, and the count was not read from the stage. v5.93.3's hython figure for this recipe was 758.
- **The prototype is 0.06 m.** The recipe's sphere is 0.06 m; the scene's older note said 0.04 m, and the reply said so.
- **The resolver knows one scene shape.** `/stage`, exactly one camera, a Camera LOP feeding a Render Settings or Karma Render Settings node directly, and one imported world that still carries its import record. Anything else is UNKNOWN, by design.
- **Enforcement is keyed on the prim path.** A model that sends the recipe's graph under a different `primpath` is not corrected.
- **A prompt change.** The memory change is a sentence in the panel's prompt. A model can still ignore it.
- **The older Scatter note is still recited.** The scene's notes still say "45 degree" and "763 instances", and the memory answer repeated the 763. Nothing in this release rewrites a note.
- **Not exercised in Houdini:** the `parms_missed` reports, the memory handlers' failure path, the turn budget, the COP changes, `execute_python`'s falsy result, `execute_vex`'s class table and the error reply's id. The housekeeping default was live for the runs above and was not checked row by row.
- **The store's real-USD mode still falls back on a rebind.** With the pane connected before the scene opens, the second store open logged "Moneta init with use_real_usd=True failed" again. The store still loaded its 2,026 records, and search and recall ran in that state in the earlier session. Not fixed.
- **Not fixed:** a retried change can still apply twice. The reviewed fix, a reply cache keyed on the command id, is unsafe here because recipes derive the id from the payload.
- **The TOPs render tools still skip parameters silently.** That file is quarantined by the repo's own test.
- **The baselines are leads, not proven bugs.**

The inherited [v5.93.3 limits](v5.93.3.md#validation-and-limits) remain, except "The model edits the recipe", which this release closes for the Scatter recipe, and "Not seen in the GUI", which it closes for the 20-degree mask.
