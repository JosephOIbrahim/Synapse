# v5.85.4 — A first save that no longer freezes

**The first save of an untitled scene no longer freezes Houdini.** When an
untitled scene is saved for the first time, SYNAPSE copies the memory it kept
for that scene into the new project. It wrote a full checkpoint for every
record, on Houdini's main thread, so the time grew with the square of the
record count. In a timed run with 1,458 unsaved records, the first save took
309 seconds. The copy now checks the whole batch once, checkpoints once and
mirrors once, so the number of checkpoints no longer depends on how many
records there are.

**Each untitled session keeps its own memory.** Launching Houdini into an
untitled scene used one shared memory folder under the temp directory. Every
launch inherited every earlier launch's records, and the first save of each
scene carried all of them into its project. Each launch now gets its own
folder, which is what File > New already did. Records that earlier launches
left in the shared folder stay on disk where they were. They are no longer
copied into new projects.

**Clearing the file-based memory store no longer hangs.** SYNAPSE keeps memory
in one of two stores. The file-based store's clear waited on a lock it already
held, so a call to it never returned. The only caller in SYNAPSE is the Clear
All button of the older `synapse.ui` panel, which the registered Houdini panel
does not load, so a normal session was unlikely to reach it. Clearing now
empties the records and the pending writes, releases the lock, and then saves.

**The scout tests no longer depend on your SideFX help library.** A checkout
with a SideFX library configured had its pages mixed into the scout test
fixtures, and two tests failed there while a clean copy passed. Those tests
now run with the library switched off. The library merge keeps its own tests.

**Source release for Houdini 22.0.400 / Python 3.13.** No new Windows installer
is included. The older v5.75.2 Setup does not contain these changes. Follow
[source installation](../getting-started/installation.md#source-installation),
then restart Houdini and separate MCP processes to load the updated source.

## Validation and limits

The save times were measured in `hython` on Houdini 22.0.400 with the Moneta
store, real `pxr` and 1,458 records. With the v5.85.3 code holding them in the
shared folder, the first save took 309 seconds. With this code, a session
holding all 1,458 saved in 3.2 seconds. With the 1,458 left in the shared
folder and one new record in the session, the save took 0.09 seconds and only
the new record was copied. Timings on Python with the hash embedder show the
same shape: 100, 200 and 400 records took 1.24, 3.87 and 14.11 seconds before
the change and 0.15, 0.24 and 0.47 seconds after, with five snapshots at
every size.

On that machine the default embedder falls back to hashing, because Houdini's
Python has no ONNX session, yet the store records the model's id. With the
ONNX model, re-embedding each record would cost roughly 5 to 15 milliseconds.
That estimate was not measured.

Eleven new tests cover the three fixes. Against the v5.85.3 code, ten of them
fail. The eleventh, a copy that fails halfway and completes on retry, pins
behavior both versions keep. Four assertions in three address tests used to
pin the exact shared untitled folder. They now assert the per-session folder,
which is what they were guarding: a writable address in the temp directory,
never Program Files or the working directory. The full `tests/` suite passed
locally on Windows with Python 3.14, with the tests that need a Houdini runtime
deselected: 10,171 passed, 457 skipped, 0 failed. Publication requires all six
GitHub CI jobs to pass on the exact tagged commit, linked in the GitHub
release.

Some limits remain. The GUI first save was not repeated after the change; the
`hython` save runs the same callback path. The retry test injects its failure
before a deposit. A failure inside a deposit takes the failed path, which the
verified reopen still guards, but no test drives it. An untitled session's
notes still go to the shared untitled folder while its memory sits in its own
folder. The Moneta store still cannot be cleared: it refuses, and the older
panel's Clear All button only logs the refusal. On the file-based store, a
background write that was already in flight when the clear began can still be
appended after the save and bring a cleared record back on reopen.

The inherited [v5.85.3 limits](v5.85.3.md#validation-and-limits) remain.
