# v5.97.2 - Safer Solaris wiring

**Seven fixes in the Solaris graph builder.** Insertions keep the exact upstream
output. Existing merge inputs reserve explicit slots before implicit appends.
Invalid request shapes stop before scene changes, and a verified connection
receipt comes from the final observed wires.

This is a source release for Windows/Houdini 22.0.400 and bundled Python 3.13.
No new Windows Setup is included. The older v5.86.0 installer does not contain
these fixes; follow [source installation](../getting-started/installation.md#source-installation).
Reload/restart instructions apply when the artist chooses to update, not to a
running session merely because a source release was published.

## What changes

- An insertion must preserve the displaced **node and output index**, not just
  reach the same node through a different output.
- An implicit append to an existing merge cannot reuse a slot reserved by an
  explicit wire later in the request. Both request orders get the same plan.
- `display_node` must be a string or `None`, including on empty graphs.
- Sparse input-gap warnings use adjacent-index comparisons, not an allocation
  proportional to the largest input number. Nonexistent native ports still fail.
- `dry_run` must be a boolean. A string such as `"false"` does not become an apply.
- Managed `parms` must be an object. Artist-owned existing-node metadata remains
  ignored rather than treated as a parameter edit.
- After layout/display/cook work, final socket readback determines the receipt.
  Later drift produces an error instead of a stale verified connection.

Product files: [`handlers_solaris_graph.py`](../../python/synapse/server/handlers_solaris_graph.py)
and [`solaris_graph_plan.py`](../../python/synapse/server/solaris_graph_plan.py).
The [scoped regression tests](../../tests/test_solaris_evolution_regressions.py)
cover the seven fixes with synthetic host doubles.

## What was measured

The exact native-tested source commit is
`b7301f3f985d1c0a9876b8ee629472392422bc26`, based on
`54cbe14264c29792678d9fd12a11b36ac5f2fd90`. Release documentation/version metadata
does not alter the [pinned native input closure](../../harness/notes/release-v5.97.2/native_validation/input-pins.json).

In two separate headless H22.0.400/Indie processes, actual HOM sockets and composed
USD were measured through the complete copied handler:

- 21 preflight controls preserved native scene state and undo history.
- Seven positive/recovered graph cases passed preview, apply and repeat checks.
- Three deliberately corrupted real sockets after native cook failed closed;
  native undo restored the exact graph/USD state and undo labels in each case.
- Seven saved cases reopened and replayed in a fresh process with zero full-state
  differences. Artist sentry parameters, comments, position and user data survived.

The producer executed 73 handler calls in total. Both processes exited zero;
controller wall time was 5.6373359 seconds. These synthetic timings do not measure
artist time or a complex scene's benefit.

Evidence and original reproduction code:

The source candidate's existing CI was verified across six Windows/macOS/Ubuntu

cell. That historical run is not attestation of a later release commit. Final
publication requires successful CI for the exact final 40-character commit SHA,
with version/README and applicable production-contract checks included.

## Limits that remain

**This is scoped native handler validation.** It does not establish production
package startup, interactive panel/HTTP/WebSocket/bridge execution, natural GUI
callbacks or a distinct physical licence-seat allocation.

**Undo depends on the caller's boundary.** The standalone handler restored its
own group in these tests. An outer production undo group can prevent immediate
rollback; grouping alone does not promise automatic scene restoration. Inspect
partial work and use the artist's undo when required.

No whole-catalog freshness/strict companion battery, new installer qualification,
painted Qt seat run, nonempty unrelated artist undo-history control or conflicting
merge opinion-strength assay is claimed. Current production-path CPU checks are
structural/synthetic and do not replace those native/interactive gates.

The live installation was not upgraded. The copied-scene benefit benchmark remains
unmeasured and needs a separate controlled run. No roadmap/proposal feature,
autonomous model training or memory evolution is part of this release.

Inherited [v5.97.1 limits](v5.97.1.md#limits) remain unless explicitly changed here.
