# v5.93.2 — A tool call stops waiting two seconds, Scatter keeps to up-facing faces, and the memory card shows only memory

Three fixes from a day of checks on [v5.93.1](v5.93.1.md), and a tidy of the
repository's root. The first fix was measured in the Houdini GUI. The other two
were not seen there.

**A tool call stops waiting two seconds.** The panel opens one connection to
Houdini for each tool call, and it opened it to `localhost`. On Windows that
name resolves to `::1` before `127.0.0.1`, the listener is IPv4-only, and each
connect waited about two seconds before it fell back. Every tool call paid it.
The panel now connects to `127.0.0.1` first and keeps `localhost` as the
fallback for a listener bound to IPv6 only.

**Scatter Instances keeps to up-facing faces.** The recipe's scatter node now
sets `enabledirection` to 1 and `maxangle` to 45. Without them the instances
landed on every collider face the camera could see, walls and windows
included. The mask moves most of them down to the lane. It is not ground-only:
up-facing ledges, sills and roofs still catch some.

**The "what I remember" card shows only memory.** `synapse_recall` falls back
to the knowledge corpus when memory has no match. The card then showed a
reference article as a HIT: an article about heightfield terrain sat under
every reply about a cobblestone lane. A match whose source is the knowledge
corpus is no longer counted as a deposit, and a recall with nothing else hides
the card. The recall tool itself is unchanged.

**The repository's root is tidier.** This one is for developers. Eight root
scripts that nothing in the product, the tests, the installer or CI refers to
moved to `attic/root-2026-10/`, and four dated reports moved to
`docs/archive/`. Nothing was deleted. `LATENCY_PLAN.md`, which described v4.2.1
on Houdini 21, now holds this release's measurements.

**Source release for Houdini 22.0.400 / Python 3.13.** No new Windows Setup is
included. The v5.86.0 Setup contains none of the changes in v5.87.0 through
this release. Follow
[source installation](../getting-started/installation.md#source-installation),
then restart Houdini to load the updated source.

## Validation and limits

**The connect, measured.** Against the listener on port 9999 of a running Houdini 22.0.400: `localhost` took 2.01 s to connect and `127.0.0.1` took 0.009 s. In the panel's turn ledger for the week before the fix, 27 of the 30 tools with three or more calls had a median of 2.0 s or more, `synapse_ping` among them.

**The fix, seen in the GUI.** In Houdini 22.0.400 on the demo scene, v5.93.1 and then v5.93.1 with this fix, same model, same two requests. Tool time per call went from 2.02–2.75 s to 0.05–0.75 s. "How was this world scaled and grounded?" took 37.2 s with 11 tool calls before and 8.7 s with 6 after. The Scatter request took 54.0 s with 10 calls before and 25.6 s with 9 after. The model made a different number of calls each time, so the per-call time is the like-for-like number. A recorded run-through on the fix then passed all five demo beats' content: the recall, the scale-and-ground read, a 24-frame render with 24 of 24 frames verified, a Scatter build and the camera-path read. In that run the scale-and-ground request took 20.9 s, 15.0 s of it in one `synapse_memory_query` call.

**The mask, in hython.** Houdini 22.0.400, the demo scene, the recipe's own payload built with `hou` and no model. Without the mask: 531 instances from −0.07 to 11.01 m, 346 of them above 1.5 m. With it: 763 instances from −0.17 to 7.58 m, 53 above 1.5 m. No parameter was missing and no node reported an error or a warning.

**The mask, through the panel agent, headless.** Three Scatter runs in hython 22.0.400, each on a fresh copy of the demo scene, with the worker built as the panel builds it, on deepseek-v4.1-flash:cloud through Ollama. All three built in one `synapse_solaris_build_graph` call with the display flag left where it was and no node warnings: 763, 763 and 577 instances, in 33 to 54 s. No run called recall, search or context. In the third the model lowered the scatter count from the recipe's 2,000 to 1,500. Six runs of the same request on the old recipe, on 1 October, gave 531 each.

**Why the recipe carries it.** Before this release the model set the mask only when it found it in a memory record that an earlier bench had written. In three GUI runs on the old recipe it set it twice and left it out once, when 531 instances landed on the walls again.

**The card.** Three new tests on the function that decides what the card shows: a knowledge-only recall is not a hit, a memory match still is, and a mixed recall shows only the memory. Under hython 22.0.400 on real Qt, the test files that touch the card ran 233 passed and 27 failed on this code, against 230 and the same 27 on the code before it.

**Tests.** New test files: `tests/test_tool_executor_loopback.py` (2 tests) and `tests/test_recall_card_knowledge.py` (3). One existing test that pinned the literal `localhost` now expects `127.0.0.1`. The full `tests/` suite passed on the release tree on Windows with Python 3.14, with the tests that need a Houdini runtime deselected as CI does: 10,779 passed, 428 skipped, 183 deselected, 5 xfailed, 0 failed. Publication requires all six GitHub CI jobs to pass on the exact tagged commit, linked in the GitHub release.

**Limits.**
- **Two of three not seen in the GUI.** The recipe's mask ran in hython, with `hou` and through the panel agent. The card change ran as tests. Neither has been seen in the Houdini GUI. The card's hide is Qt code with no test of its own.
- **Not ground-only.** With the mask, 53 of 763 instances still sat above 1.5 m.
- **The model edits the recipe.** In one run of three it changed the scatter count. The recipe's values are what the model is shown, not what it must send.
- **A reply can contradict its build.** On the old recipe, one GUI reply said the rocks were on the walls and offered to add the mask, when its own call had set it and its own numbers were the masked result.
- **The memory query.** One `synapse_memory_query` call took 15.0 s in a GUI turn, and its median over the week was 17 s. Not fixed.
- **Prompt size.** With the two-second wait gone, a turn's time is the model's. One Scatter turn sent 599,114 input tokens over 11 rounds, and no turn has had a prompt-cache read.
- **The slash palette.** Typing `/scene` and Enter opened the render workspace, and `/help` and Enter sent an unrelated question to the model: the top row is a fuzzy match on descriptions, not the exact command. `/render` and `/spatial` chose the right row. Not fixed.
- **Other tools' undo steps** still read as the tool's internal name and its arguments, the Scatter build's included.
- **The Render dialog** took about 30 s to fill in the first time it was opened in one session, and scrolling over one of its number fields changes the value.
- **A headless agent run opens the live memory store.** Setting `SYNAPSE_MEMORY_BACKEND=jsonl` for the bench did not keep it off the workstation's Moneta store. It added no records, and it rewrote the snapshot on exit.
- **Scope of the runs.** One model, deepseek-v4.1-flash:cloud, and one scene.

The inherited [v5.93.1 limits](v5.93.1.md#validation-and-limits) remain, except one in part: three of that release's five changes have now been seen in the GUI.
