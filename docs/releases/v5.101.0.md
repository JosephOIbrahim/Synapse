# SYNAPSE v5.101.0

**The Render QC timing measurement lands, and it does not clear its budget.** A
four-part harness stages frames, times three passes per frame, decides under a
frozen rule, and emits a receipt that recomputes from raw records. The verdict
is **branch 4**: on the deciding tier the pipeline's floor — everything except
the dense analysis — is **5.732 s** against the **2.0 s** the frozen rule
carries, 2.9× over, while read plus write is only **0.300 s**. A cheaper scan
cannot reach the budget, because the scan's dense share is **12%** of the work.

**Durable worker receipts land behind a gate.** A request record and one
terminal receipt per request, written through an exclusive temp and
`os.replace`, with the reply's mask bound to the worker that wrote it. Nothing
calls them yet, and the node that owns them has **not** passed its crux review.
See [Limits](#limits).

Every comparison in this note is against the v5.100.0 tag unless it names
another commit. The timing lane is harness-only: it changes nothing an
installed seat runs. The receipts lane adds one product module, described
below.

## The timing measurement

- **Verdict: branch 4, row 3, unanimous** across the three deciding stills,
  char-9 and char-2. Producer:
  `harness/vision/qc_timing/timing_receipt.json`, `decision.units`.
- **Deciding tier:** T **6.474 s**, R+W **0.300 s**, Floor **5.732 s**, dense
  share **0.120**. char-9: T 3.469, R+W 0.185, Floor 3.079, share 0.113.
  char-2: T 2.310, R+W 0.067, Floor 2.196, share 0.047 over 24 frames.
  Producer: the same `decision.units` block; every value is the median across
  that unit's conclusive frames.
- **The run:** 541 records — 417 timed, 121 untimed, 3 dry. **0 exceptions,
  0 inconclusive, 0 check disagreements.** 45 passes were voided, every one
  naming a foreign process caught in the before or after scan (`python.exe`,
  `python3.13.exe`, `hython.exe`, `husk.exe`); this session started none of
  them. No voting unit lost its conclusive frames. Producer:
  `run-20261111-1357/timed/raw.jsonl`.
- **The budget is an input to the measurement, not a result of it.** The 2.0 s
  constant is `B_SECONDS` in `harness/vision/qc_timing/decide.py`, part of
  frozen rule revision 2 (`B = 2.0`, `threshold = 0.5`), and the receipt records
  the same value in its `rule` block. Every figure above was computed against
  that 2.0 s. Whether 2.0 s is the right number is a separate open question
  (QC-Q3); it is not waiting on the measurement existing.
- **Independently recomputed** by a referee that did not build the receipt:
  all 1,240 per-frame numbers, 81 boundary cases at T = 2.0, R+W = 2.0,
  Floor = 2.0 and share = 0.5, and `decide.decide()` returning a dict identical
  to the receipt's `decision`. Recomposing from the producer's own code at
  `f91d5d28` reproduced the file byte for byte.
- **The receipt carries no frame names and no workstation model strings.**
  0 of 124 staged names, no stem and no project-name form, and neither a
  `cpu_model` nor a `scratch_drive_model` key anywhere in the document.
  Producer: `make_receipt.compose()` at `f91d5d28`.
- **Closure predicate:**
  `harness/next-release/proposals/predicates/test_nr_qc_timing.py`,
  **36 passed** at `195365a1`.

## Limits

- **No artist sees a finding from the timing harness.** It is a measurement
  tool under `harness/`; nothing in the product calls it.
- **Nothing calls the receipts module.** It ships dormant.
- **The budget question is open.** The 2.0 s constant is in the frozen rule and
  every figure above is computed against it. Whether 2.0 s is the right number
  is owner decision **QC-Q3**, still open. The measurement informs that
  decision; it does not settle it.
- **The timing data is one run on one machine.** 124 frames, one host, with 45
  passes voided for foreign processes.
- **The receipts crux has not run.** `NR-RECOVERY-RECEIPTS` waits on the Codex
  usage limit, not before 2026-11-14. This note's receipts section is
  provisional until then.
- **The never-launched rule node is not drafted.** It is recorded as a gate
  item of its own.
- **Master's range carries two merge commits.** `19a2fb74` and `db8b43a6` both
  merge the timing branch, because the trial tree was built, then stripped of
  frame names and workstation strings, then merged again. The tree content is
  what was tested and what CI passed on; only the log shape is doubled.
  Producer: `git log --format='%h %p %s' v5.100.0..db8b43a6`, where both entries
  show two parents and neither commit touches a product path.
- **This note does not report a local suite count as a release number.** The
  machine that ran the two trees had `mcp` absent, which is why its rows carry
  60 failures and 92 errors that CI does not. Those rows exist to show the two
  trees agree; the CI table below carries the release's counts.
- **anthropic 2.x remains unsupported.** The pin stays `anthropic>=1.0.0,<2`
  in `pyproject.toml`.
- **Setup remains unsigned.**
