# SYNAPSE v5.103.0 — the SIM plane

**Additive and inert.** This release adds a place to record harness changes and
the evidence for them. Nothing on the runtime path imports it, no existing
command behaves differently, and an installed seat works as it did.

## What ships

### `harness/sim/` — the Self-Improvement Memory plane

A harness edit that cannot say which failure it addresses, what it predicted and
what happened is a change nobody can evaluate twice. This package makes those
three things mandatory.

| Module | What it does |
|---|---|
| `schema.py` | `ProblemCluster`, `AttemptRecord`, `EditScope`, the lifecycle verdicts, and a JSON Schema. A cluster id is a hash of the normalised symptom, so the same failure lands in the same file without a human deciding it. |
| `store.py` | One file per cluster, append-only. No update, no delete. A per-cluster exclusive lock refuses a second concurrent writer rather than merging. Every line is validated on read as well as on write, so a hand edit fails to load instead of being trusted. |
| `setting.py` | σ = (model id, evaluation split, harness hash) with `differs_from()` — the input the transfer boundary consumes. |
| `harness_hash.py` | H_t as a hash over a declared list of editable surfaces. A declared edit moves it; an undeclared file does not. |
| `propose.py` | `validate_candidate` — the proposer contract, enforced by refusal. |
| `select.py` | Stage 2: prediction plus measurement becomes `RETAIN / REVISE / REPLACE / REMOVE / REJECTED_SCREENING` in plain code. |
| `transfer.py` | On a change of model or split, classify every retained edit: invariant gates anchor, model-specific repairs and domain heuristics go provisional, everything else is carried. |
| `cli.py` | `python harness/sim/cli.py transfer …` prints the plan as a table or JSON. |

### Two opt-in hooks

`harness/harness2/compositor.py` and `harness/jev/jev_screen.py` accept a
`sim_rejects` argument. With one, a candidate the ledger refuses cannot be
adopted and a leg that would CLEAR cannot — the screen can only get stricter,
never kinder. With none, both behave exactly as before.

### The held-out split, recorded as data

`python/synapse/loop/light_gate.py` now stamps each observation with its
`sample_index` and records `training_run_ids` and `holdout_run_ids` for every
validation round. `training_visible_runs(result)` is the only view a proposer may
read, and a run held out in any round stays excluded even when a later round uses
it as training.

### The bench split

`harness/bench/manifest.json` gains a `split` block: eight evolve tasks, four
holdout (`exp-02`, `sop-02`, `ari-02`, `mem-01`), weight 35 against 15. Only a
human edits it. `exp-01`, the T4 ceiling task, stays in evolve.

## Evidence

The release-gate stock suite on the release tree, fenced as every release runs it
(`run-stock-tree.sh`, Python 3.14.2, `tests/`, `-m "not live"`):

```
13,057 passed, 727 skipped, 11 deselected, 10 xfailed in 513.80s
```

Against the `v5.102.0` line at `2037c268` — 12,940 passed, 0 failed, 727 skipped —
that is **+117 passed and nothing else moved**: 117 is the new test count, no skip
was added, removed or relocated, and there are no failures. The figure is bound to
the run at `0bb06001`; later commits change documentation only, which
`git diff --stat` shows by touching nothing under `tests/`.

**Scope, stated plainly.** This gate collects `tests/` only. The project's default
`testpaths` also name `harness/jev/tests`, `harness/harness2/tests` and
`harness/attest/tests`, and the release gate has never collected those — they are
run separately when their files change. Calling this "the full stock suite" would
overstate it, which is why it is not called that here.

## What this does not do

- **It does not make an existing signal honest.** The RSI registry already
  records that nothing in this codebase has improved itself. A ledger can record
  that a metric is dishonest; it cannot make it honest. Any proposer built on top
  must first satisfy the ladder's L1 on its own reward signal.
- **SIM cannot see which model ran a turn.** No runtime artifact persists the
  model id today, so σ's model half is supplied by the caller. Until that
  changes, the transfer boundary works from a declared setting, not an observed
  one.
- **The held-out fence is a convention plus tests, not a type-level guarantee.**
  A consumer that reads raw `OBSERVED` rows rather than going through
  `training_visible_runs()` still sees held-out outcomes.
- **The custody ledger still holds every row.** It is an append-only audit chain
  and a row cannot be moved to a second chain without breaking the binding that
  makes it custody. What changed is that the split is stated rather than implied.
- **The compose hook needs candidates written to the SIM contract.** It accepts an
  `id`, a `cluster_id` (or a cluster declaration), an `ex_ante_prediction`, an
  `edit_scope`, a `target_artifact` and a diff. A stock `harness2` candidate carries
  `{id, claim, change, files, probe, exclusion}` and none of those, so a wave run as
  the harness stands today has every candidate refused. That is the safe direction —
  the gate fails closed — but it means the hook is unusable until the candidate
  schema grows the contract fields, and no wave has been run against it.
- **The bench remains one task set.** The `split` block names an evaluation
  split, but nothing forces a consumer to honour it; the 12 tasks are still the
  same file.

## Upgrading

Nothing to do. No configuration, no migration, no new dependency, no network
call. `harness/sim/` is inert until something calls it, and the release suite is
the evidence that nothing else changed.
