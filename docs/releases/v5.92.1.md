# v5.92.1 — A turn that runs out of tool rounds ends in words, and a failed build says what it left behind

**A turn that runs out of tool rounds ends in words.** The panel agent may use
up to 25 tool rounds in one turn. A turn that reached that limit used to stop
where it was, so the reply ended on the model describing a tool call that never
ran. [v5.92.0](v5.92.0.md#validation-and-limits) listed this as an open limit.
The last round now carries an instruction to answer with what the turn already
has. If the model still asks for a tool on that round, the tool is not run and
the turn closes with a fixed line: the request used all its tool rounds, nothing
changed after the last tool result, and sending the request again continues
from the scene as it is. That line is kept in the conversation, so the next
request starts from a complete turn. The usage ledger keeps `outcome: cap_hit`
and adds `wrap_up`, which is `answered` or `closed`.

**A failed build says whether it was rolled back.**
`synapse_solaris_build_graph` undoes its own work when a new node shows an error
badge. Inside the panel that undo could not run. The panel wraps every tool that
changes the scene in one undo step of its own, and Houdini 22.0.400 refuses an
undo inside an open undo step. So the new nodes stayed wired into the network,
while the error said "build rolled back" and "Nothing was left in the network".
The error is now written after the rollback attempt. When the rollback ran, the
text is unchanged. When it did not, the error says the build failed and was not
rolled back, that its nodes are still in the network, and that one Ctrl+Z or
REVERT removes them. With undo switched off, it says to remove them by hand.
Only the message changed. A failed build inside the panel still leaves its
nodes in the network until they are undone.

**Source release for Houdini 22.0.400 / Python 3.13.** No new Windows Setup is
included. The v5.86.0 Setup contains none of the changes in v5.87.0 through
this release. Follow
[source installation](../getting-started/installation.md#source-installation),
then restart Houdini to load the updated source.

## Validation and limits

**The round limit, forced.** The Scatter Instances request from v5.92.0 ran as one panel turn in hython 22.0.400, on a fresh copy of the demo scene, on deepseek-v4.1-flash:cloud through Ollama, with the limit lowered to 4, 6 and 9 rounds.
- At 4 rounds the model answered on its last round. The ledger recorded `cap_hit` with `wrap_up: answered`, and the reply ended as a question to the artist.
- At 6 rounds the model asked for another tool on its last round. The tool was not run, the reply ended with the fixed closing line, and the ledger recorded `cap_hit` with `wrap_up: closed`. The scatter had already been built earlier in that turn, and the closing line does not list it.
- At 9 rounds the request finished in 8 rounds, under the limit.

**The three v5.92.0 requests, repeated.** The Scatter Instances, blocker and Render Pass requests each ran three more times on the fix, by the same method as v5.92.0. All nine built their workflow, and every reply ended as a finished answer. No turn used more than 14 of its 25 rounds.
- Scatter: 18, 48 and 39 s, with 531 instances each time. In one of the three runs, the Configure Primitive node that hides the collider carried a warning badge ("Local variable 'protoprimname' not found"). The other two runs had no badges.
- The blocker: 7, 6 and 6 s, with the light's `light:filters` targeting a `KarmaBlockerLightFilter` prim each time.
- The passes: 14, 13 and 6 s, with two RenderPass prims each time.

**The rollback message, live.** On a copy of the demo scene in hython 22.0.400, `synapse_solaris_build_graph` was given a Python Script LOP that raises. Called directly, the build was rolled back and nothing was left in the network. Called inside another undo step, and through the panel's execution bridge with its undo wrapping forced on, the node stayed wired in and the display node lost its stage. The error then read "build failed and was NOT rolled back", and one undo removed the node. Headless hython leaves the bridge's undo wrapping off, which is why the v5.92.0 runs never showed this.

**Tests.** `tests/test_worker_round_cap.py` is new, with 8 tests. `tests/test_solaris_graph_oncamera.py` gained 4 tests for the wording of a failed build. The full `tests/` suite passed on the release tree on Windows with Python 3.14, with the tests that need a Houdini runtime deselected as CI does: 10,628 passed, 427 skipped, 120 deselected, 5 xfailed, 0 failed. Publication requires all six GitHub CI jobs to pass on the exact tagged commit, linked in the GitHub release.

**Limits.**
- **Scope of the runs.** Every run was headless, on one model, deepseek-v4.1-flash:cloud, and on one scene. Neither change has been seen in the GUI.
- **The closing line.** It says that nothing changed after the last tool result. It does not list what the turn changed before that.
- **The wrap-up answer.** It depends on the model following the instruction on its last round. When it does not, the fixed line closes the turn.
- **A failed build inside the panel.** Its nodes still stay in the network until they are undone. Other tools that undo their own work on failure have not been checked inside the panel's undo step.
- **The warning badge.** The Scatter recipe's warning in one run of three is not fixed in this release.

The inherited [v5.92.0 limits](v5.92.0.md#validation-and-limits) remain, except the round limit ending a turn mid-sentence.
