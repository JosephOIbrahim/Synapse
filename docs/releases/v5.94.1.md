# v5.94.1 - A reopened store keeps real USD

Three commits on top of [v5.94.0](v5.94.0.md): a documentation update from the night of that release, and two fixes from the morning after. Both fixes were seen working in the Houdini GUI on this release's code, and a five-beat rehearsal ran on it.

**A memory store reopened in the same process keeps real USD.** v5.94.0's notes listed this limit: "The store's real-USD mode still falls back on a rebind." The cause is now known. Moneta's USD target drops its stage and its sublayers when it closes, but keeps its root layer, and every store SYNAPSE builds for a directory stays alive until the process ends. So `.moneta/usd/cortex_root.usda` stayed registered with USD, a second open of the same directory in that process could not create it, and the store came back without USD sublayers after logging "Moneta init with use_real_usd=True failed". A rebind makes exactly that second open: it opens the target store, closes it, and opens it again to verify what it carried. Closing a Moneta-backed store now releases the target's root layer once the handle has closed, also when the handle's close raises.

**The Scatter resolver's collider label names no vendor.** The resolver labelled the source of its collider binding with the key of the import record, and that key carries a vendor's name. A binding label is part of a tool result, which the model reads and can quote in a reply. The label now reads "import record, grounding collider". Nothing else in the result changes, and the key the importer writes is untouched.

**The README and the architecture overview describe v5.94.0's changes.** The README gains a section on building from a verified recipe, with its own diagram, and states the turn budget. The overview shows the two ways memory is read and how a verified recipe reads the scene before it builds.

**Source release for Houdini 22.0.400 / Python 3.13.** No new Windows Setup is included. The v5.86.0 Setup contains none of the changes in v5.87.0 through this release. Follow [source installation](../getting-started/installation.md#source-installation), then restart Houdini to load the updated source.

## Validation and limits

**The reopen, outside the GUI.** Under hython 22.0.400, on scratch stores. Before the fix: the first open got real USD, the root layer was still registered after the close, and the second open logged the failure and came back with the mock target. After it: three opens in a row kept real USD, and the layer was no longer registered after each close. A rebind through `rebind_owner` carried one record, verified it and left a store with real USD; a record added afterwards was in the snapshot, in the JSONL mirror and in the typed cortex, and a later open read both.

The log shows the same two loads with no failure line 25 minutes later, in another session with the pane added first and the demo scene opened after it; Doctor was not run there. On 10/4 the log holds the failure line four times.

**Limits.**
- **The fix reaches into the engine.** It clears a private attribute, `_root_layer`, on Moneta's USD target. If Moneta renames it, the fallback returns, and only the three real-USD tests would say so. The proper fix is in Moneta's own `close()`.
- **The engine's own USD layers start empty on every open.** `.moneta/usd/cortex_root.usda` and `.moneta/usd/cortex_protected.usda` were 11 bytes each both times they were looked at on 10/5, after an open: Moneta's USD target calls `Sdf.Layer.CreateNew` on them when it is built. They are not the store's typed cortex, `.moneta/cortex_root.usda`, a separate file that SYNAPSE writes, which held 3.2 MB and was not recreated. The store loaded 2,026 records at the first of those opens and 2,027 at the second. What the engine would otherwise keep in those layers from one session to the next was not looked at. Not changed here.
- **Doctor's "moneta substrate" row still reads "needs attention",** with a note that the store is mock-backed. The note predates real-USD stores. Not fixed.
- **The rehearsal is one run,** typed, on a copy of the scene, not recorded.
- **An older note is still read back.** In the rehearsal, the answer after the relaunch gave the landing numbers and then repeated the scene's older Scatter decision, "45 degree" and "763 instances", minutes after the build at 20 degrees. Joe then recorded the 20-degree decision through the panel, which added it to the scene's notes and one record to the store. Asked again from a fresh launch on the demo scene, the answer gave both decisions in order and said the tightening "supersedes the earlier numbers": 758 instances at 20 degrees, against 763 at 45. That is one run. Nothing in this release rewrites or retires a note.
- **The model's calls vary.** All four Scatter turns made the resolver call and the build call. Three made one more call, a recipe lookup twice and project setup once. The fourth made two more, after the build, to read the instance count from the stage.
- **The first `synapse_project_setup` call of a session fails an internal integrity check.** The demo scene folder's tool journal holds 24 such failures since 9/30. Fourteen are followed by a successful call within two seconds, and ten are not: among those ten, two a second apart on 10/3, and one on 10/5 that came seconds after the pane was connected in an untitled session, with no question asked. Where that last call comes from was not traced. In each of the four panel turns on this release's code that began with that call, the second call succeeded in the same second, and the turn's ledger records one successful call. Not fixed.
- **Two tests fail under hython, with this release's fix and without it:** `test_hard_exit_preserves_all_deposits` and `test_ephemeral_path_is_pxr_free`. Each runs a subprocess of `sys.executable`, which there is hython. Both pass on stock Python 3.14.

The inherited [v5.94.0 limits](v5.94.0.md#validation-and-limits) remain, except "The store's real-USD mode still falls back on a rebind", which this release closes; "One run each", which is now three resolver runs and a rehearsal; "No instance count at 20 degrees in the GUI", which was read; and "The older Scatter note is still recited", which the bullet above updates.
