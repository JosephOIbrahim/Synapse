# Ruling — next-release direction (2026-11-06)

Owner direction, recorded so the graph and the teams do not re-litigate it.

## What the owner said

> "incorporating OpenCV 5.1 with GPU use for SYNAPSE … Think deeply about not
> replacing currently running tasks but development in tandem or consecutively."

Read as: the GPU vision goal stands, and new work must run alongside or after
whatever is already running — never by displacing it.

## Decisions this closes

| ID | Decision | Basis |
|---|---|---|
| **D6** | Build route: **source-built OpenCV 5.1 + opencv_contrib with CUDA** | The blueprint's own recommendation (§8.1 build candidates, §10 build lock). The CPU-only wheels cannot satisfy a GPU requirement |

*outputs*, not assumptions. They are recorded from the feasibility probe, never
guessed.

## Operating rules that follow

1. **Tandem, not replacement.** A new wave runs in its own worktrees; an
   in-flight CI run, a running render or another session is never stopped to
   make room.
2. **JEV decides the order.** The graph guard's receipt
   (`harness/harness2/runs/next-release/graph_decision.json`) names what lands
   now; a seat does not overrule it by preference.
3. **Every node lands the way G25 and G32 did:** worktree off `master`,
   failing-first tests, one atomic commit, adversarial review, and a merge that
   only the owner authorizes.
4. **The GPU track starts as a probe.** WP1 produces a feasibility receipt and
   a build route before anyone commits product code or a build artifact.
