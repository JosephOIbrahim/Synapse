=== THE CLAIM YOU ARE TESTING ===

The positioning document, leading the page, marked SHIPPING:

=== THE THREE WAYS THIS LIES. CLOSE ALL THREE. ===

**1. Do not benchmark a competitor's product.** We cannot run their code honestly and do not need to. **Arm B is computable without them:** serialise a scene the way any outside-in tool MUST, and count the tokens. That is a floor on what sending-the-scene costs, not a claim about anyone's implementation. State it that way in the receipt.

**2. FLAT COST ON A FAILED TASK IS NOT A FEATURE.** A system that answers nothing has beautifully flat token usage. **Every measurement pairs cost with OUTCOME.** A turn that failed its task is reported separately and NEVER averaged into the cost curve. This is the single thing that makes this benchmark honest rather than flattering, and if you do only one thing from this brief, do this one.

**3. Token counts may not be deterministic.** Run the same task on the same scene TWICE before trusting any figure. If they differ, that is a noise floor and it is MEASURED, not assumed - same discipline RETINA applies to render deltas.
