=== THE PRINCIPLE, AND WHY IT IS NOT NEGOTIABLE HERE ===

Blueprint §P2: **routing is probe-derived, never config-declared.**

> A model list typed into a config file is documentation. A capability probe against the provider is a probe.

**This project has the receipts for that distinction.** `hou.ActiveRender` is documented as working and is absent at runtime. `EXPECTED_HOUDINI_VERSION` was declared and never assigned, so every session silently loaded a five-year-old corpus. Five Solaris tools were registered, tested, and completely unreachable.

**A model list is exactly the same shape of claim**, and it fails the same way: quietly, while looking healthy.

=== WHAT YOU ARE BUILDING ===

A layer that returns a structure. **No panel work in this leg** — §04's own ordering, and the right one: a rail that reports a number the product cannot yet produce is instrumentation ahead of its subject.

**§3.3, the probe result:**

```
model, tier_candidates, available, quota_remaining, quota_total,
cost_per_1k_in, cost_per_1k_out, latency_ms, probed_at
```

**Colour state is COMPUTED from `probed_at` age and quota ratio. Never stored. Never typed.**

```
green   probed available
red     probed rate-limited
grey    probe stale - UNKNOWN, not assumed
```

**There is no state meaning "we think so."** That is the whole design, and it is why grey exists as its own state rather than degrading to green.

=== THE PART THAT NEEDS CARE ===

**Staleness must degrade to grey, never to green.** A probe that has not run recently reports UNKNOWN. The failure mode you are designing against is a panel that shows a model as available because the last probe said so an hour ago — that is the phantom-API pattern with a timestamp on it.

**And the probe must never be the thing that trips a rate limit.** A liveness check that consumes the quota it reports on is self-defeating; state the polling interval you chose and why.
