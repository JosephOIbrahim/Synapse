=== THE QUESTION ===

The tool surface is quoted at **17,310 tokens**. That is a total. **A total is not a plan** — you cannot reduce what you have not decomposed, and the shape of the reduction depends entirely on where the mass sits.

**Per tool, per component: name, description, input schema.** Which tools are the heaviest, and what inside them is heavy?

=== WHAT TO LOOK FOR, FROM FIRST PRINCIPLES ===

A tool definition has three cost centres and they compress differently:

**The name** — trivial, and untouchable. Renaming tools breaks every caller.

**The description** — prose, and the model reads it to decide when to call. **This is where verbosity hides**, and it is the only part where cutting risks correctness: a description trimmed too far produces a tool the model stops reaching for. Report length distribution, not just total.

**The input schema** — JSON Schema, and this is usually where the surprise is. Enums with 40 members, nested objects, per-field descriptions repeated across tools. **Schema mass often exceeds description mass** and is far safer to compress, because a shorter schema does not change when a tool gets called, only how its arguments are stated.

=== THE FINDINGS THAT WOULD CHANGE THE PROGRAMME ===

**Concentration.** If 20 of 120 tools carry half the mass, the reduction is a targeted edit rather than a sweep. Report the Pareto curve.

**Duplication.** Repeated schema fragments across tools — the same `node_path` description written 60 times — compress by extraction, not by cutting. **This is free reduction: no capability lost.**

**Dead surface.** A tool registered and never called costs its full definition on every single turn. Cross-reference the registry against any call evidence you can find — the routing log, the tool-status history, the tests. **S1 found five Solaris tools that were registered, tested and completely unreachable.** If any registered tool has never been invoked, its entire definition is pure cost.

**And the honest counter-question:** is 2,000 tokens even achievable for 120 tools? That is ~17 tokens per tool, which is a name and almost nothing else. **If the ceiling is unreachable at the current tool count, say so** — the real decision may be fewer tools rather than smaller ones, and that is a product decision, not an optimisation.
