=== WHY A PROBE COMES FIRST ===

The scoped-delta primitive needs pixels out of Houdini. Nobody has established how, on 22.0.368.

This project has now been wrong three times by designing on an assumed API, and once by sending a vendor a claim it had not fully checked. H3a - the probe that preceded H3b - is the reason the SideFX ask was correct rather than embarrassing. **This leg is that, for capture.**

=== THE QUESTIONS, IN ORDER ===

**Q1 - what capture verbs exist?** Live `dir()` against 22.0.368. At minimum:
  - hou.SceneViewer flipbook / flipbookSettings, and what it writes
  - hou.RopNode.render to disk (H3a already established: NO cancel verb on it)
  - Copernicus buffer readback - **note that "documented Copernicus buffer-to-numpy readback" is an OPEN SIDEFX ASK**, so treat a clean path here as surprising and verify twice
  - any hou.ui / viewport grab API
For each: CONFIRMED / ABSENT / UNVERIFIABLE with a `dir()` anchor.

**R50 is binding.** ABSENT requires a positive control ON THE SAME CLASS - H3a caught FIVE of its own ABSENT verdicts as artifacts of asking the wrong class. Where no control is possible, the verdict is UNVERIFIABLE, never ABSENT.

**Q2 - can a render emit an integer object-ID AOV?** This is the crux of the whole harness. Without a per-pixel prim identity there is no mask, and without a mask there is no "only X changed".
  - what render var / AOV name does Karma expose for object or prim ID
  - is it integer, and is it emitted as Raw (uncolour-managed)
  - does `retina/ingest.py` already know how to read it - it claims "ID/data AOVs (Raw) never colour-transformed", so check whether that path is exercised or aspirational

**Q3 - what does one capture COST?** Wall-clock, on a trivial scene. This decides whether verification runs per-mutation or only on demand, and it is a design input, not a footnote. R73 established the only render stop is `rkill` - blunt, process-level, effect on a partial frame unknown. **A verification that cannot be interrupted and costs 40 seconds is a different product from one costing 0.4.**

**Q4 - is the denoiser controllable?** A denoiser makes two identical renders differ NON-LOCALLY, which voids the primitive entirely - a one-prim mutation could move pixels anywhere in frame. Establish whether it can be turned off per-render, and whether it is on by default.
