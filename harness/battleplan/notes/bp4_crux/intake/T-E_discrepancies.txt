(2) "byte counts corrected 7168/6451 -> 7155/6384" — UNFALSIFIABLE FROM GIT HISTORY AS STATED;
    both actually-committed MANIFEST.md versions already show 7155/6384.

$ cd SCR_M && git log --all --format='%h %ci %s' -- docs/intake/src/MANIFEST.md
  2574de6b 2026-09-03 18:39:31 -0400  intake (in place, R135 harvest): ... byte counts

  03a4e43d 2026-09-03 18:12:01 -0400  intake: Home the World Labs blueprint + coffee notes
                                       under docs/intake/src/

Only two commits, anywhere in the repo (git log --all), ever touch this path. Both of them,
when read, already contain 7155/6384:
  - SCR_I MANIFEST.md (branch content at 03a4e43d): Bytes column = 7155 / 6384 (T-A_hash_
    verification.txt above).
  - SCR_M2574 MANIFEST.md (master content at 2574de6b): Bytes column = 7155 / 6384 (same).

There is no git-tracked version of MANIFEST.md, on any ref, that ever shows 7168/6451. The
claimed wrong numbers must therefore refer to an UNCOMMITTED intermediate state of the
hand-run's working tree (edited, then corrected, before ever being staged) — plausible given
the receipt's own "writers.hand_run" window is 18:04-18:13 and the harvest re-verify happened
at 18:39, but NOT something a git-history audit can confirm or refute. Recording this as
UNKNOWN/unverifiable rather than false: the claim is consistent with what a diligent harvester
would report if they watched the hand-run's screen, it just leaves no trace in `git log --all`
for an outside auditor to check independently.

diff of the two committed MANIFEST.md files (branch vs. master@2574de6b) — the ONLY
difference between them, confirmed via `diff`:
  35a36,37
  > (blank line)
  > **Harvest note (2026-09-03, CTO seat, R135 in-place):** this manifest was written by hand
  > on master outside the BP4 harness (writer: Joe's Claude Code session, 18:04-18:13). At
  > harvest the SHA256 column was re-verified with `Get-FileHash` on master (match) and the
  > Bytes column corrected to on-disk sizes (was 7168 / 6451; on disk 7155 / 6384 - cause of
  > the original miscount UNKNOWN). ...

So: the two committed manifests are identical in every substantive cell (file inventory table,
cross-check table) — the ONLY delta is this appended 2-line harvest-note paragraph, which is
where the 7168/6451 claim lives as PROSE, not as a table value that was ever actually
committed wrong. Master's own receipt marks the miscount's cause "UNKNOWN", which this audit
independently corroborates in the stronger sense: not just the CAUSE but the EXISTENCE of a
7168/6451-valued commit is unconfirmable.
