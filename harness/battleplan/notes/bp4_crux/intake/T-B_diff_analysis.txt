ADVERSARIAL NOTE on the check methodology itself (see mutations, T-F / INTAKE-M2)
--------------------------------------------------------------------
A naive check that only counts '@@' occurrences (`git diff ... | grep -c '^@@'`) is NOT
sufficient to verify "confined to the header block": git's default 3-line context window
merges a change near the header with a second, nearby change below the separator into a
SINGLE reported hunk when they are within ~6 lines of each other. Verified by mutation
INTAKE-M2 (full detail in T-F_mutations.txt): inserting an out-of-header line at line 16
(3 lines below the line-13 separator) still reports as 1 hunk under `grep -c '^@@'`, but a
range-aware check (does any '+' line's new-file line number fall at/after the separator)
correctly reddens. The acceptance predicate's own phrasing anticipates this: "the crucible
reads the hunk's line range" — a hunk-count-only check is not what's specified, and would
be a weaker gate than the predicate calls for.
