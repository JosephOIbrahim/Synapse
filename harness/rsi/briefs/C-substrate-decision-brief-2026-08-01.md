## Recommendation

RATIFY-AND-STABILIZE (Option A), gated on an address fix that must land first.

The decision this brief was convened to make has already been made in production and nobody noticed. `packages/synapse.json:22-25` sets `SYNAPSE_MEMORY_BACKEND=moneta` (commit b2c2c04, "turn the substrate on"), and the resolved copy was deployed to the live H22 prefs at `C:/Users/User/OneDrive/Documents/houdini22.0/packages/synapse.json` on 2026-07-27 08:34. The production log at `~/.synapse/logs/synapse.log` records 21 memory-store constructions between 2026-07-28 and 2026-08-01 13:16:32 and every single one logs `Memory backend: moneta (hash-ngram-v1-d256-n1_3)`. Zero jsonl inits in the window. There is a real Moneta snapshot on disk with 159 live session rows. So option (c) "full flip now" is moot, and option (b) "stay jsonl" is not a hold — it is a rollback of a flip that is already carrying production traffic.

What is NOT settled, and is the actual blocker, is that the substrate has no stable address. `store.py:890-904` compares the full path returned by `hou.hipFile.path()` against the bare string `"untitled.hip"`, so for an unsaved scene the comparison is always unequal and the `$HOUDINI_TEMP_DIR` branch is dead code. The store therefore lands in `<houdini-cwd>/untitled.hip/.synapse`. The log shows this landing in two different places depending on how Houdini was launched, and TWICE (2026-07-31 14:42:14 and 2026-08-01 10:25:01) it landed in `C:\Program Files\Side Effects Software\Houdini 22.0.397\bin\untitled.hip`, raised `PermissionError: [WinError 5] Access is denied`, and silently logged "Serving jsonl". The substrate reverts to a different backend based on a shortcut's working directory. Nothing built on top of that is durable.

So: ratify moneta as the substrate (it already is), but land the address fix as C-0 before any other RSI loop is allowed to persist onto it. Explicitly do NOT set `use_real_usd=True` and do NOT register the schema in this round — both are real levers with existing assets, but they buy nothing until the address is deterministic, and they add a hard `pxr` import to the memory path that SYNAPSE deliberately avoids.

## Options

- A. RATIFY-AND-STABILIZE (RECOMMENDED) — Accept moneta as the live substrate (it already is), fix the store address first, leave use_real_usd=False and the schema unregistered. WHAT BREAKS: nothing new; this is the current state minus a bug. Fixing _resolve_project_path (store.py:890-904) MOVES the store address for unsaved scenes — the 159 existing rows at C:/Users/User/untitled.hip/.synapse/.moneta would no longer be found unless the fix preserves or migrates that root. WHAT MIGRATES: one decision — adopt the existing C:/Users/User/untitled.hip root as canonical, or relocate to $HOUDINI_TEMP_DIR/untitled as the code intended and copy the snapshot across. ROLLBACK LEVER: two independent ones — delete the SYNAPSE_MEMORY_BACKEND block from the deployed packages/synapse.json (restores jsonl on next Houdini start), and the address fix is a single function revert. LOOPS CHANGED: R and A3 ride get_synapse_memory (handlers_render.py:1577; evolution.py via store.py) so both stabilize; S rides the same env switch through ledger.py:328 moneta_backend_enabled() so it stabilizes too; O and F are UNAFFECTED (see blocking fact 8). EFFORT: small — ESTIMATE, one function plus a migration decision; I did not scope the test surface. RISK: LOW, and it is the only option that reduces risk rather than adding a new surface.

- B. ROLLBACK TO JSONL and formally retire the 'Moneta is the substrate' claim — Remove the env block from packages/synapse.json and the deployed copy. WHAT BREAKS: the 159 production rows in the Moneta snapshot become unreadable to the running system (they are not lost — snapshot.json is on disk — but nothing reads them under jsonl). The ledger Moneta enrichment seam (ledger.py:280-330) goes dark by design. WHAT MIGRATES: nothing forward; you would want a reverse backfill of the 159 rows into memory.jsonl, which does not exist (backfill.py is jsonl→Moneta only, per its docstring at line 1). ROLLBACK LEVER: re-add the env block. LOOPS CHANGED: this is the option that KEEPS A3's converter alive — evolution.py:14-16 states its own removal condition is the moneta default, and tests/test_moneta_crucible.py::test_moneta_backend_never_fires_evolution proves moneta never fires it, so under jsonl A3's converter is back on the live path and must be fixed rather than deleted. EFFORT: trivial to flip, moderate to write the reverse backfill — ESTIMATE. RISK: MEDIUM — it discards a flip that has run without a functional complaint for five days, and it re-opens A3 as real work.

- C. SHADOW-BACKFILL RECONCILIATION — Set the backend to 'shadow' for a bounded period to reconcile the split data before re-committing to moneta. WHAT IT MEANS: store.py:867-881 builds a ShadowMemoryStore (shadow_store.py:1-17) — writes go to BOTH jsonl and Moneta, reads are served from the jsonl PRIMARY, and every read is diffed into a ParityReport. WHAT BREAKS: reads silently revert to jsonl semantics, so the 159 moneta-only rows written 7/27-7/28 stop being visible to recall — this is a REGRESSION from today, not a hold. WHAT MIGRATES: it does not migrate anything by itself; backfill.py is the migration tool and is separate. ROLLBACK LEVER: the same env var. LOOPS CHANGED: same three as A (R, S, A3) but with jsonl read semantics, which is the wrong direction. EFFORT: trivial to set — ESTIMATE. RISK: MEDIUM. Worth naming because the brief asked for a staged flip and this is the mechanism that exists for one, but the staging window has already been skipped in production and re-entering it costs read fidelity. Recommend only if the split data (blocking fact 7) turns out to matter more than five days of moneta traffic.

- D. FULL USD SUBSTRATE — Set use_real_usd=True in moneta_store.from_storage_dir and register the schema via PXR_PLUGINPATH_NAME in the Houdini package env. WHAT IT MEANS: this is the only option that makes the 'USD cognitive substrate' claim literally true; today it is false (159/159 rows have usd_link None). The assets exist and are ready — C:/Users/User/Moneta/schema/ contains plugInfo.json, generatedSchema.usda, MonetaSchema.usda. WHAT BREAKS: it pulls a hard pxr import into the memory path (Moneta api.py selects UsdTarget on that flag), reversing a stated SYNAPSE architectural constraint (moneta_runtime.py header, harness AP9); it adds real per-sleep-pass disk I/O; and it creates a new on-disk layout to version and back up that has never run under SYNAPSE's load. WHAT MIGRATES: existing rows do not gain usd_link retroactively — you would be starting a second, differently-shaped store. ROLLBACK LEVER: the flag, but any USD authored in the interim is orphaned. LOOPS CHANGED: same three, plus it is the only option that makes the agent.usd/cognitive-twin story real. EFFORT: unknown — I did not scope it and will not estimate. RISK: HIGH today, LOW-to-MEDIUM once the address is deterministic. REJECT FOR THIS ROUND, revisit after C-0 lands.
