01Verdict

Two halves of one path. The machine half runs but does not guarantee what it claims; the human half is complete, styled, tested — and has never been reachable.

The machine half of the proposal path is built and has run — propose → validate → park → apply is real code with 57 instantiate_graph and 65 propose_graph provenance records already on disk (producer: python -c over .synapse/provenance/*.json, counting the op key; 5,000 of 5,001 files parsed — the 5,001st is a .tmp). What it does not do is hold the three guarantees it was graded on. Of "one undo group / one main-thread dispatch / one cook": one is asserted without evidence, one is three dispatches under a 10-second bound that does not stop the payload it abandons, and one does not exist.

The human half — the surface where a person reads what the machine proposes and says yes to part of it — is a complete, styled, test-covered widget wired to a gate that nothing in production feeds. get_process_bridge() is the only non-test constructor of LosslessExecutionBridge in the tree (shared/bridge.py:2942; grep for LosslessExecutionBridge( returns exactly one production hit) and it builds gate-less: bridge._gate = None with consent_callback=lambda op: True (shared/bridge.py:2942-2943). _check_consent therefore never reaches Path 1 (shared/bridge.py:2436-2450), _propose_gate is never called (shared/bridge.py:2452-2464), HumanGate.propose() has no production caller, and _ProposalCard never renders.

The single thing most in the way is not the card's shape — it is that the card has no producer, and the obvious wiring re-arms a confirmed main-thread self-deadlock that the codebase documents in its own words: "⚠ MAIN-THREAD HAZARD — currently UNREACHABLE, and that is load-bearing" (shared/bridge.py:2517-2540), pinned by tests/test_panel_consent_no_freeze.py:35. C1 as briefed (hunk list, Apply/Edit/Skip, Apply-all, typed approval) is buildable on existing primitives and is not the hard part; the hard part is a non-blocking panel dispatch, which is panel-side work the bridge file explicitly refuses to paper over.

Corrected — what changed in this sentence

The draft opened with "built, tested, and has run." Tested is withdrawn from that list for the apply path, and the guarantee qualifier is inline rather than appended. The apply path's pinning suite (tests/test_graph_builder_mile3.py:1-21, "Four scenarios, all driven by a FAKE hou") installs a hand-rolled _FakeUndos with no areEnabled — so it proves the undo call was made, never that an undo entry exists or that one Ctrl+Z reverses it. Detail and the replacement grade in §6.1.

Order of operations follows from that split. Everything ungated and headless-testable is cheap and unblocks the verification loop (§9 Band A). Everything the crucible found wrong on the apply path is correctness debt that must land before anyone trusts an apply result (Band B). The card itself cannot move until a producer exists, and the producer is the one item that can re-arm a live freeze (Band D).
