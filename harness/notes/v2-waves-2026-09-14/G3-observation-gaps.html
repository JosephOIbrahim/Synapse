§1Verdict in one paragraph

SYNAPSE's observation surface today is four record systems that fire, disagree about what a record is, and are read back by nothing. Two are always-on. FloorGate provenance writes one flat {op_id, op, ts, session, payload_digest, result_digest, outcome, origin, parent} record per mutating registry.invoke() — 5000 records + 1 orphaned temp file on disk (ls .synapse/provenance = 5001 entries, of which 5000 match op-*.json and one is tmp7qjf1g7h.tmp, VERIFIED-RUNTIME), FIFO-capped at 5000 (floor_gate.py:126), of which exactly three are read by anything in production (doctor.py:856-866, newest 3 into the support bundle). AuditLog — absent from revision 1 entirely — writes a far richer hash-chained, Fernet-encrypted entry carrying the handler's full input payload and full returned output on the same mutating commands, with no env gate and no allowlist (handlers.py:551-556 → handlers.py:597-620 → core/audit.py:220,327-343): 122 daily files, 143 MB, spanning audit_2026-02-06.jsonl to audit_2026-09-14.jsonl — the newest written today (ls ~/.synapse/audit | wc -l, du -sh, VERIFIED-RUNTIME). Nothing reads those files back: AuditLog.get_entries() (core/audit.py:344) queries the in-memory list, so a fresh process cannot read its own history, and a repo-wide grep returns nine writer sites and zero file readers outside the doctor's newest-3 bundle.

The third system, the LOOP — the forecast/terminal/delivery journal at loop/coordinator.py — is fully built on both the producer and the consumer side and has produced zero records on this host: no loop/ directory exists under .synapse/ or ~/.synapse/ (VERIFIED-RUNTIME), because SYNAPSE_LOOP_ENABLED is set nowhere outside three test files (host/memory_loop.py:24-25), its 12-command allowlist covers 10 reachable commands out of 131 registered (memory_loop.py:17-21 vs grep -c "reg.register(" handlers.py = 131), and its delivery leg cannot complete without a Hanish/Octavius substrate that no installer, package file, or CI job configures (loop/subprocess_port.py:116-120).

The fourth is the one the repo actually legislates — “Provenance or it didn't happen… written to agent.usd with decision + reasoning + revert” (harness/CLAUDE.md:16-17) — which refers to none of the other three. It means memory/agent_state.py:549 log_decision(), which has exactly one production caller (host/graph_synth_runtime.py:122), covering exactly one route, and zero readers anywhere in the tree (grep -rn "memory/decisions" python/ returns only writer-side hits).

On top of that: one of fourteen traced live mutation routes emits nothing anywhere, three more emit nothing to any operation-record system, two bypass the only LOOP entry point structurally at any configuration, and at least twenty-five distinct sites return or persist a status that does not describe what happened — including the one channel a model actually reads back, which is deposited the string "Executed: <cmd>" whether the command succeeded or failed (handlers.py:610 → session/tracker.py:322-328).

The system is not under-instrumented by accident. It is instrumented four different ways that disagree about what a record is, and every one of them is write-only.
